## 1. Η υπόθεση Α του προηγούμενου handoff ΑΝΑΙΡΕΘΗΚΕ (μετρημένο)
- Το webpack (`WorkerPlugin`) ξαναγράφει `{ type: 'module' }` → `{ type: undefined }` όταν `output.module=false`.
  Στα 1.057 chunks του live (`561f201e`) και οι 4 Workers γεννιούνται `{type:void 0, name:"plan-ocr"|"plan-align"|"space-detect"|"survey-preview"}` ⇒ **κλασικοί**, το `importScripts` δουλεύει.
- Το «Module scripts don't support importScripts()» το προκάλεσε η **δική μας** χειροκίνητη γέννηση με `type:'module'` στην επαλήθευση. ⇒ **ΜΗΝ** αλλάξεις splitChunks/workerChunkLoading για αυτό.
- ⚠️ Ασυμμετρία (μόνο σημείωση): dev (Turbopack) = module Workers · prod (webpack) = κλασικοί.

## 2. Η ΠΡΑΓΜΑΤΙΚΗ αιτία (μετρημένη ζωντανά στο nestorconstruct.gr)
Διαγνωστικός Worker (blob που φορτώνει το ίδιο bundle και ακούει `unhandledrejection`):
`TypeError: e.replace is not a function at new r.U (plan-ocr…js) ← 88244…js (onnxruntime-web)`. Ο πραγματικός Worker: **καμία** απάντηση, **κανένα** `error`.
Αλυσίδα: το `onnxruntime-web` 1.30 (`ort.wasm.bundle.min.mjs`) κάνει στην εκκίνηση `new URL("ort.wasm.bundle.min.mjs", import.meta.url)`.
Ο κανόνας του `next.config.js` (`test:/\.mjs$/, include:/node_modules/, type:'javascript/auto'`, για το pdfjs) επέβαλλε τύπο JS
και στα `.mjs` που ζητούνται ως **URL** (προεπιλογή webpack: `asset/resource`) ⇒ το URL έλυσε στο ίδιο το module του ORT
(`r(488244)` = `{InferenceSession…}`) ⇒ `.replace` σε αντικείμενο ⇒ `unhandledrejection` στην ασύγχρονη εκκίνηση webpack
(`r.x = () => r.e(…).then(…)`) ⇒ **δεν** φτάνει ως `error` στο `Worker` ⇒ ο πελάτης στέλνει στο κενό ⇒ πάνελ για πάντα «Προετοιμασία…».
