## 3. Ευρήματα (ΜΕΤΡΗΜΕΝΑ στον αέρα)
**Α. Αιτία πτώσης.** Παραγωγή = webpack (`next build`· dev = Turbopack). Το bundle του Worker
`/_next/static/chunks/plan-ocr.c6bbbf9d142730d4.js` (23.964 B) στην εκκίνηση κάνει `r.x = () => r.e(88244).then(…)` —
τα εξαρτήματά του (`onnxruntime-web`, `InferenceSession`) κόπηκαν από το splitChunks στο `88244.9c613cd2d7923759.js`
(71.261 B, HTTP 200). Η φόρτωση chunk του webpack στον Worker είναι `r.f.i` = **`importScripts`**. Ο Worker γεννιέται
`{ type: 'module' }` (`plan-ocr-worker-spawn.ts:14`) ⇒ γέννηση του ίδιου URL στη σελίδα έδωσε:
`Uncaught TypeError: Failed to execute 'importScripts' on 'WorkerGlobalScope': Module scripts don't support importScripts().`
- Ίδιο μοτίβο γέννησης (`new Worker(new URL(…), { type: 'module' })`) σε: `plan-align-worker-spawn.ts`,
  `space-detect-worker-spawn.ts`, `survey-preview-worker-spawn.ts` — δουλεύουν **μάλλον** επειδή δεν τους κόπηκε chunk
  (το `plan-align` bundle 12.521 B, χωρίς `r.e` στην εκκίνηση — ΜΗ μετρημένο για τους άλλους δύο).

**Β. Το πάνελ κολλάει για πάντα.** Τύλιξα `window.Worker` (καταγραφή spawn/error/message) → «Ακύρωση» (⇒ `cancelled` ✅) →
«Ξανά» ⇒ πάλι `running/starting` **χωρίς νέα γέννηση Worker**. Άρα ο πελάτης (`src/lib/workers/worker-rpc-client.ts`)
**δεν έλαβε ποτέ `error`** (αλλιώς `broken=true` ⇒ fallback ⇒ `failed: worker-unavailable`). Κρατά νεκρό Worker και
στέλνει αιτήματα στο κενό. **Γιατί δεν έφτασε το `error` μέσα στην εφαρμογή ΔΕΝ αποδείχθηκε** (στη χειροκίνητη γέννηση
έφτασε). Υπόθεση: σφάλμα αξιολόγησης module / απόρριψη υπόσχεσης στον Worker δεν γίνεται πάντα `error` στο αντικείμενο.

## 4. Επόμενα (με τη σειρά)
0. **Έρευνα (web)**: πώς το κάνουν οι μεγάλοι (Figma, transformers.js, MediaPipe, Comlink, Next.js/webpack docs για
   `workerChunkLoading`, module vs classic Workers, self-contained worker bundles). Καμία λύση χωρίς πηγή.
1. **SSoT audit (grep)** πριν από κώδικα: `src/lib/workers/*` (client/host/protocol/`latestOnly`), οι 4 `*-worker-spawn.ts`,
   `next.config.js` webpack() (splitChunks, `!isServer`, `dev` skip γρ. ~231), τυχόν υπάρχουσα χειραψία/timeout.
2. **Διόρθωση Α** — προτεινόμενο (α): **ένα σημείο** στο `next.config.js` (webpack, client): bundles Worker αυτάρκη (χωρίς
   split chunks ⇒ ποτέ `importScripts`), καλύπτει και τους 4. Εναλλακτική (β): κλασικός Worker (χωρίς `type:'module'`) μόνο
   για OCR — μία γραμμή, αλλά αφήνει τους άλλους εκτεθειμένους. Απόφαση μετά την έρευνα· ρώτα τον Giorgio.
3. **Διόρθωση Β** — χειραψία εκκίνησης στο κοινό RPC: ο host στέλνει «έτοιμος», ο client χωρίς «έτοιμος» σε N s ⇒ νεκρός ⇒
   `failed: worker-unavailable` (μοτίβο Comlink ready). + `error`/`messageerror`. Tests στο `src/lib/workers/__tests__`.
4. **Φρουρός** (πρόταση, ρώτα): άγκυρα/πύλη ότι κανένα bundle Worker της παραγωγής δεν περιέχει `importScripts` όταν
   γεννιέται `type:'module'` — αλλιώς ξαναγίνεται σιωπηλά.
5. **Επαλήθευση**: τοπικό `next build` (μόνο αυτό αναπαράγει· βαρύ, 14 GB heap — **ρώτα**) → land/push με εντολή → ζωντανά
   ξανά: OCR τελειώνει, `nestor-models-v1` γεμίζει, χρόνοι ανά στάδιο, συντελεστής 1 vs 2 ⇒ οριστικό `maxDetectPixels`.
6. Μετά: 0.7 (ADR-929 §6.16 + changelog πάνω στο Δ20 από το main, ADR-884 §4.14) — να γράφει και αυτό το εύρημα.
