# CHECK 3.10

Firestore `query()` with `where()` MUST include `companyId`

## Ο άξονας απομόνωσης ρωτιέται στην αυθεντία

Η πύλη δέχεται ερώτημα χωρίς `companyId` **μόνο** όταν το `src/services/firestore/tenant-config.ts`
(η ίδια αυθεντία με τη CHECK 3.35) το δικαιολογεί για τη **συγκεκριμένη** συλλογή που ονομάζει το μπλοκ:

- `mode: 'userId'` → το μπλοκ πρέπει να φιλτράρει στο δηλωμένο `fieldName`.
- `mode: 'none'` **και** `unscopedCategory: 'public-world'` (επίπεδο Α: `PUBLIC_LANDS` · `PUBLIC_BUILDINGS` ·
  `PUBLIC_UNITS`, `allow read: if true`) → κανένας άξονας, ρητά. Φίλτρο `companyId` εκεί θα έκρυβε το κοινό
  κτίριο από κάθε άλλον χώρο. *(Προστέθηκε 2026-10-04, πρώτος καταναλωτής ερωτήματος: `usePublicUnits`.)*

⚠️ Το `project-scoped` (`CAD_FILES` κ.λπ.) έχει επίσης `mode: 'none'` αλλά **παραμένει** στην αυστηρή διαδρομή:
είναι απομονωμένο μέσω του έργου. Μετρημένο με μετάλλαξη: ίδιο ερώτημα σε `CONTACTS` ή `CAD_FILES` → BLOCK.
