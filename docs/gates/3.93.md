# CHECK 3.93 — Πύλη της προβολής του Cloud Functions

**Πύλη της προβολής του Cloud Functions** (ADR-874 · ADR-873 Ε-873.2) — «μεταγλωττίζει το functions build **ακριβώς** ό,τι λέει το SSoT της εφαρμογής;».

🔴 **ΤΟ ΠΕΡΙΣΤΑΤΙΚΟ, ΜΕΤΡΗΜΕΝΟ 2026-09-22**: το `functions/` είναι **χωριστή μονάδα npm** που το Firebase ανεβάζει μόνη της (`firebase.json` → `source: functions`) — **δεν** μπορεί να κάνει import από το `src/`. Γι' αυτό κρατούσε **χειρόγραφα αντίγραφα**: το `search-config.mirror.ts`, τα 24 ονόματα συλλογών, τα προθέματα ID, τον decoder DXF. Το `4bd107bd` (2026-05-02) άλλαξε **μόνο** το SSoT του search index· ο **μοναδικός** writer της παραγωγής (η Cloud Function, ADR-029) ευρετηρίαζε **λάθος πεδία ~5 μήνες**. Script συγχρονισμού **υπήρχε** — δεν το καλούσε **κανένα** hook και **κανένα** workflow. Φρουρός που δεν τρέχει είναι σχόλιο.

🔴 **ΚΑΙ ΤΟ ΧΕΙΡΟΤΕΡΟ (Ε-874.1)**: το αντίγραφο του `normalizeSearchText` / `generateSearchPrefixes` στο functions **δεν** ήταν αντίγραφο — δεν διπλώνει το τελικό σίγμα, δεν αφαιρεί λατινικούς τόνους, δεν σπάει το `PRJ-001` σε `001`. Το `/api/search` κανονικοποιεί το **ερώτημα** με τον αλγόριθμο της εφαρμογής· δύο αλγόριθμοι στις δύο πλευρές του **ίδιου** `array-contains-any`. Αναζήτηση «001» **δεν μπορούσε** να βρει το `PRJ-001`.

🏆 **Η ΛΥΣΗ ΕΙΝΑΙ ΤΟΥ KUBERNETES, ΤΑ ΚΛΕΙΔΙΑ ΕΙΝΑΙ ΔΙΚΑ ΜΑΣ.** `hack/update-codegen.sh` + `hack/verify-codegen.sh`: ο κώδικας **παράγεται**, αποθηκεύεται, και η πύλη ρωτά «ξαναπαράγεται ίδιος;». Εδώ `npm run generate:functions-projection` + αυτή η πύλη. Και ένα βήμα πέρα: η λίστα κλειδιών των σταθερών **ΔΕΝ γράφεται πουθενά** — **υπολογίζεται** από κάθε `COLLECTIONS.KEY` που διαβάζεται κάτω από το `functions/src`. Χειρόγραφη λίστα θα ήταν ένα ακόμη mirror.

| | Τι | Πώς |
|---|---|---|
| **modules** | φορητά αρχεία, **αυτούσια** (bytes του SSoT) | καμία μετατροπή ⇒ καμία «επιτρεπτή διαφορά», κανένας normalizer |
| **constants** | υποσύνολο σταθερού χάρτη (`COLLECTIONS`, `ENTERPRISE_ID_PREFIXES`) | κλειδιά = ό,τι διαβάζεται, τιμή = το literal του SSoT (AST) |
| **κλειστότητα** | φορητό module κάνει import **μόνο** node builtins και άλλα προβαλλόμενα | `@/`, πακέτο ή μη προβαλλόμενο σχετικό ⇒ ⛔ |

| Κατάσταση | Σημαίνει |
|---|---|
| `stale` | άλλαξε το SSoT χωρίς αναπαραγωγή **ή** κάποιος έγραψε με το χέρι στο `generated/` — **η ίδια αποτυχία** |
| `missing` / `orphan` | λείπει αρχείο του σχεδίου / υπάρχει αρχείο που δεν ανήκει στο σχέδιο (θα μεταγλωττιζόταν μπαγιάτικο) |
| `invalid` | το σχέδιο δεν χτίζεται: παραβίαση κλειστότητας, κλειδί που διαβάζεται αλλά δεν δηλώνεται, μη-literal τιμή, χρήση του αντικειμένου **ολόκληρου** (`Object.keys(COLLECTIONS)` ⇒ τα κλειδιά δεν υπολογίζονται — **άρνηση, ποτέ μαντεψιά**) |

⚠️ **Οι τιμές με `process.env.X || 'literal'`**: η εφαρμογή μπορεί να αλλάξει το όνομα με `NEXT_PUBLIC_*`, μια Cloud Function **δεν** βλέπει αυτή τη μεταβλητή. Η προβολή κουβαλά την **προεπιλογή** και σημειώνει inline κάθε τέτοιο κλειδί. Override διαφορετικό από την προεπιλογή = split brain εφαρμογής/trigger.

⛔ **ΜΗΝ** γράψεις στο `functions/src/generated/` — ούτε «μια μικρή διόρθωση». Άλλαξε το SSoT και τρέξε τον γεννήτορα.
⛔ **ΜΗΝ** προσθέσεις κλειδιά στο `.functions-projection.json`: διάβασε `COLLECTIONS.NEW_KEY` στον κώδικα και ξαναπαράγαγε.
⛔ **ΜΗΝ** «λύσεις» μια παραβίαση κλειστότητας κάνοντας το φορητό module να εισάγει με `@/`: πρόβαλε και την εξάρτηση, ή κόψ' την.

⚡ ~0,5s (AST σε ~70 αρχεία). **Χωρίς σκανδάλη**: ένα νέο κλειδί σε **οποιοδήποτε** αρχείο του `functions/src` αλλάζει το σχέδιο. Καθαρό in-memory Node ⇒ Φάση 1, δίπλα στα 3.33/3.34 — **καμία baseline, ποτέ**.
