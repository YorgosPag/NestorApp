# CHECK 3.57 — Πύλη ισοτιμίας production build

**Πύλη ισοτιμίας production build** (ADR-788) — «χτίζει **κάθε** production build τον server που **στέλνεται**, ή απλώς κάτι που του μοιάζει;». 🔴 **Το σχόλιο ΥΠΗΡΧΕ και ΑΠΕΤΥΧΕ**: δύο workflows γράφουν **κατά λέξη** «*Any workflow calling build:ci MUST set NODE_OPTIONS itself*»· ένα τρίτο (ο ΧΡΗΣΜΟΣ του 3.51) το αγνόησε. Μετρημένο στο **ίδιο commit** (2026-08-21, run `32458992910`): `docker-build.yml` **20** μεταβλητές ✅ · `bundle-ratchet.yml` **20** ✅ · ο χρησμός **1** ⇒ **OOM στα ~4,1 GB**. ⚠️ Και το σχόλιο **μέσα** στο τρίτο έλεγε ότι έλειπε «**μία γραμμή env**»: **έλειπαν 19 από τις 20** — *η περιγραφή της διόρθωσης ΗΤΑΝ η απόκλιση*. Ίδιο σχήμα με τις 2 λίστες namespace του **3.34** (63) και τη λίστα 18-vs-26 του **3.37**. **Ένα anchor χωρίς gate είναι σχόλιο** (3.36). 🔑 **Η ΑΥΘΕΝΤΙΑ ΕΙΝΑΙ ΡΟΛΟΣ, ΟΧΙ ΟΝΟΜΑ ΑΡΧΕΙΟΥ**: κανονική είναι η κλήση `build:ci` που ζει στο **Tier 1** workflow **όπως το δηλώνει το `.ci-gate-tiers.json`** — χειρόγραφο `docker-build.yml` μέσα στην πύλη θα ήταν **τέταρτη** λίστα (άγκυρα `Κ1`). **6 ρητές καταστάσεις, κλειστή λογιστική fail-closed** (άγνωστη ⇒ `throw` **με όνομα**): ✅ `canonical-build` **1** · ⛔ `env-drift` 0 · ⛔ `env-value-drift` 0 (το περιστατικό **8192** της 04/08) · ⛔ `cross-env-build` 0 · ⛔ `unanalyzable-caller` 0 · 🔶 `redundant-parity-build` **1**. ⚠️ **Το 🔶 ΔΕΝ μπλοκάρει, με λόγο**: το `bundle-ratchet.yml` είναι σήμερα **σωστό** (20/20)· ⛔ θα το έκανε μονίμως κόκκινο ⇒ `SKIP_` ⇒ διακοσμητικό (3.39), ✅ θα **θεσμοθετούσε** την επανάληψη. Ονομάζεται, με γραμμένη κατεύθυνση: διαβάζει **μόνο** `.next/static`, που υπάρχει **μέσα στην εικόνα**. ⚠️ **ΚΡΙΤΗΡΙΟ ΠΟΥ ΜΕΤΡΗΘΗΚΕ ΚΑΙ ΑΠΟΡΡΙΦΘΗΚΕ**: «καμία κλήση `npm run build`» (το `build` καρφώνει `cross-env NODE_OPTIONS=8192` και **σβήνει** ό,τι έθεσε το workflow) έδωσε **1 εύρημα / 1 ψευδώς θετικό = 100%** — `ssot-discover.yml:466` γράφει `npm run build:tokens` **μέσα σε echo**. Κρατήθηκε `build(?![:\w])`· το υπόλοιπο (εντολή μέσα σε κείμενο περίληψης) είναι **δηλωμένο όριο**, μετρημένο **0**. **SSoT — καμία νέα μηχανή**: ο **μόνος** αναγνώστης workflow (`lib/ci/workflow-meta.js`, ADR-757) έμαθε **ένα** πεδίο (`env:` ανά βήμα)· δεύτερος αναγνώστης YAML θα ήταν η «δεύτερη διάλεκτος» του ADR-749. ⚠️ Η πρώτη γραμμή βήματος φέρει `- ` ⇒ τα κλειδιά κάθονται **δύο κενά** πιο μέσα· λάθος εσοχή ⇒ **μηδέν** κλειδιά ⇒ `{}` ⇒ κάθε σύγκριση περνά κενή και **η πύλη γίνεται μονίμως πράσινη** (άγκυρα `Μ0.2`). 🔬 **Η ΒΑΘΜΟΝΟΜΗΣΗ ΕΙΝΑΙ ΤΟ ΚΕΝΤΡΟ**: το `Π1` τρέχει την πύλη στον **ΠΡΑΓΜΑΤΙΚΟ** κώδικα του `76235be6` και απαιτεί ⛔ με «**λείπουν 19/20**»· το `Π2` αποδεικνύει τον **παρονομαστή** (το αδελφό workflow του **ίδιου** commit ήταν ήδη σε ισοτιμία, αλλιώς η πύλη θα ήταν απλώς θορυβώδης). ⚠️ **Καρφωμένο commit, ΠΟΤΕ `HEAD`**· το `gitShow` **σκάει** σε κενή απάντηση. ⚠️ **ΜΗΝ** το κάνεις ratchet (δεν υπάρχει «λιγότερα builds με λάθος περιβάλλον από χθες» — **ένα** αρκεί για να μετρήσει μια πύλη τον λάθος server)· **ΜΗΝ** λύσεις κόκκινο αντιγράφοντας τις 20 μεταβλητές (**η προτιμώμενη διόρθωση είναι «μην ξαναχτίσεις»** — τράβα την εικόνα, πρότυπο `i18n-ssr-oracle.yml`)· **ΜΗΝ** κρύψεις build σε σύνθετη ενέργεια (σαρώνονται, ⇒ ⛔ `unanalyzable-caller`). Layer 1 = σκανδάλη **μέσα στην πύλη** (~0,1s· workflows · `.github/actions/**` · μητρώο · ο κώδικας της ίδιας της πύλης — αλλιώς αλλαγή στο κριτήριο περνά χωρίς να ασκηθεί το κριτήριο)· **Layer 2 = job στο ΥΠΑΡΧΟΝ `ci-gate-tiers.yml`, άνευ όρων** (μητρώο και workflows αλλάζουν **ανεξάρτητα**, και η ταυτότητα της κανονικής κλήσης εξαρτάται **και από τα δύο**). **Κανένα νέο workflow γι΄ αυτήν** — το μητρώο παρακολουθεί **αρχεία**, όχι jobs· **34** πύλες (33→34 από το `i18n-ssr-oracle.yml`), **επαληθευμένο ΕΚΤΕΛΩΝΤΑΣ** το 3.37.
