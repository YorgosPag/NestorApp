# CHECK 3.92 — Πύλη του συνόρου ιδεμποτίας

**Πύλη του συνόρου ιδεμποτίας** (ADR-872 · ADR-853 Ε3 Φάση 2) — «εκτελείται κάθε πράξη **μία** φορά ανά `Idempotency-Key`, και όποιος το παρακάμπτει, το είπε με λόγο;».

🔴 **ΤΟ ΠΕΡΙΣΤΑΤΙΚΟ, ΜΕΤΡΗΜΕΝΟ 2026-09-21** (ADR-853 §13): τρία `503` στη σειρά σε `POST` πρόσκλησης ⇒ **τρεις** αποστολές της ίδιας πράξης. Ο `apiClient` ξανάστελνε **κάθε** μέθοδο έως 3 φορές σε δίκτυο/`5xx`, και από **193** κλήσεις που αλλάζουν δεδομένα, **καμία** δεν κουβαλούσε `Idempotency-Key`. Σφάλμα δικτύου ή `504` **δεν** σημαίνει «δεν εκτελέστηκε»: ο handler μπορεί να έγραψε, και να χάθηκε μόνο η απάντηση.

🏆 **Η ΛΥΣΗ ΕΙΝΑΙ ΤΗΣ STRIPE, Η ΠΥΛΗ ΕΙΝΑΙ ΔΙΚΗ ΜΑΣ.** Ο πελάτης στέλνει **ένα** κλειδί ανά πράξη, **ίδιο** σε κάθε επανάληψη, και το `withAuth` / `withPersonalOrOrgAuth` εκτελεί μία φορά και αναπαράγει την αποθηκευμένη απάντηση (IETF `draft-ietf-httpapi-idempotency-key-header-07`). Αυτό όμως κρατά **μόνο** όσο (α) τα σύνορα καλούν το στρώμα και (β) κάθε route περνά από σύνορο. Η Stripe το εγγυάται μέσα στο SDK της· εδώ το εγγυάται η πύλη.

| | Ερώτημα | Μηχανισμός |
|---|---|---|
| **Κ1** | κάθε `{ mode: 'natural' }` έχει `why` ≥ 15 χαρακτήρες; | ⛔ |
| **Κ2** | η ρίζα `withAuth` καλεί το `runIdempotently` **2** φορές (ανώνυμος + αυθεντικοποιημένος κλάδος), η `withPersonalOrOrgAuth` **1**, η `withVendorLinkDoor` **1** (ADR-876 §5 — δημόσια πόρτα, principal = ο σύνδεσμος); | ⛔ |
| **Κ3** | route `POST/PUT/PATCH/DELETE` που **δεν** καλεί κανένα σύνορο; | 🔴 ratchet κατά ταυτότητα |

🔑 **ΤΑ ΣΥΝΟΡΑ ΥΠΟΛΟΓΙΖΟΝΤΑΙ, ΔΕΝ ΑΠΑΡΙΘΜΟΥΝΤΑΙ.** Σταθερό σημείο στο AST: ρίζες + κάθε εξαγόμενη συνάρτηση (εκτός `route.ts`) που καλεί ήδη γνωστό σύνορο. Μετρημένο 2026-09-22: **27** σύνορα, ανάμεσά τους `runGuarded`, `createMigrationRoute`, `projectPreviewRoute`, `withNetworkDoor`. Μια χειρόγραφη λίστα factories θα πάλιωνε με την πρώτη νέα factory. Η μετάλλαξη «ένα μόνο πέρασμα» κοκκινίζει **και στο πραγματικό δέντρο** (Δ2), άρα η αλυσίδα έχει πράγματι βάθος.

⚠️ **Ένα εξαγόμενο `POST` σε κοινό αρχείο είναι handler, όχι factory**: ως «σύνορο» θα κάλυπτε ψευδώς κάθε route που το καλεί (Π4). Γι' αυτό τα ονόματα μεθόδων HTTP αποκλείονται από τον υπολογισμό.

📏 **Η baseline (38)**: webhooks (Mailgun/Telegram), cron, OAuth `authorize`/`token`, MCP, δημόσιοι σύνδεσμοι με token (`mandate/[token]`, `vendor/quote/[token]`), `auth/*`, και μερικά routes με έλεγχο ταυτότητας **μέσα** στον handler (`showcase/email`, `impact-preview`). Τα server-to-server δεν τα καλεί ο `apiClient`, άρα δεν χρειάζονται κλειδί. Όσα μένουν εκτός για ιστορικούς λόγους μειώνονται μόνο: ένα **νέο** route εκτός συνόρου μπλοκάρει.

⛔ **ΜΗΝ «διορθώσεις» το Κ3 με `natural`**: το `natural` λέει «ιδεμποτικό εκ κατασκευής», όχι «δεν χρειάζομαι σύνορο». Και **μην** βάλεις `natural` επειδή «έτσι κι αλλιώς δουλεύει»· ο λόγος πρέπει να αποδεικνύεται στον handler (π.χ. `set` boolean).

⚠️ **Δηλωμένο όριο**: το «ξαναστέλνει κάποιος **δεύτερος** βρόχος μια πράξη;» (hook, `setTimeout`, βιβλιοθήκη) **δεν** αποφασίζεται στατικά. Ο ένας κριτής του πελάτη είναι ο `shouldRetry` (ADR-826 §8α).

⚡ ~3s (AST σε `src/lib` + `src/app/api` + `src/server`). **Χωρίς σκανδάλη**: μια νέα factory οπουδήποτε αλλάζει την απάντηση.

🧪 **Άγκυρες**: `npm run test:idempotency-boundary`.
- Πύλη: Π1–Π5 (Κ3) · Ν1–Ν2 (Κ1) · Ρ1–Ρ2 (Κ2) · Δ1–Δ2 (πραγματικό δέντρο).
- Σύνορο: Ι1–Ι11 (`with-idempotency.test.ts`).
- Πελάτης: Ρ1–Ρ10 (`enterprise-api-client-auth-retry.test.ts`).

**Μεταλλάξεις: πύλη 6/6 · σύνορο + πελάτης 21/21 κόκκινες.**

Escape: `SKIP_IDEMPOTENCY_BOUNDARY=1`
