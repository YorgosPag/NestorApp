## 4. ΕΠΟΜΕΝΟ — «Πληρωμή τώρα» με ΟΛΟΥΣ τους τρόπους (απόφαση Giorgio 2026-11-11: «ΠΑΜΕ ΝΑ ΥΛΟΠΟΙΗΣΟΥΜΕ ΟΛΑ»)
**Πρώτα Plan Mode + έρευνα σε επίσημες πηγές + ΠΡΑΓΜΑΤΙΚΟ SSoT audit (grep). Νέο ADR (επόμενος ελεύθερος αριθμός: `ls` τη στιγμή που χρειάζεται — CHECK 3.49) ή νέα ενότητα του ADR-ACC-018 — απόφαση του πράκτορα με αιτιολόγηση.**

Στόχος: στη δημόσια σελίδα κουμπί «Πληρωμή τώρα» ⇒ ο πελάτης διαλέγει τρόπο και πάει σε **ξεχωριστή ροή ανά τρόπο**:
1. **Κάρτα** (+ Apple Pay / Google Pay ως πορτοφόλια καρτών).
2. **Πληρωμή μέσω τράπεζας = IRIS Commerce** (ΔΙΑΣ: υποχρεωτική αποδοχή σε κάθε POS/e-shop από 1/12/2025· επιλογή τράπεζας + ασφαλής ανακατεύθυνση ή QR, πληρωμή ΗΔΗ συμπληρωμένη). Λογότυπα τραπεζών **μόνο** μέσα σε αυτή τη ροή, από τον πάροχο (όχι δικά μας — εμπορικά σήματα / όψη phishing).
3. **Τραπεζική μεταφορά με EPC QR** — υπάρχει ήδη (`invoice-payment-instructions.ts`).
4. Αξιολόγηση PayPal / Revolut Pay / άλλων: ΜΟΝΟ μετά από έρευνα (νομιμότητα ως ηλεκτρονικό μέσο για εξόφληση τιμολογίου, αναγνώριση δαπάνης, κόστος).
5. **Αυτόματη καταγραφή πληρωμής** (λείπει σήμερα, §16 «Εκτός εμβέλειας»): webhook παρόχου ⇒ ΕΝΑΣ γραφέας `PAYMENT_RECORDED` με ίχνος ⇒ `paymentStatus`/`balanceDue` ⇒ η σελίδα δείχνει «Εξοφλήθηκε». Ιδεμποτία (CHECK 3.92, `Idempotency-Key`/event id), επαλήθευση υπογραφής webhook, μερικές πληρωμές, επιστροφές.

**Sandbox πρώτα (απόφαση Giorgio)**: όλος ο κώδικας στήνεται πάνω σε **test mode / sandbox** παρόχου με **πλασματικό λογαριασμό εμπόρου**. Οι πραγματικοί λογαριασμοί είσπραξης ορίζονται αργότερα ως **ρύθμιση** (όχι αλλαγή κώδικα). Αρχιτεκτονική ανεξάρτητη παρόχου (port/adapter: ένα συμβόλαιο `PaymentProvider`, ένας adapter ανά πάροχο). Κλειδιά δοκιμής: τα βάζει ο Giorgio στο περιβάλλον — ο πράκτορας **δεν** εισάγει κλειδιά/διαπιστευτήρια.

**Έρευνα που χρειάζεται (επίσημες πηγές)**: πάροχοι με IRIS + κάρτες + sandbox στην Ελλάδα (Viva · Nexi · Adyen · Stripe · Everypay · τράπεζες) — υποστήριξη IRIS, webhooks, sandbox, προμήθειες, άδεια SDK (μόνο MIT/Apache/BSD, N.5)· υποχρεώσεις διασύνδεσης POS/ERP–myDATA για ηλεκτρονικές πληρωμές (τρόπος πληρωμής στο παραστατικό)· PayPal/Revolut. Τελική επιλογή παρόχου = **απόφαση Giorgio**.

Νομικό πλαίσιο (βρέθηκε 2026-11-11, πηγές 2016–2018 — επαλήθευσε ισχύ): τιμολόγια προς ιδιώτες ≥500 € εξοφλούνται με ηλεκτρονικά μέσα πληρωμής (ν. 3842/2010 αρ. 20 §3, όπως ν. 4446/2016 αρ. 69)· κάρτες = ηλεκτρονικό μέσο.
