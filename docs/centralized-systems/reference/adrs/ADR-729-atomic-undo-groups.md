# ADR-729 — Ατομικές ομάδες αναίρεσης: **ΜΙΑ ενέργεια χρήστη = ΜΙΑ εγγραφή ιστορικού**

**Ημ/νία**: 2026-07-29 · **Status**: IMPLEMENTED & GREEN
**Σχετικά**: ADR-057 (`completeEntities` SSoT) · ADR-459 Φ7 (`CompositeCommand` / `appendToLast`) ·
ADR-539 Φ4b + ADR-678 Φ3 (`executeAsAtomicBatch`) · ADR-650 §M10g (capability anchor) ·
ADR-722 §5 (εκεί μετρήθηκε το σφάλμα) · ADR-607 (batch entity commands)

---

## 1. Το πρόβλημα — **μετρημένο**, όχι εικαζόμενο

Ζωντανή επαλήθευση στο πραγματικό εργοτάξιο (`47_ergasia.dxf`, 93 σημεία ⇒ **186 ετικέτες**),
2026-07-29:

| Μέτρηση | Αποτέλεσμα |
|---|---|
| Ψήσιμο ⇒ οντότητες σκηνής | 2.910 → **3.096** (+186) |
| Κάθε πάτημα «Αναίρεση» αφαιρεί | **1 οντότητα** (επαληθευμένο σε 16 συνεχόμενες) |
| Πόσες αναιρέσεις ήταν **δυνατές** | **ακριβώς 100** — μετά το ιστορικό εξαντλήθηκε |
| Αποτέλεσμα | **86 ετικέτες έμειναν ορφανές και ΔΕΝ αναστράφηκαν** |

**Η αιτία, στον κώδικα:** το `completeEntities` (`hooks/drawing/completeEntity.ts`) έκανε **βρόχο**
καλώντας `completeEntity` ανά οντότητα· καθεμιά έσπρωχνε **δική της** εγγραφή στο `CommandHistory`.
Ένα ψήσιμο = **1 διαγραφή + 186 δημιουργίες = 187 εγγραφές**, έναντι
`maxHistorySize: 100` (`core/commands/interfaces.ts`) όπου το `trimUndoStack` πετάει τις
**παλαιότερες**. Η αριθμητική κλείνει ακριβώς με το μετρημένο «100 αναιρέσεις».

### 1.1 Οι δύο συνέπειες — και η δεύτερη είναι η σοβαρή

1. Η εντολή **δεν ξεκάνεται**: φτάνεις στις 100 από τις 186 και μένεις με ορφανές οντότητες.
2. 🔴 **Κάθε παρτιδική εντολή σβήνει ΟΛΟ το προηγούμενο ιστορικό της συνεδρίας.** Ο χρήστης χάνει τη
   δυνατότητα να ξεκάνει **άσχετη** δουλειά που είχε κάνει πριν. Το κόστος **δεν** πληρώνεται εκεί
   που φαίνεται — πληρώνεται σε δουλειά που χάνεται σιωπηλά.

### 1.2 Γιατί δεν το έπιασε **κανένα** από τα 21 tests της περιοχής

Επαληθεύουν όλα το **αποτέλεσμα** των εντολών στη σκηνή (η σκηνή έχει τα σωστά entities) — **ποτέ το
πλήθος εγγραφών ιστορικού**, ποτέ το ταβάνι. Η **κοκκομετρία της αναίρεσης** δεν ήταν ιδιότητα που
κοίταξε κανείς. Ίδιο σχήμα με το «`0` = κανείς δεν κοίταξε» των N.11 / N.12.

## 2. Έρευνα — τι κάνουν οι μεγάλοι (**επαληθευμένο 2026-07-29**, όχι γνώση εκπαίδευσης)

Ο κανόνας είναι **καθολικός** και στους τέσσερις, και ο μηχανισμός είναι πάντα **εμβέλεια**
(άνοιγμα/κλείσιμο), ποτέ «τύλιξε αυτόν τον πίνακα»:

| Εργαλείο | Μηχανισμός | Πηγή |
|---|---|---|
| **Revit** | `TransactionGroup` + `Assimilate()` — «all transactions within the group will be merged into a single transaction… you only have 1 action in Undo/Redo menu, instead of many». Ένθετες ομάδες αφομοιώνονται στην εξωτερική. Υπάρχει και `RollBack()`. | [revitapidocs — TransactionGroup](https://www.revitapidocs.com/2024/f1113d30-4c36-7844-1537-aad7f095cea0.htm) · [The Building Coder](https://thebuildingcoder.typepad.com/blog/2015/02/using-transaction-groups.html) |
| **AutoCAD** | `UNDO Begin/End`: «The Begin option groups a sequence of actions into a set… UNDO and U treat grouped actions as a **single action**». | [Autodesk — UNDO (Command)](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Core/files/GUID-2729A466-B199-4840-B92B-4D8A38A8ADB8.htm) |
| **Cinema 4D (MAXON)** | `doc.StartUndo()` / `doc.EndUndo()`: «**Only the Start/EndUndo containers determine how often you need to hit Ctrl-Z**». | [MAXON Python SDK — BaseDocument](https://developers.maxon.net/docs/py/2024_4_0a/modules/c4d.documents/BaseDocument/index.html) |
| **Γενική πρακτική** | «Multiple commands can be queued at once to be executed but **stacked as a single command**… the action could be undone with just one click.» | [Implementing undo/redo with the Command Pattern](https://gernotklingler.com/blog/implementing-undoredo-with-the-command-pattern/) |

### 2.1 🎯 Πού πάμε **ΠΙΟ ΠΕΡΑ** από τους μεγάλους

Και στα τρία εργαλεία η εμβέλεια είναι **πειθαρχία**: αν ο προγραμματιστής ξεχάσει να την ανοίξει, η
αποτυχία είναι **σιωπηλή** — πολλά βήματα undo, κανένα σφάλμα, κανένα προειδοποιητικό σήμα. Ακριβώς
έτσι γεννήθηκε το σφάλμα του §1 εδώ.

**Η απάντηση αυτού του ADR: η ατομικότητα γίνεται ΔΟΜΙΚΗ, όχι πειθαρχία.** Την εμβέλεια την ανοίγει
**το ίδιο το `completeEntities`** — η ΜΙΑ ραφή απ' όπου περνούν υποχρεωτικά όλοι οι παραγωγοί
παρτίδας (ADR-057 SSoT). Άρα:

> **Κανένας μελλοντικός παραγωγός παρτίδας δεν *μπορεί* να ξεχάσει την ατομικότητα — τη
> κληρονομεί χωρίς να την ξέρει.**

Δεύτερο κέρδος, καθαρά παρεπόμενο: το `maxHistorySize: 100` σήμαινε στην πράξη «100 **οντότητες**»,
που για τον χρήστη είναι **απρόβλεπτο**. Τώρα σημαίνει «100 **ενέργειες**» — υπόσχεση που
καταλαβαίνει. Δεν χρειάστηκε καμία αλλαγή σταθεράς: η σημασία διορθώθηκε από τη δομή.

## 3. Η απόφαση

### 3.1 Νέο SSoT: `CommandHistory.runAsSingleUndo(name, work)`

```ts
runAsSingleUndo<T>(name: string, work: () => T): T
```

Ό,τι εκτελεστεί μέσα στο `work()` — **όσο βαθιά κι αν βρίσκεται στη στοίβα κλήσεων** —
προσγειώνεται ως **ΕΝΑ** βήμα αναίρεσης.

| Ιδιότητα | Συμπεριφορά |
|---|---|
| Εκτέλεση | Το command τρέχει **ΤΩΡΑ** (η σκηνή πρέπει να είναι σωστή για την επόμενη εντολή της παρτίδας)· απλώς **συλλέγεται** αντί να σπρωχτεί στη στοίβα |
| Ένθεση | Εσωτερική εμβέλεια **ενώνεται** με την εξωτερική (Revit assimilation)· **μόνο** η εξώτατη γράφει εγγραφή |
| 0 παιδιά | Καμία εγγραφή-φάντασμα, καμία ειδοποίηση |
| 1 παιδί | Σκέτο το command — μηδέν composite overhead, **ίδια συμπεριφορά με πριν** |
| N παιδιά | **ΕΝΑ** `CompositeCommand` |
| Σφάλμα μέσα στο `work()` | **Rollback**: τα εκτελεσμένα ξετυλίγονται αντίστροφα και **τίποτα** δεν μπαίνει στο ιστορικό (Revit `TransactionGroup.RollBack`) |
| Ειδοποιήσεις | **1** αντί για N (186 ειδοποιήσεις ακροατών → 1) |
| Merge | Δεν επιχειρείται: μια ομάδα **ΕΙΝΑΙ** μια διακριτή ενέργεια χρήστη |

### 3.2 Γιατί **εμβέλεια** και όχι το υπάρχον `executeAsAtomicBatch`

Το `executeAsAtomicBatch(children)` (ADR-539 Φ4b) απαιτεί τα commands **χτισμένα και ανεκτέλεστα**.
Ο παραγωγός οντοτήτων **δεν μπορεί** να το ικανοποιήσει: κάθε `completeEntity` διαβάζει τη
**γραμμένη** σκηνή (`getScene`) πριν χτίσει την επόμενη — μέσα σε Block Editor η οντότητα είναι
**μέλος** του ενεργού block (ADR-641). Χτίσιμο όλων up-front θα απαιτούσε αναδιάρθρωση της ADR-057
SSoT που χρησιμοποιεί **κάθε** εργαλείο σχεδίασης.

Η εμβέλεια **δεν ζητά καμία αναδιάρθρωση του καλούντος** — γι' αυτό πιάνει και ό,τι εκτελεί
**ένθετος** κώδικας που δεν ελέγχεις: `postCreateCommands` (ADR-507 §5δ.9), δομικές αντιδράσεις,
`appendToLast` (ADR-459 Φ7).

**Τα δύο συνυπάρχουν και δεν επικαλύπτονται**: `executeAsAtomicBatch` = «έχω N έτοιμα commands»·
`runAsSingleUndo` = «θέλω ό,τι συμβεί εδώ μέσα να είναι μία ενέργεια». Μηδέν νέα κλάση ομαδοποίησης
— χρησιμοποιείται το υπάρχον `CompositeCommand`.

### 3.3 `CompositeCommand` — προαιρετικό όνομα ομάδας

Ονομασμένη ομάδα ⇒ `getDescription()` = `«όνομα (N operations)»` — **φραγμένη** ετικέτα: μια παρτίδα
186 ετικετών δεν επιτρέπεται να παράγει περιγραφή 186 όρων στο UI αναίρεσης. **Χωρίς** όνομα η
συμπεριφορά είναι **ακριβώς** η ιστορική (`'Composite'` + ένωση παιδιών με `' + '`) ⇒ μηδέν αλλαγή
για `appendToLast`, `executeAsAtomicBatch`, BIM/3D.

### 3.4 Πού **δεν** μπήκε: το `ICommandHistory`

Το `runAsSingleUndo` ζει στην **κλάση**, όχι στο interface — ίδια σύμβαση με το `appendToLast`
(ADR-459 Φ7), που επίσης δεν είναι στο interface. Το `ICommandHistory` υλοποιείται **δομικά** από
test doubles (`TextGripHandler.test.ts`)· προσθήκη υποχρεωτικής μεθόδου θα τα έσπαγε χωρίς κανένα
όφελος — όλοι οι καταναλωτές παίρνουν την κλάση μέσω `getGlobalCommandHistory()`.

## 4. Τι άλλαξε

| Αρχείο | Αλλαγή |
|---|---|
| `core/commands/CommandHistory.ts` | **+`runAsSingleUndo`** / `isGrouping` / ιδιωτικά `endGroup`, `pushGroupEntry`, `undoInReverse`· το `execute` **και** το `appendToLast` συλλέγουν όταν η ομάδα είναι ανοιχτή |

| `hooks/drawing/completeEntity.ts` | Το `completeEntities` τυλίγει **αδιαπραγμάτευτα** τον βρόχο (εξήχθη ως `completeEntitiesInGroup`) |

### 4.1 Ο περιορισμός του ADR-722 §5 **αίρεται χωρίς παράκαμψη**

Το `topo-bake-commit` τεκμηρίωνε: «τύλιγμα και των δύο σε ένα `CompoundCommand` θα απαιτούσε
παράκαμψη της SSoT». **Το δίλημμα ήταν ψευδές**: η εμβέλεια τυλίγει **γύρω** από το
`completeEntities` αντί να το παρακάμψει, άρα η διαδρομή που **επιβάλλει** το capability anchor του
ADR-650 §M10g μένει **ακέραιη** (το anchor είναι allowlist εισαγωγών — καμία εισαγωγή δεν άλλαξε).

## 7. Γνωστά όρια (ρητά, όχι παραλείψεις)

- **Παραγωγοί που καλούν `completeEntity` (ενικός) σε δικό τους βρόχο** δεν προστατεύονται
  αυτόματα. Σήμερα **δεν υπάρχει τέτοιος** (grep 2026-07-29: όλες οι πολλαπλές δημιουργίες περνούν
  από `completeEntities`). Ο σωστός τρόπος για έναν μελλοντικό είναι να ανοίξει ο ίδιος
  `runAsSingleUndo` — ή, καλύτερα, να χρησιμοποιήσει το `completeEntities`.
- **Ο `maxHistorySize: 100` δεν άλλαξε.** Τώρα σημαίνει «100 ενέργειες», που είναι η αρχική
  πρόθεση («Standard for CAD applications»). Καμία αλλαγή σταθεράς δεν δικαιολογείται από τα
  δεδομένα.
- **Το `CompoundCommand` παραμένει** ως δεύτερη κλάση ομαδοποίησης δίπλα στο `CompositeCommand`
  (προϋπάρχον χρέος, BIM/MEP καταναλωτές). **Δεν** αγγίχτηκε εδώ — θα ήταν άσχετο εύρος (N.8).
  Καταγράφεται ως γνωστό διπλότυπο έννοιας.
