# ADR-749 — Ενοποίηση της μηχανής παραβιάσεων SSoT: μία μέτρηση, τρεις καταναλωτές

**Κατάσταση**: ΥΛΟΠΟΙΗΜΕΝΟ (2026-08-03) · **Σχετικά**: ADR-294 (SSoT ratchet), ADR-314, ADR-584 (N.18), ADR-742 (§7quaterdecies)

> **Μία πρόταση**: την ερώτηση «πόσες παραβιάσεις SSoT υπάρχουν;» την απαντούσαν **τέσσερις**
> ανεξάρτητες υλοποιήσεις σε **πέντε** διαλέκτους regex, δίνοντας **τρεις** διαφορετικούς αριθμούς
> για το ίδιο δέντρο — και το ratchet συνέκρινε το αποτέλεσμα της μιας με το baseline της άλλης.

---

## 1. Το εύρημα, μετρημένο

Ίδιο `.ssot-registry.json`, ίδιο `src/`, ίδια στιγμή (2026-08-03):

| Μηχανή | Ρόλος | Μονάδα μέτρησης | POSIX `[[:space:]]` | Αρχεία / Παραβιάσεις |
|---|---|---|---|---|
| `check-ssot-imports.js` | **Η ΠΥΛΗ** (CHECK 3.7) | ανά (module, γραμμή) | ❌ **νεκρό** | **48 / 61** |
| `ssot-audit.sh` | Η ΑΝΑΦΟΡΑ | ανά (module, γραμμή) | ✅ ζωντανό | **73 / 86** |
| `ssot-baseline-engine.js` | **ΤΟ BASELINE** | ανά **(pattern, γραμμή)** | ✅ ζωντανό | **73 / 103** |
| `registry-golden-regex.test.js` | ΤΟ TEST | — | ✅ (`grep -E`) | επικύρωνε **διάλεκτο που κανείς δεν εκτελεί** |

Η απόκλιση **αποσυντέθηκε πλήρως** και αθροίζει κλειστά:

```
 61  (πύλη)
+25  ← 6 patterns με POSIX που στην πύλη πιάνουν ΜΗΔΕΝ
 86  (αναφορά)
+17  ← γραμμές που πιάνονται από 2 patterns του ΙΔΙΟΥ module
103  (baseline)
```

Τα 41 αρχεία που διαφωνούσαν αθροίζουν διαφορά **42 = 25 + 17**. Δεν έμεινε ανεξήγητο υπόλοιπο.

### 1.1 Αιτία Α — POSIX κλάσεις νεκρές στην πύλη

Το `[[:space:]]` σε JS RegExp **δεν σημαίνει «κενό»**. Είναι κλάση χαρακτήρων `[ : s p a c e`
ακολουθούμενη από literal `]`. Δεν πετάει σφάλμα· απλώς δεν πιάνει τίποτα, για πάντα.

Μετρημένο σε **11.091 αρχεία**:

| Module | Πύλη (JS, αμετάφραστο) | Μεταφρασμένο |
|---|---|---|
| `tabs-primitive` | **0** | 22 |
| `agent-capability-registry` | **0** | 80 |
| `no-navigation-flash` | **0** | 4 |
| `tenant-document-ownership` (×2) | **0** | 1 |
| `chart-card-shell` | **0** | 0 |

**Πέντε modules δεν επέβαλλαν τίποτα στο CHECK 3.7.**

### 1.2 Αιτία Β — διπλομέτρηση ανά pattern

Το `escape-command-bus` έχει `e\.key\s*===\s*'Escape'` **και** `key\s*===\s*'Escape'`· το δεύτερο
είναι υπερσύνολο του πρώτου. Η γραμμή `useEscapeKey.ts:15` είναι **ένα** bypass, μετριόταν **δύο**.

🔴 **Η επικίνδυνη συνέπεια**: το ratchet συνέκρινε `τρέχον(μηχανή πύλης)` με
`baseline(μηχανή baseline)`, με το δεύτερο **φουσκωμένο κατά 69%**. Ένα αρχείο με baseline 4
μπορούσε να **κερδίσει** παραβιάσεις μέχρι το 4 και να περάσει. **Η πύλη δεν ήταν σφιχτή· ήταν
μετρήσιμα χαλαρή.**

### 1.3 Το test επικύρωνε λάθος μηχανή

Το `registry-golden-regex.test.js` έτρεχε `grep -E` με το σκεπτικό ότι *«το ERE είναι η στενότερη
μηχανή, άρα ασφαλής τομή»* (ADR-294, 2026-07-16). Ο κανόνας εφαρμόστηκε **μισός**: φύλαγε από
κατασκευές JS-only (`(?:...)`) αλλά **όχι** από ERE-only. Το `[[:space:]]` είναι **έγκυρο ERE** ⇒
περνούσε πράσινο ⇒ και ήταν νεκρό στην παραγωγή.

> 🔑 **Ένα test σε μηχανή που κανείς δεν εκτελεί δεν είναι test.**

## 2. Τι κάνουν οι μεγάλοι (έρευνα 2026-08-03)

| Πηγή | Ο κανόνας τους |
|---|---|
| **Google Tricorder** (ICSE'15· SWE book κεφ. 20) | ρητός σχεδιαστικός στόχος: *«consistent view of analysis results… prevents situations in which one developer is trying to fix an issue while another introduces it»* |
| **PHPStan** `--generate-baseline` · **detekt** `--create-baseline` · **ESLint** `--suppress-all` | το baseline παράγεται από **το ίδιο εκτελέσιμο** με τον έλεγχο — ποτέ ξεχωριστό πρόγραμμα |
| **ESLint bulk suppressions** (Απρ. 2025) | κλείδωμα ανά **(αρχείο, κανόνας)**· όταν το πλήθος ανεβαίνει δείχνει **όλες** τις παραβιάσεις: *«Rather than trying to guess which violations to hide, ESLint chooses to show the full picture»* |
| **detekt** finding signatures | fingerprint ανά οντότητα — **τεκμηριωμένα εύθραυστο** ⇒ απορρίφθηκε |
| **SARIF / GitHub code scanning** | σταθερό `ruleId` + `partialFingerprints`· ένα artifact, πολλοί καταναλωτές |
| **Semgrep** | κανόνας-ως-**δεδομένο** ⇒ **υποχρεωτικά** παραδείγματα δύο κατευθύνσεων (`ruleid:` / `ok:`) |

### 2.1 Το δομικό κενό — και πού πάμε παραπέρα

Στο ESLint / PHPStan / detekt ένας κανόνας είναι **κώδικας**, άρα έχει unit tests. Στο δικό μας
μητρώο ένας κανόνας είναι **regex string** — δεδομένο, χωρίς κανένα test. Γι' αυτό η ίδια αστοχία
έχει εμφανιστεί **τέσσερις** φορές:

1. 6 patterns με POSIX (2026-08-03)
2. 3 patterns `xlineMode\.(mode|angleValue|offsetDistance)` — το idiom δεν υπάρχει στον κώδικα
3. `jobs-visibility`: `type\s+JobFilter\s*=` ενώ ο κώδικας γράφει `export interface`
4. ADR-294 v3.0: `(?:...)` που «δεν έπιανε τίποτα» στο ERE

Και οι τέσσερις είναι η ίδια πρόταση: **«0 = κανείς δεν κοίταξε», όχι «καθαρό»**.

**Η δική μας συνεισφορά** πάνω από την πρακτική τους: μια πλήρης σάρωση δίνει **δωρεάν** τη
ζωντάνια ανά pattern. Pattern με μηδέν ευρήματα είναι *καθαρό* ή *νεκρό* — και τα δύο ξεχωρίζουν
**μόνο** από παράδειγμα που εκτελείται στη **μηχανή της πύλης**. Αυτό γίνεται ratchet (§5).

```

  registry.js     φόρτωση μητρώου + ΚΛΕΙΔΩΜΑ ΔΙΑΛΕΚΤΟΥ + μεταγλώττιση
  scan.js         Η ΜΟΝΑΔΙΚΗ μέτρηση  (analyzeFile → Map<module, πλήθος>)
  baseline.js     σχήμα v2, σύγκριση ratchet, εγγραφή
  full-scan.js    ένα πέρασμα στο src/ με worker threads
  proofs.js       απόδειξη ζωής ανά pattern
  pattern-proofs.js  τα ίδια τα παραδείγματα (πρώην test fixture)
        ▲
        ├── check-ssot-imports.js   Η ΠΥΛΗ (CHECK 3.7) + `--generate-baseline`
        ├── ssot-audit.js           Η ΑΝΑΦΟΡΑ (npm run ssot:audit)

```

**Διαγράφηκαν** (τέσσερα αρχεία):

| Αρχείο | Γιατί |
|---|---|

| `scripts/ssot-baseline-engine.js` | το baseline είναι πλέον **σημαία της πύλης** (πρότυπο PHPStan) |

Η κεφαλίδα του `check-ssot-imports.js` **προειδοποιούσε γι' αυτό ήδη από τις 2026-07-16**
(*«two implementations of one gate is how gates silently diverge»*) — και μέσα σε τρεις εβδομάδες
υπήρχαν τέσσερις. Η προειδοποίηση παραμένει, ενισχυμένη.

## 4. Η μονάδα μέτρησης και το σχήμα v2

**Μία γραμμή που παρακάμπτει ΕΝΑ module = ΜΙΑ παραβίαση**, όσα patterns κι αν την πιάνουν.
Γραμμή που παρακάμπτει **δύο διαφορετικά** modules μετράει δύο — δύο SSoT παρακάμφθηκαν.

Αλλιώς ο δείκτης παύει να μετράει τον **κώδικα** και μετράει το **μητρώο**: προσθέτεις ένα
επικαλυπτόμενο pattern και ο αριθμός ανεβαίνει χωρίς να αλλάξει γραμμή κώδικα.

```jsonc
// v1 — σκέτο σύνολο ανά αρχείο
{ "src/a.ts": 4 }

// v2 — ανά αρχείο ΚΑΙ module (κοκκομετρία ESLint)
{ "src/a.ts": { "escape-command-bus": 2, "date-local": 2 } }
```

⚠️ **Γιατί έπρεπε να αλλάξει**: με σκέτο σύνολο επιτρέπεται **ανταλλαγή** — σβήνεις μία παραβίαση
ενός module, προσθέτεις μία άλλου, το σύνολο μένει 4, **η πύλη περνάει**. Ανά module είναι αδύνατο.
Το test `ανταλλαγή παραβίασης μεταξύ modules ⇒ ΜΠΛΟΚ` το κλειδώνει από άκρη σε άκρη.

Το v1 **απορρίπτεται με σφάλμα**, δεν διαβάζεται υποβαθμισμένα: σιωπηλή υποβάθμιση είναι ο
μηχανισμός που γέννησε όλο αυτό — μια πύλη που δουλεύει «κάπως» δεν φαίνεται ποτέ χαλασμένη.

## 5. Κλείδωμα διαλέκτου + απόδειξη ζωής

**Κλείδωμα διαλέκτου** (`registry.js`): το μητρώο έχει **μία** διάλεκτο — ECMAScript, αυτή που
εκτελεί η πύλη. Απορρίπτονται θορυβωδώς: POSIX κλάσεις, GNU `\<` `\>`, inline flags `(?i)`,
atomic `(?>`, `\K`, Python `(?P<>`. Καθεμία είναι είτε συντακτικό σφάλμα σε JS είτε — χειρότερα —
σημαίνει κάτι εντελώς άλλο **χωρίς να παραπονεθεί**.

Το κλείδωμα έχει **αυτοέλεγχο**: 6 γνωστά κακά δείγματα πρέπει να πιάνονται, και 6 έγκυρα
ECMAScript patterns (μαζί με lookahead/lookbehind, που **είναι** εγγενή) να μην πιάνονται. Φρουρός
χωρίς αυτοέλεγχο είναι μονίμως πράσινος.

**Απόδειξη ζωής** (`proofs.js`): τα `shouldMatch`/`shouldSkip` προήχθησαν από test fixture σε
πρωτογενή δεδομένα κανόνα (`lib/ssot/pattern-proofs.js`) — μοντέλο Semgrep, τα tests ζουν δίπλα
στους κανόνες — και τα διαβάζουν **δύο** καταναλωτές: το golden test και το `ssot:audit`.

**Ratchet**: `UNPROVEN_CEILING = 622` patterns χωρίς δηλωμένη απόδειξη. Μόνο μειώνεται· νέο module
φέρνει την απόδειξή του στην ίδια δέσμευση.

Η **τομή** (ούτε δήλωση ούτε ευρήματα στο `src/`) είναι το κοφτερό σήμα και τη δίνει
`npm run ssot:audit -- --dormant`: **606 από 671**. Σκέτο «μηδέν ευρήματα» θα ήταν 651 — αναφορά με
~97% ψευδώς θετικά, δηλαδή αναφορά που κανείς δεν διαβάζει (ο πήχης της Google για blocking checks
είναι ≤10%).

## 6. Τι **δεν** λύνει αυτό το ADR (δηλωμένο)

- **`bim-to-boq-bridge`**: το `BIM_TO_ATOE_MAPPING` ορίζεται στο
  `bim/config/bim-to-atoe-mapping.ts:334`, που **δεν** είναι στο allowlist ⇒ το **σπίτι** της
  σταθεράς καταγγέλλεται (2 παραβιάσεις). Ο κώδικας που **υπάρχει** είναι *καλύτερος* από την
  περιγραφή του μητρώου: πίνακας στο config, πρόσβαση μόνο μέσω `resolveAtoeMapping()`, 10+
  services τον καταναλώνουν έτσι, και το `BimToBoqBridge.ts` δεν τον αγγίζει ποτέ. **Ξένο module —
  εκκρεμεί απόφαση Giorgio + changelog ADR-363.**
- **`xline-mode-store`**: τα 3 patterns φυλάνε idiom (`xlineMode.mode`) που **δεν υπάρχει πουθενά**·
  ο store εξάγει `getMode()`/`setMode()`. **Ξένο module — εκκρεμεί απόφαση Giorgio + ADR-359.**
- **SARIF έξοδος**: δεν υλοποιήθηκε. Ο πυρήνας παράγει ήδη `{module, line, text, pattern}` ανά
  εύρημα, οπότε είναι μηχανική προσθήκη όποτε χρειαστεί ενσωμάτωση με GitHub code scanning.

## 8. Παράπλευρα ευρήματα που διορθώθηκαν

1. **Το `registry-baseline-reconciliation` ήταν ήδη κόκκινο** (326 > 318 ταβάνι). Ο ratchet
   μετρούσε **35 `_comment_*` δείκτες** που είναι **δομικά αδύνατον** να αποκτήσουν `addedDate` —
   μόνιμο, αδιόρθωτο χρέος μέσα σε blocking gate που ζητά «πρόσθεσε addedDate». Πλέον μετρώνται
   μόνο πραγματικά modules· ταβάνι **318 (με θόρυβο) → 285 (πραγματικά)**.
2. **6 modules του ADR-748** (`jobs-registry`, `ribbon-tab-specialties`, `jobs-access`,
   `jobs-visibility`, `job-suggestion`, `effective-permissions-client`) καταχωρήθηκαν 2026-08-02
   **χωρίς `addedDate`**. Απέκτησαν την πραγματική τους ημερομηνία (επαληθεύσιμη από το git).
   **Το gate τα έπιασε· δεν ανέβηκε ταβάνι για να γίνει πράσινο.**
3. **`RECONCILED_AFTER_BASELINE` άδειασε** — οι 8 εγγραφές συμφιλιώθηκαν *κατασκευαστικά* από την
   αναγέννηση του baseline (η επιλογή «(γ)» που ονομάζει το ίδιο το μήνυμα διόρθωσης). Τέσσερις
   έγραφαν ρητά *«Εκκρεμεί ρητή μέτρηση»* — η μέτρηση **έγινε**, ανά module.
4. **Το `test.each` με άδεια λίστα σφάλλει** στο Jest. Αντικαταστάθηκε με ζωντανό ισχυρισμό: ένα
   test που **εξαφανίζεται** όταν αδειάζει η λίστα είναι σιωπηλή τρύπα — ίδια οικογένεια.
5. 🔴 **Το CLAUDE.md N.12 και το `test-execution-budget.md` έλεγαν ψέματα**: *«το `ssot:audit` το
   τρέχει το pre-commit hook»*. **Δεν το τρέχει κανείς.** Το hook τρέχει CHECK 3.7 (staged αρχεία)
   και CHECK 3.18. Το συμπέρασμα «μην το τρέχεις εσύ» μένει σωστό για λόγους κόστους — ο **λόγος**
   ήταν λάθος, και είναι σημαντικό γιατί κανείς δεν επικύρωνε αυτόν τον αριθμό αυτόματα.
