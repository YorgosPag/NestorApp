# ADR-830 — **Η μετάφραση που έφτασε και κανείς δεν ξαναρώτησε**

**Κατάσταση**: **ΟΛΟΚΛΗΡΩΜΕΝΟ** (§4-§7) · μία ανοιχτή, **ξεχωριστή** εκκρεμότητα (§8)
**Ημερομηνία**: 2026-08-30
**Σχετικά**: ADR-744 §11/§15 (bundle registry, route slice — **ο ίδιος** χώρος, **άλλο** ελάττωμα) ·
ADR-777 §8.29 (ένας ιδιοκτήτης για την αλλαγή γλώσσας) · ADR-666 (pseudo locale) ·
ADR-798 §13 (ο μπαλωματής του `t`) · ADR-587 §6.1 («άγκυρα χωρίς πύλη είναι σχόλιο») ·
ADR-749 (μία μηχανή, όχι τέσσερις)

## §1. Το γεγονός, όπως το είδε ο άνθρωπος

Ο χρήστης επιλέγει **English** από τον επιλογέα γλώσσας, με την οθόνη ανοιχτή στο
`/o/[workspace]/listings/mandates/requests`. Το αποτέλεσμα:

| τι | αποτέλεσμα |
|---|---|
| ο **επιλογέας** | ✓ δίπλα στο **English** |
| το **αριστερό μενού** | **αγγλικά** — *Dashboard, Properties, Contacts* |
| οι **ημερομηνίες** | **αγγλική μορφή** — `8/30/2026`, όχι `30/8/2026` |
| το **περιεχόμενο της σελίδας** | **ελληνικά** — *«Εισερχόμενα αιτήματα ανάθεσης»* |

Και έμενε έτσι: **7+ δευτερόλεπτα**, μετά από πλοήγηση σε άλλη σελίδα και πίσω,
**οριστικά**. Μόνο ένα `F5` το διόρθωνε.

Η εύλογη ανάγνωση —*«λείπουν οι αγγλικές μεταφράσεις»*— είναι **λάθος**, και το
μετρήσαμε πριν γράψουμε γραμμή κώδικα:

```
el: 586 κλειδιά · en: 586 κλειδιά · λείπουν στο en: 0
```

Η σελίδα ήταν ήδη **πλήρως** i18n-ized (πίνακες κλειδιών σε
`components/mandate/inbox/mandate-inbox-labels.ts`, μηδέν ωμό ελληνικό στο JSX), ο
loader είχε `case 'property-market'` **και για τις δύο** γλώσσες, και το
`bundle-registry` κρατά κατάσταση ανά **(γλώσσα, namespace)** — σωστά.

**Καμία στατική ανάγνωση δεν μπορούσε να βρει αυτό το ελάττωμα.** Βρέθηκε ζωντανά.

## §2. Η αιτία

Η μέτρηση που κλείδωσε τα πάντα, στην **ίδια στιγμή**, στο ίδιο instance:

```js
i18n.language                                                  // 'en'
i18n.store.getResource('en','property-market','mandate.inbox.title')
// → "Incoming mandate requests"        ← ο store ΕΧΕΙ το σωστό
i18n.t('property-market:mandate.inbox.title')
// → "Εισερχόμενα αιτήματα ανάθεσης"    ← το t() δίνει το ΛΑΘΟΣ
i18n.t('property-market:mandate.inbox.title', { lng: 'en' })
// → "Εισερχόμενα αιτήματα ανάθεσης"    ← ΑΚΟΜΑ ΚΑΙ με ρητή γλώσσα
```

Άρα κάτι μεσολαβεί **μετά** τον store. Ο διαχωρισμός που το απέδειξε:

| κλειδί | ζωγραφίστηκε στο fallback καρέ; | `t()` |
|---|---|---|
| `mandate.inbox.title` | **ναι** | ελληνικά ❌ |
| `mandate.inbox.anonymity` | όχι | **αγγλικά** ✅ |
| `mandate.request.title` (άλλη σελίδα) | όχι | **αγγλικά** ✅ |

Μόνο ό,τι **ζωγραφίστηκε** κόλλησε. Αυτό είναι υπογραφή **cache**, και η τελική
απόδειξη ήταν ένα `icu.mem.en = {}` — το ίδιο `t()`, αμέσως μετά, απάντησε
**«Incoming mandate requests»**.

### Ο μηχανισμός, γραμμή προς γραμμή

Το `i18next-icu@2.4.1` (`dist/commonjs/index.js`):

```js
function getDefaults() {
  return { memoize: true, memoizeFallback: false, bindI18n: '', bindI18nStore: '', … };
}
// …
if (memoize) {
  if (bindI18n)      i18next.on(bindI18n, () => this.clearCache());
  if (bindI18nStore) i18next.store.on(bindI18nStore, () => this.clearCache());
}
// …
var memKey = this.options.memoize && `${lng}.${ns}.${key.replace(/\./g,'###')}`;
var hadSuccessfulLookup = info && info.resolved && info.resolved.res;
if (memoize && (memoizeFallback || !info || hadSuccessfulLookup)) setPath(this.mem, memKey, fc);
```

**Τρία πράγματα συναντιούνται:**

1. **Το `memKey` κρατά τη γλώσσα που ΖΗΤΗΘΗΚΕ, όχι εκείνη από την οποία ΛΥΘΗΚΕ.**
   Στο καρέ όπου `lng === 'en'` αλλά το lazy bundle δεν έχει προσγειωθεί, το i18next
   λύνει μέσω `fallbackLng: 'el'` και επιστρέφει **ελληνικό** κείμενο — που
   αποθηκεύεται κάτω από κλειδί **`en.property-market.mandate###inbox###title`**.

2. **Η δικλείδα `memoizeFallback: false` είναι ΑΝΙΚΑΝΗ.** Φυλάει με
   `hadSuccessfulLookup = info.resolved.res`, δηλαδή *«βρέθηκε κείμενο»* — **αληθές
   και για fallback**. Είναι, άλλη μια φορά, το σχήμα του `CLAUDE.md`: **«βρέθηκε»
   δεν σημαίνει «βρέθηκε στη γλώσσα που ζητήθηκε»**. Η προστασία υπήρχε, είχε το
   σωστό όνομα, και δεν φύλαγε τίποτα.

3. **Το `clearCache()` ΥΠΑΡΧΕΙ και δεν καλείται ΠΟΤΕ.** Δένεται αποκλειστικά μέσω
   `bindI18n` / `bindI18nStore`, που έχουν **`''` ως default**. Το `config.ts:81`
   έγραφε σκέτο **`.use(ICU)`** — μηδέν options ⇒ **οι δύο handlers δεν εγγράφονται
   ποτέ** ⇒ το cache ζει όσο η καρτέλα.

### Γιατί «κάθε σελίδα», και γιατί όχι το κέλυφος

Ο επιλογέας (`language-switcher.tsx:76-85`) προφορτώνει **μόνο** τα
`COMMON_NAMESPACES` (+`admin` στο `/admin`), και το `changeLanguage` προσθέτει τα
`CRITICAL_NAMESPACES`. Αυτά προλαβαίνουν **πριν** το `i18n.changeLanguage` ⇒ το
κέλυφος δεν έχει ποτέ fallback καρέ ⇒ **σωστά αγγλικά**.

Κάθε **άλλο** namespace φορτώνεται lazy από το `useTranslation`, δηλαδή **μετά** την
αλλαγή γλώσσας ⇒ έχει πάντα fallback καρέ ⇒ **μολύνεται**. Επιβεβαιώθηκε ότι το
ελάττωμα δεν ανήκε στη σελίδα: το `/dashboard` έδειχνε *«Καλημέρα, …»* με το μενού
στα αγγλικά.

**Και γι' αυτό η ψυχρή φόρτωση ήταν πάντα σωστή**: εκεί το bundle προσγειώνεται πριν
το πρώτο render του περιεχομένου, οπότε δεν υπάρχει fallback καρέ να αποθηκευτεί.

## §3. Ό,τι απορρίφθηκε, και γιατί

| εναλλακτική | γιατί **όχι** |
|---|---|
| `memoize: false` | Θεραπεύει, αλλά ξανα-μεταγλωττίζει **κάθε** ICU μήνυμα σε **κάθε** render, σε κάθε λίστα, για πάντα. Μόνιμο κόστος σε hot path για πρόβλημα **φρεσκάδας**. |
| Προφόρτωση κι άλλων namespaces στον switcher | Θεραπεύει το **δείγμα**. Το fallback καρέ επιβιώνει για όποιο namespace δεν μπήκε στη λίστα — και η λίστα είναι **χειρόγραφη**, δηλαδή αποκλίνει. |
| `fallbackLng: false` | Σβήνει το σύμπτωμα με **ωμά κλειδιά** στην οθόνη — ανταλλαγή μιας κλάσης ελαττώματος με χειρότερη (ADR-744 §8 το απαγορεύει ρητά). |
| Δικό μας wrapper γύρω από το `t` | Δεύτερη μηχανή δίπλα σε υπάρχουσα (ADR-749). Η βιβλιοθήκη **έχει** τον μηχανισμό· του λείπει η **ρύθμιση**. |
| Χειροκίνητο `clearCache()` στον switcher | Ένας καλών σήμερα, τρεις σε έξι μήνες, και το route slice δεν περνά από εκεί **ποτέ**. |

## §4. Η απόφαση

**`src/i18n/config.ts`** — η **μοναδική** `.use(ICU)` του παραγωγικού κώδικα
(επαληθεύτηκε με grep· οι υπόλοιπες 14 ζουν σε test setups):

```ts
.use(new ICU({
  bindI18n: 'languageChanged',
  bindI18nStore: 'added removed',
}))
```

🔑 **Το `added` είναι το κρίσιμο, όχι το `languageChanged`.** Το δεύτερο πιάνει μόνο
την αλλαγή γλώσσας. Το πρώτο πιάνει **ολόκληρη την κλάση**: *κάθε φορά που κείμενο
προσγειώνεται μετά το πρώτο render* — lazy `loadNamespace`, route slice
(ADR-744 §15), HMR. Το ελάττωμα δεν είναι «η αλλαγή γλώσσας χαλάει»· είναι **«ένα
cache γεμίζει από fallback και δεν ακυρώνεται όταν φτάνει η αλήθεια»**. Η αλήθεια
φτάνει με `added`.

## §5. Το δεύτερο εύρημα — `<html lang>` καρφωμένο στο `el`

Μετρήθηκε στην ίδια συνεδρία: με την οθόνη **ολόκληρη** στα αγγλικά,
`document.documentElement.lang` έμενε **`el`**. Το `app/layout.tsx:66` γράφει
`<html lang="el">` και **σωστά** — είναι Server Component, και το
`getInitialLanguage()` επιστρέφει σκόπιμα πάντα `DEFAULT_LANGUAGE` ώστε server και
πελάτης να συμφωνούν στο πρώτο καρέ. Απλώς **κανείς δεν το διόρθωνε ποτέ μετά**.

Δεν είναι διακοσμητικό: το `lang` είναι η **μόνη** δήλωση που διαβάζουν ο αναγνώστης
οθόνης (αγγλικά διαβασμένα με ελληνική προφορά είναι ακατάληπτα), ο συλλαβισμός, ο
ορθογράφος και οι μηχανές αναζήτησης — ρητή απαίτηση **WCAG 3.1.1**.

Ο συγχρονισμός μπήκε **δίπλα στην αυθεντία** (listener στο `languageChanged` μέσα
στο `config.ts`), **όχι** σε component: ένα `useEffect` σε provider θα ήταν **δεύτερος
ιδιοκτήτης** του ίδιου attribute, ελεύθερος να αποκλίνει και σιωπηλά ανενεργός σε
όποιο δέντρο δεν τον περιλαμβάνει (π.χ. `global-error.tsx`, με δικό του `<html>`).

## §6. Boy Scout

`lazy-config.ts:3` έκανε `import ICU from 'i18next-icu'` με **μηδέν** χρήσεις στο
αρχείο. Ένας νεκρός δρόμος που φαίνεται σωστός είναι χειρότερος από απουσία:
ο επόμενος θα τον έβρισκε με συμπλήρωση κώδικα και θα έστηνε **δεύτερο** ICU δίπλα
στο πρώτο. Διαγράφηκε.

## §7. Οι άγκυρες

`src/i18n/__tests__/icu-cache-invalidation.test.ts` — **5 tests, όλα πράσινα**
(και τα 166 tests των 11 i18n suites πέρασαν, μηδέν παλινδρόμηση).

| test | ρωτά |
|---|---|
| **Κ1** *(παρονομαστής)* | Με σκέτο `.use(ICU)`, **βλέπω τη βλάβη;** Απαιτεί ελληνικό μετά την άφιξη του αγγλικού bundle. |
| **Κ2** | Με τα bindings, το `t()` δείχνει το κείμενο που έφτασε. |
| **Κ2β** | Η **ελληνική** διαδρομή δεν θυσιάστηκε για να διορθωθεί η αγγλική. |
| **Κ2γ** | Το `added` πιάνει την **κλάση**: κείμενο που φτάνει **χωρίς** αλλαγή γλώσσας. |
| **Κ3** | Το **παραγωγικό** `config.ts` ζητά **και τα δύο** bindings — και **δεν** περιέχει σκέτο `.use(ICU)`. |

⚠️ **Το Κ1 είναι το σημαντικότερο.** Χωρίς αυτό, το Κ2 θα μπορούσε να είναι πράσινο
επειδή το ελάττωμα **δεν υπήρξε ποτέ** — σχόλιο μεταμφιεσμένο σε άγκυρα (CHECK 3.54).
⚠️ **Το Κ3 είναι αυτό που μας αφορά.** Τα Κ1/Κ2 περιγράφουν τη **βιβλιοθήκη**· χωρίς
το Κ3, κάποιος ξαναγράφει `.use(ICU)` και τα δύο πρώτα μένουν πράσινα — *«κάλυψη σε
νεκρό δίδυμο δεν είναι κάλυψη»*.

🔬 **Ένα μάθημα από την πρώτη γραφή του Κ3**: κοκκίνιζε επειδή το πληρωμένο σχόλιο
του `config.ts` **αναφέρει** τη γραφή `.use(ICU)` για να την απαγορεύσει. Ένας
έλεγχος που δεν ξεχωρίζει κώδικα από πρόζα **τιμωρεί την τεκμηρίωση**, και η επόμενη
«διόρθωση» θα ήταν να σβηστεί το σχόλιο. Τα σχόλια αφαιρούνται **πριν** τον έλεγχο.

## §8. Ανοιχτό, και **ξεχωριστό** από αυτό το ADR

Το fallback **καρέ** εξακολουθεί να υπάρχει: για ένα σύντομο διάστημα μετά την
αλλαγή γλώσσας, ένα lazy namespace δείχνει το ελληνικό κείμενο πριν το αγγλικό
προσγειωθεί. **Δεν είναι πια μόνιμο** — αυτό ήταν το ελάττωμα και έκλεισε — αλλά
είναι ορατό αναβόσβημα.

⚠️ **ΜΗΝ το «λύσεις» επεκτείνοντας τη λίστα του switcher** (§3). Η σωστή ερώτηση
είναι *«ποια namespaces είναι **ενεργά στην οθόνη τώρα**;»*, και την ξέρει το
`bundle-registry`, όχι μια χειρόγραφη λίστα. Θέλει δικό του σχεδιασμό.
