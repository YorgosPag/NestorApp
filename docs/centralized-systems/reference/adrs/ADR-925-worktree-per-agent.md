## 1. Το ερώτημα

> **«Γιατί δύο πράκτορες μοιράζονται ΕΝΑ working tree και ΕΝΑ ευρετήριο, όταν το git δίνει δωρεάν ένα ανά πράκτορα;»**

## 2. Το πρόβλημα (μετρημένο, όχι θεωρητικό)

Το ADR-924 έλυσε τη **μία** όψη: οι πύλες κρίνουν πλέον το commit, όχι τον δίσκο (ratchet της CHECK 3.107: 84 → 2). Η **ρίζα** μένει:
όλοι οι πράκτορες γράφουν στο ίδιο δέντρο **και** σταδιοποιούν στο ίδιο ευρετήριο. Μετρημένες συνέπειες, όλες από αυτό το repo:

| Συνέπεια | Πού καταγράφηκε |
|---|---|
| Commit 4 αρχείων απέτυχε **3 φορές σε 3 πύλες** για ξένη αστάδιοποίητη δουλειά | ADR-924 §2 |
| Πράκτορας έκανε commit τη **δική μου** WIP (κοινό ευρετήριο) — «`git log`, όχι μόνο `status`» | MEMORY: multi-agent hub |
| Απαγόρευση `stash` / `checkout` / `git add -A` — καθολικές εντολές πάνω σε ξένη δουλειά | κανόνες κάθε handoff |
| Σταδιοποίηση **μόνο των δικών μου γραμμών** με `readIndexText` + `writeIndexBlob` σε αρχεία με ξένες αλλαγές | handoff ADR-924 §0 |
| Η παγίδα της Φ4 βρήκε **19 untracked + 3 αρχεία με ξένες αστάδιοποίητες αλλαγές** στο ίδιο τρέξιμο | ADR-924 §8.10–§8.11 |
| `fleet/lock-guard`: ένα αρχείο, ένας κάτοχος — αλλιώς **μπλοκ** στο Edit | `.claude-rules/fleet/README.md` |

Κάθε ένα από αυτά είναι **μπάλωμα** πάνω στο ίδιο ελάττωμα: δύο ανεξάρτητες εργασίες σε μία κατάσταση.

## 5. Απόφαση

> ⚠️ Ο πίνακας §5.1 είναι η αρχική πρόταση. Όπου διαφέρει, ισχύει η §10.

**Κάθε πράκτορας σε δικό του worktree. Το κύριο checkout γίνεται χώρος ΕΝΣΩΜΑΤΩΣΗΣ — κανείς δεν γράφει εκεί κώδικα.**

### 5.1 Το μοντέλο

| | |
|---|---|
| **Δημιουργία** | `claude --worktree <θέμα>` (ή `EnterWorktree`) ⇒ `.claude/worktrees/<θέμα>/`, κλάδος `worktree-<θέμα>` |
| **Βάση** | `worktree.baseRef: "head"` στο `.claude/settings.json` — 🔴 **όχι** η προεπιλογή `"fresh"`: εκείνη ξεκινά από το `origin/main`, ενώ εδώ τα commits ζουν τοπικά στο `main` για μέρες πριν το push ⇒ ο πράκτορας θα ξεκινούσε από **παλιό** κώδικα |
| **Περιβάλλον** | `.worktreeinclude` (`.env` · `.env.local`)· `pnpm install --offline` (hard links από το store — ίδιος τόμος C:)· `PORT` ανά worktree για dev server |
| **Commit** | με εντολή Giorgio, **στον κλάδο του worktree** (ο hook τρέχει τα scripts του worktree — κρίνει **μόνο** αυτή τη δουλειά: ούτε ξένη αστάδιοποίητη, ούτε ξένο ευρετήριο) |
| **Ενσωμάτωση** | `git rebase main` στο worktree ⇒ `git merge --ff-only worktree-<θέμα>` στο κύριο checkout· σύγκρουση = στο worktree, ποτέ στο `main` |
| **Push** | από το `main`, μόνο με εντολή Giorgio (αμετάβλητο) |
| **Καθαρισμός** | αυτόματος από το Claude Code όταν δεν υπάρχει δουλειά· αλλιώς ερώτηση |

### 5.2 Τι αλλάζει στους υπάρχοντες μηχανισμούς

| Μηχανισμός | Μετά |
|---|---|
| ADR-924 (όψη του commit) | **μένει** — ζώνη ασφαλείας: η δική σου αστάδιοποίητη δουλειά απέναντι στη σταδιοποιημένη· και ό,τι τρέξει ακόμη στο κοινό checkout |
| `fleet/lock-guard` (κλείδωμα αρχείου) | ⬇ περιττό για συγκρούσεις **αρχείων** (κάθε worktree έχει δικά του)· οι **λωρίδες** μένουν χρήσιμες για σημασιολογικές συγκρούσεις (δύο πράκτορες στην ίδια περιοχή ⇒ δύσκολο rebase) |

| κανόνες «ποτέ `stash`/`checkout`/`add -A`» | ισχύουν **στο κύριο checkout**· μέσα στο δικό σου worktree, το δέντρο είναι δικό σου |

## 7. Δηλωμένα όρια και κίνδυνοι

1. **Δίσκος**: 37.763 αρχεία ανά worktree + `node_modules` (hard links ⇒ κυρίως εγγραφές καταλόγου, όχι 2,7 GB). Να μετρηθεί (Φάση 1).
2. **Windows `MAX_PATH`**: χωρίς `core.longpaths` τα βαθιά μονοπάτια του `.pnpm` μέσα σε `.claude/worktrees/<όνομα>/` μπορεί να αποτύχουν.
3. **Θύρες / emulators / βάσεις** δεν απομονώνονται — ένας dev server ανά worktree με δική του `PORT`· ένας Firestore emulator κοινός.
4. **Γεννημένα αρχεία που δεν είναι tracked** (π.χ. `.next/`, cache του 3.70) ξαναχτίζονται ανά worktree — πρώτη εκτέλεση πιο αργή.
5. **Μακροχρόνιοι κλάδοι** = δύσκολα rebase. Κανόνας: μικρά worktrees, ενσωμάτωση συχνά.
6. Οι hooks του Claude Code με `${CLAUDE_PROJECT_DIR}` δείχνουν **στο κύριο checkout** (τεκμηριωμένο)· τα `fleet` hooks γράφουν κοινό `locks.json` — σωστό για λωρίδες.

## 8. Απορριφθείσες εναλλακτικές

- **Κοινό `node_modules` με junction/symlink** σε όλα τα worktrees: γρήγορο, αλλά σπάει την απομόνωση στην πρώτη αλλαγή εξάρτησης (η κοινότητα το αποθαρρύνει ρητά). Μένει **μόνο** ως μετρημένη εφεδρεία αν η Φάση 1 βγάλει απαγορευτικό install.
- **Πλήρες δεύτερο clone ανά πράκτορα**: διπλό `.git`, χωρίς κοινά refs — κάθε ενσωμάτωση γίνεται push/pull. Το worktree μοιράζεται το `.git` δωρεάν.
- **Συνέχεια με κοινό δέντρο + ADR-924**: λύνει τις πύλες, όχι το κοινό ευρετήριο (commit ξένης WIP) ούτε τις απαγορεύσεις `stash`/`checkout`.
- **`git stash --keep-index` πριν τις πύλες**: καθολικό, αγγίζει ξένη δουλειά (ADR-924 §5).

## 10. Τι υλοποιήθηκε (2026-10-31)

### 10.1 Αποφάσεις Giorgio

- **Commit**: ο πράκτορας που έγραψε τον κώδικα, στο δικό του κλαδί, χωρίς εντολή. Εκεί δεν φτάνει ούτε στο `main` ούτε στην παραγωγή.
- **Ένταξη στο `main` και push**: μόνο με εντολή Giorgio.
- **Τρέχουσα αδέσμευτη δουλειά**: δεν αγγίζεται. Η επιβολή ανοίγει στο επόμενο καθαρό σημείο.

### 10.4 Παγίδες που βρέθηκαν στην υλοποίηση

- 🔴 **`--ignore-scripts` άφηνε το `react-compose-refs` χωρίς το patch του React 19** (982 αντί 1.265 bytes). Ένα worktree θα έτρεχε άλλον κώδικα από το κύριο, σιωπηλά. Το `wt:new` τρέχει πλέον ρητά το `patch-radix-react19.js`.
- 🔴 **Το patch έγραφε επί τόπου σε hard link**, δηλαδή στο κοινό store. Τώρα σβήνει πριν γράψει.
- **`git commit --amend` δεν ξανακρίνει τίποτα**: το index ταυτίζεται με το HEAD και το hook βλέπει κενό σύνολο. Γι' αυτό το `wt:land` κάνει `reset --soft` στη βάση, ώστε όλη η αλλαγή να περάσει από τις πύλες.
- **Το git εξάγει `GIT_DIR`/`GIT_INDEX_FILE` μέσα σε hook.** Αν κληρονομηθούν, κλήση git στο `cwd` χτυπά άλλο repo· το `scripts/lib/agent-worktree/git.js` τα αφαιρεί.

- 🔴 **Το `core.autocrlf=true` έδινε CRLF στο worktree, ενώ το git κρατά LF** ⇒ η CHECK 3.84 έκρινε «μπαγιάτικο» χωρίς αλλαγή περιεχομένου. Το `wt:new` παίρνει τα αρχεία αυτούσια (`-c core.autocrlf=false`), οπότε ο δίσκος ταυτίζεται με το git και οι πύλες αποτυπώματος δεν χρειάζονται αλλαγή.
- 🔴 **Το `main` ήταν ελλιπές σε καθαρό αντίγραφο**: η CHECK 3.108 (`3e9671f8`) ζητούσε `scripts/lib/i18n-namespace-family/{baseline,request}.js` και `.i18n-namespace-family-baseline.json`, που δεν έγιναν ποτέ commit. Το κοινό δέντρο το έκρυβε, γιατί τα αρχεία υπήρχαν στον δίσκο. Μπήκαν σε αυτό το κλαδί.
- 🔴 **Το `git worktree remove` αφήνει φακέλους** (3,7 MB σε `node_modules`, `packages`, `src`: 0 αρχεία, 5.404 συνδέσμους). Το `wt:remove` ολοκληρώνει το σβήσιμο και ελέγχει ότι ο φάκελος έφυγε. Για τον κρατημένο φάκελο βλ. §12.

## 11. `.gitattributes` (2026-10-31)

### 11.1 Το πρόβλημα

Το `-c core.autocrlf=false` του `wt:*` καλύπτει μόνο τις δικές του εντολές. Κάθε άλλη εντολή git ακολουθεί τη ρύθμιση του μηχανήματος, άρα οι πύλες αποτυπώματος βλέπουν άλλα bytes σε Windows και σε CI.

### 11.2 Απόφαση

| Κανόνας | Αρχεία | Λόγος |
|---|---|---|
| `* text=auto eol=lf` | προεπιλογή | Το `eol` υπερισχύει του `core.autocrlf`. Το σκέτο `text=auto` θα άφηνε CRLF στα Windows |
| `text eol=crlf` | `.bat`, `.cmd`, `.ps1` | Ο διερμηνέας των Windows. Το repo έχει σήμερα μόνο 19 `.ps1` |
| `-text` | `.dxf`, `.tek` | Κείμενο όπου τα bytes είναι το περιεχόμενο, και το diff μένει χρήσιμο |
| `binary` | εικόνες, γραμματοσειρές, μοντέλα, αρχεία | Η ανίχνευση του git δεν είναι εγγύηση: το `spike-out.pdf` έχει καταγραφεί ως κείμενο |
| εξαίρεση | `recovery/lost-found/*.bin` | Κείμενα με κατάληξη `.bin`. Χωρίς αυτήν, 5 αρχεία εμφανίζονται αλλαγμένα |

Πηγές: [gitattributes](https://git-scm.com/docs/gitattributes) και [GitHub, line endings](https://docs.github.com/en/get-started/git-basics/configuring-git-to-handle-line-endings). Για τα `.ps1` οι πηγές διαφωνούν· κρατήθηκε το CRLF, που είναι ήδη η κατάσταση 13 από τα 19 στον δίσκο.

### 11.4 Όρια

- Το κύριο αντίγραφο **δεν** γίνεται LF από μόνο του: τα αρχεία αλλάζουν μόνο όταν τα ξαναγράψει checkout. Ο πλήρης καθαρισμός του δίσκου του θέλει καθαρό σημείο.
- Οι κανονικοποιήσεις EOL στις πύλες (`scripts/lib/text-eol.js`) και το `EXACT_BYTES` του `wt:*` μένουν ως δεύτερη γραμμή άμυνας.
- 7 αρχεία `.ts`/`.js` και 1 `.md` στα 179 `i/-text` είναι κώδικας ή κείμενο που το git θεωρεί δυαδικό. Δεν άλλαξε τίποτα γι' αυτά.

## 12. `wt:remove`: σύγκλιση σε κρατημένο φάκελο (2026-10-31)

### 12.1 Το ελάττωμα

Το `wt:remove` ήταν σειρά βημάτων με μία είσοδο: απαιτούσε καταχωρημένο worktree και έσβηνε το κλαδί τελευταίο. Μια διακοπή στη μέση άφηνε κλαδί ή φάκελο, και η ίδια εντολή δεν ξανάτρεχε.

### 12.2 Μετρήσεις (Windows, git 2.54, Node 20)

Μια διεργασία κρατά τον φάκελο ή υποφάκελο με το cwd της:

| Πράξη | Αποτέλεσμα |
|---|---|
| `git worktree remove` | Έξοδος **255**, αλλά η καταχώρηση **έχει ήδη σβηστεί** |
| `git branch -d` μετά | Πετυχαίνει |
| `rmSync` με `maxRetries: 10`, κράτημα από cwd | `EBUSY` σε **1 ms**: καμία επανάληψη, ούτε για κράτημα 1,2 δευτ. |
| `rmSync` με `maxRetries: 10`, ανοιχτό αρχείο | `ENOTEMPTY` σε 11 δευτ.: εδώ οι επαναλήψεις τρέχουν |
| `renameSync` του φακέλου | `EBUSY` (ρίζα) · `EPERM` (υποφάκελος) |
| `rmSync` αφού φύγει η διεργασία | Πετυχαίνει |

🔴 Ο κωδικός εξόδου του git δεν λέει τι συνέβη. Το handoff περιέγραφε επιτυχία του git και μετά `EBUSY` στο `rmSync`· με κράτημα από cwd η αποτυχία έρχεται νωρίτερα, μέσα στο ίδιο το git.

### 12.3 Απόφαση

| Κανόνας | Υλοποίηση |
|---|---|
| Σύγκλιση | Κάθε εκτέλεση κοιτά τι υπάρχει (καταχώρηση · κλαδί · φάκελος) και ολοκληρώνει ό,τι βρει |
| Κατάσταση, όχι κωδικός εξόδου | Μετά το `git worktree remove` ξαναδιαβάζεται η λίστα. Αν η καταχώρηση μένει, το git αρνήθηκε πραγματικά (π.χ. `lock`) και δεν αγγίζεται τίποτα |
| Το κλαδί είναι ανεξάρτητο | Σβήνεται με `-d` πριν από τον φάκελο. Το `-d` φυλάει τα commits που δεν εντάχθηκαν |
| Υπόλειμμα = τιμή | `clearResidue` επιστρέφει την αιτία. Το CLI τη δείχνει, λέει πώς συνεχίζεις και βγαίνει με κωδικό 1 |
| Αναμονή | Δικός μας βρόχος, 11 προσπάθειες με γραμμική αύξηση (~11 δευτ.), για διεργασία που κλείνει ή antivirus. Το `maxRetries` του `rmSync` δεν καλύπτει το cwd (§12.2) |
| Από μέσα | Άρνηση πριν από κάθε αλλαγή: το cwd κρατά τον φάκελο, άρα ο πράκτορας κάνει πρώτα `ExitWorktree` |

Φράχτες, επειδή το σβήσιμο είναι πλέον αναδρομικό και χωρίς καταχώρηση:
- Το worktree αναζητείται και κατά φάκελο: σε rebase εμφανίζεται χωρίς κλαδί, και αλλιώς θα περνούσε για υπόλειμμα.
- Φάκελος με `.git` κατάλογο είναι ανεξάρτητο repo: άρνηση.
- Το όνομα περνά από το `assertTask` και ο φάκελος ζει στη ρίζα που ανήκει στο `wt:*`.

Η ίδια μηχανή καθαρίζει και το `discardWorkspace` του `wt:new`.

### 12.4 Απορριφθείσες εναλλακτικές

- **Μετονομασία σε ταφόπλακα και σβήσιμο αργότερα** (`rimraf.moveRemove`): μετρημένα αποτυγχάνει στο ίδιο κράτημα (§12.2), άρα δεν λύνει αυτή την περίπτωση.
- **`rimraf` στο σενάριο**: υπάρχει ήδη στο `package.json`, αλλά η αναμονή που χρειάζεται εδώ είναι μία γραμμή βρόχου γύρω από το `rmSync`, και η τεχνική που τον ξεχωρίζει (move-remove) απορρίφθηκε παραπάνω.
- **Εύρεση ή τερματισμός της διεργασίας**: το `handle.exe` δεν υπάρχει στο μηχάνημα, και το να σκοτώνεις ξένη διεργασία δεν είναι δουλειά εντολής καθαρισμού.

Πηγές: [Node.js `fs.rmSync`](https://nodejs.org/api/fs.html#fsrmsyncpath-options), [rimraf](https://github.com/isaacs/rimraf), [git-worktree](https://git-scm.com/docs/git-worktree).
