> 🎯 **Σε μία πρόταση**: η διαθεσιμότητα μιας αγγελίας είναι **ρητά** «έτοιμη», «προγραμματισμένη μέσα σε δηλωμένο
> διάστημα» ή «άγνωστη», και η μηχανή ταιριάσματος υπόσχεται μόνο ό,τι είναι σίγουρο: το **τέλος** του διαστήματος.

## §1. Το πρόβλημα

Ο παλιός τύπος ήταν `{ from: string | null; to: string | null } | null`. Το `from: null` σήμαινε **δύο** πράγματα:
«διαθέσιμο ήδη» **ή** «άγνωστη αρχή». Και η ζήτηση «Τώρα» δεχόταν **κάθε** αγγελία χωρίς δήλωση, με το σκεπτικό
«αφού δημοσιεύτηκε, είναι διαθέσιμη». Αυτό έβγαζε σε ζήτηση «Τώρα» και διαμερίσματα που ακόμη χτίζονται.
Κανένας παραγωγός δεν γέμιζε το πεδίο (§8.99.2), άρα το διφορούμενο δεν είχε φανεί ακόμη.

## §2. Έρευνα *(ADR-777 §8.99.4, 2026-10-23)*

- **idealista**: «Fecha de entrega de llaves: 3er trimestre 2027», ακρίβεια τριμήνου, μόνο για προβολή.
- **ImmoScout24**: «Verfügbar ab Q1 2027 / ημερομηνία», συχνά ελεύθερο κείμενο· βρέθηκε ληγμένη υπόσχεση.
- **RESO**: `AvailabilityDate`, μία ημερομηνία, χωρίς ακρίβεια και χωρίς λήξη.
- **Zillow / Rightmove**: φίλτρο ημερομηνίας μόνο στις ενοικιάσεις. Δεν βρέθηκε τεκμήριο για το πώς χειρίζονται
  τις αγγελίες χωρίς ημερομηνία. Η τεκμηριωμένη πρακτική είναι ότι η ενεργή αγγελία μεταπώλησης είναι διαθέσιμη
  από το status της **πηγής** (MLS), και τα νεόδμητα δηλώνουν ημερομηνία.
- **Κανείς** δεν ταιριάζει ζήτηση πάνω στην ημερομηνία.

## §3. Η απόφαση

```ts
type ListingAvailability =
  | { kind: 'ready' }
  | { kind: 'scheduled'; precision: 'quarter' | 'month' | 'day'; window: { start: string; end: string } }
  | { kind: 'unknown' };
```

| Ζήτηση | `ready` | `scheduled` | `unknown` |
|---|---|---|---|
| `whenever` | ✓ | ✓ | ✓ |
| `now` | ✓ | `window.end ≤ σήμερα` | `availability-unknown` |
| `window` | ✓ (Δ4) | `window.end ≤ toDate` | `availability-unknown` |

1. **Τρεις καταστάσεις, καμία διφορούμενη (Δ4).** Το `ready` είναι ρητό και ταιριάζει σε κάθε διάστημα.
2. **Αποθηκεύεται διάστημα, κρίνεται το τέλος (Δ2).** «Γ' τρίμηνο 2027» = 2027-07-01…2027-09-30. Η οθόνη ξαναγράφει
   «Γ' τρίμηνο», ενώ η μηχανή υπόσχεται μόνο το 30/9.
3. **Το διάστημα δεν χτίζεται με το χέρι.** Μόνος κατασκευαστής είναι το `scheduledAvailability(precision, anchor)`,
   που αρνείται ανύπαρκτη ημέρα (2027-02-30 ⇒ `unknown`, όχι 2 Μαρτίου).
4. **Το `unknown` δεν είναι ποτέ «διαθέσιμο», ούτε στο «Τώρα».** Η πρακτική της αγοράς ζει στην **πηγή**: ο επιλυτής
   (βήμα 3) δίνει `ready` στο έτοιμο ακίνητο, και `unknown` μένει μόνο όπου πραγματικά δεν ξέρουμε.
5. **Χωρίς «λήξη διαθεσιμότητας» (`to`).** Κανένας παραγωγός, καμία πηγή, κανένα πρότυπο (RESO/idealista/ImmoScout24).
6. **Ο τύπος ζει στο `types/`**, δίπλα στο `PublicListing`, γιατί το βήμα 3 τον βάζει στην αγγελία. Το λεξιλόγιο της
   ζήτησης τον **εισάγει**, όπως το `PlaceRef`.
7. **Ένα σημείο κρίσης**: το `timingBlockers`. Η ειδοποίηση μετάθεσης (βήμα 6) θα ρωτά τη μηχανή, δεν θα ξανακρίνει.

## §4. ⚠️ Συνέπεια σειράς

Μέχρι το βήμα 4 (`listingAvailabilityOf`) **όλοι** οι παραγωγοί δίνουν `LISTING_AVAILABILITY_UNKNOWN`
(`listing-resolver.ts`, `place-interest.service.ts`, `demand-answer.ts`). Άρα μια ζήτηση «Τώρα» δείχνει
«δεν ξέρουμε» αντί για αποτελέσματα. **Το βήμα 1 δεν αναπτύσσεται μόνο του**· φεύγει μαζί με τα βήματα 2–4.
