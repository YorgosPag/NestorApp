# ADR-769 — `live`: ο πίνακας **ζητάει** αλλαγή στον ιδιοκτήτη (write-back)

- **Κατάσταση**: ✅ κλειστό (2026-08-08, δύο συνεδρίες) — πυρήνας §7.1 · σύνδεση + παρουσίαση §7.2
- **Φορέας**: **ADR-766 §8 Βήμα 3** — η ναυαρχίδα, δηλωμένη «υψηλού ρίσκου»
- **Προηγούμενο**: **ADR-767** (Φ.ΣΤ `bound`) ✅ έκλεισε — μονόδρομο, πηγή→πίνακας
- **Υλοποιεί**: ADR-739 Φ.Η · ADR-766 **Α2** (ΕΝΑΣ ιδιοκτήτης) + **Α4** (καμία σιωπηλή μαντεψιά)
- **Αφετηρία (μετρημένη 08/08)**: `bim/table/` → **97 σουίτες / 2.265 πράσινα**

---

## 1. Τι ζητάει το Βήμα 3, σε μία πρόταση

Ο χρήστης γράφει σε κελί **δεμένου** πίνακα και αλλάζει η **οντότητα** — ο πίνακας δεν κρατά
την τιμή, τη **ζητάει** από τον ιδιοκτήτη, που εκτελεί **ή αρνείται με λόγο**.

## 2. 🔴 Η ΑΦΕΤΗΡΙΑ — μετρημένη με grep, όχι διαβασμένη από ADR

### 2.1 Ο ιδιοκτήτης του κανονικού παραδείγματος **υπάρχει ήδη γραμμένος**

Το ADR-766 Α2 δίνει ως παράδειγμα *«ο χρήστης γράφει 391.698,4 στη γραμμή 14 → μετακίνησε την
κορυφή 14»*. Αυτή η εντολή **υπάρχει**:

```
core/commands/entity-commands/MoveTopoSurveyPointCommand.ts   (ADR-662 §13)
  · undoable, snapshot-based
  · τρία βήματα ως ΓΡΑΠΤΟ ΣΥΜΒΟΛΑΙΟ: πηγή → παράγωγο → εξαρτημένα
  · reconcileAssociativeGeometry σύγχρονα ΜΕΣΑ στην εντολή (ADR-492: όχι reactive effect)
  · fromDrag() → null όταν τίποτα δεν άλλαξε (idempotency, N.7.2 #3)
```

⇒ **Η Φ.Η δεν χτίζει σύστημα εντολών, και δεν χτίζει καν εντολή.** Χτίζει **έναν μεταφραστή**:
κελί → αίτημα → **υπάρχουσα** εντολή. Η μόνη προσθήκη στην εντολή είναι εργοστάσιο από
**απόλυτη** τιμή (ο πίνακας δίνει απόλυτη· το `fromDrag` δέχεται delta).

### 2.2 Οι δύο φρουροί υπάρχουν ήδη

| Φρουρός | Πού | Τι απαντά |
|---|---|---|
| `assertCanEditLayer` | `core/commands/text/CanEditLayerGuard.ts` | *frozen ⇒ μπλοκ άνευ όρων· locked ⇒ μπλοκ χωρίς `canUnlockLayer`* — **ακριβώς** ο κανόνας της ArchiCAD |
| `bim/validators/*` (7) | `wall`·`beam`·`column`·`foundation`·`opening`·`slab`·`slab-opening` | ρητό pattern *hard errors block / code violations warn* |

### 2.3 🔴 Το `TableRowLink`: το ADR-767 §10 #4 διαβάζεται λάθος — **διορθώθηκε**

Το §10 #4 γράφει *«`TableRowLink` με `origin:'bound'` **αυτόματα** — ΑΝΟΙΧΤΟ»*. Η στενή
διατύπωση είναι σωστή· το συμπέρασμα που βγάζει ο αναγνώστης («δεν υπάρχει δεσμός γραμμής»)
είναι **λάθος**. Μετρημένο 08/08:

```
buildTableRowLinkIndex   → table-model-helpers.ts:194    round-trip     ✅ συνδεδεμένο
toPersistedTableRowLinks → table-model-helpers.ts:380    round-trip     ✅ συνδεδεμένο
dropTableRowLink         → table-row-column-ops.ts:371   καθαρισμός     ✅ συνδεδεμένο
setTableRowLinks         → ΜΗΔΕΝ καλούντες   ← ο ΠΑΡΑΓΩΓΟΣ
resolveTableRowLink      → ΜΗΔΕΝ καλούντες   ← ο ΚΑΤΑΝΑΛΩΤΗΣ
needsAttention           → ΜΗΔΕΝ καλούντες
```

**Η αποθήκευση είναι πλήρως συνδεδεμένη· ο παραγωγός και ο καταναλωτής απόντες και οι δύο.**
Το πεδίο ταξιδεύει σωστά σε Firestore, καθαρίζεται σωστά σε διαγραφή γραμμής, και **δεν μπορεί
δομικά παρά να είναι κενό** — γιατί κανείς δεν το γεμίζει ποτέ. **Έκτη** εμφάνιση του «το πεδίο
υπάρχει, κανείς δεν κοιτάζει». ⚠️ **ΜΗΝ γράψεις δεύτερο μοντέλο δεσμού γραμμής** — υπάρχει
ολόκληρο, με διακριτή ένωση `ids|query`, `origin` και resolver **5 καταστάσεων**.

### 2.4 Το `TableCell.locked` είναι **δηλωμένο και ανεπίβλητο**

Μοναδικός μη-σχολιακός αναγνώστης: `table-range-transfer.ts:177/213/230` — **μεταφέρεται**,
ποτέ δεν **ελέγχεται**. Το σχόλιό του (`types/table.ts:292`) δείχνει ρητά σε αυτό το ADR.

### 2.5 🔴 Η αντίστροφη χαρτογράφηση **δεν είναι παράγωγη**

```ts
// survey-tables.ts:62 — ο εμπρός χάρτης
rows = points.map((p, i) => ({ cells: {
  index: i + 1,        // ΠΑΡΑΓΩΓΟ (αύξων) — Revit: «value, not parameter» ⇒ ΠΟΤΕ γράψιμο
  x: p.x,              // άμεση παράμετρος
  y: p.y,              // άμεση παράμετρος
  z: p.z ?? null,      // άμεση — ΑΛΛΑ null ≠ 0 (ADR-720)
  code: p.code ?? '',  // άμεση
}}));
```

Στους BIM mappers το ίδιο σχήμα, ανακατεμένο: `width: safeNumber(p.width)` (γράψιμο) δίπλα σε
`concreteWeightKg(...)`, `computeColumnReinforcementQuantities(...)`, `shortId(entity.id)`
(**ποτέ** γράψιμα). Ο mapper είναι **αυθαίρετος κώδικας TS** ⇒ η αντιστροφή δεν εξάγεται
αυτόματα, πρέπει να **δηλωθεί**. Δες Δ2.

## 3. 🔴 ΤΙ ΚΑΝΟΥΝ ΟΙ ΜΕΓΑΛΟΙ — τεκμηριωμένο, με πηγές

### 3.1 Γραψιμότητα κελιού

| Σύστημα | Πρακτική |
|---|---|
| **Revit** | Αμφίδρομο εξ ορισμού. Αλλά τα *calculated values* **ποτέ**: *«are not recognized by Revit as parameters, only as values»* ⇒ γκριζαρισμένα. Ίδιο για Key Schedule ⇒ *«read-only instance parameters that are greyed out»* |
| **ArchiCAD** | *«Any changes made in the **editable fields** are automatically and instantly reflected in the Floor Plan»*. 🔑 **Οπτική γραμματική**: *«parameters that cannot be edited are shown in black, editable ones in blue type»* — η γραψιμότητα **φαίνεται πριν** τη γραφή |
| **ArchiCAD (φρουρός)** | 🔑 *«make sure the layer of the elements included in the schedule is turned on and **not locked**»* — φρουρός είναι **ο ιδιοκτήτης**, όχι το κελί |
| **AutoCAD** | Κλείδωμα κελιού σε **δύο άξονες**: *«You can lock the **Content**, **Format**, or both»*. ⚠️ Γνωστό ελάττωμα: *«after the data link is removed the cell content of the tables remain locked»* |

### 3.2 Αμφισβητούμενη αλλαγή ⇒ **πρόταση**, ποτέ σιωπηλή εγγραφή

- **Navisworks Quantification**: νέα έκδοση μοντέλου ⇒ *«you can then **accept or reject** the
  change»* (`Update Selected by the Model`). **Επικυρώνει το Δ3 του ADR-767** ως βιομηχανική πρακτική.
- **Revit — ακτίνα βλάβης**: γραφή σε *type parameter* από schedule ⇒ **μη-καταστέλλσιμη**
  προειδοποίηση *«This change will be applied to all elements of type»*. Όταν **ένα** κελί
  αγγίζει **Ν** οντότητες, ο χρήστης ενημερώνεται **πριν**, χωρίς «μην με ξαναρωτήσεις».

### 3.3 🔑 Ταυτότητα — **δύο ταυτότητες, ποτέ μία**· και **ποτέ** η ανθρώπινη

| Σύστημα | Εφήμερη | **Ανθεκτική** (δένεις μ' αυτήν) | Ανθρώπινη (**ΔΕΝ** δένεις) |
|---|---|---|---|
| **AutoCAD** | `ObjectId` — *«exists only while the database is loaded… memory address, not the same from session to session»* | **`Handle`** — *«persistent between sessions… constant throughout its life»* | — |
| **Revit** | `ElementId` | **`UniqueId`** → IFC GUID — *«unique across sessions»* | `Mark` |
| **Civil 3D** | — | DWG handle | **Point Number** — μοναδικός αλλά **renumberable**· *«primarily an organizational tool rather than a persistent identity»* |
| **Figma** | — | node id | **layer name** |

🔴 **Το αρνητικό τεκμήριο είναι το πιο διδακτικό.** Το Figma δένει τα overrides με το **όνομα
του layer** — την ανθρώπινη ταυτότητα — και **γι' αυτό ακριβώς σπάει**: *«Figma only preserves
text overrides. To keep any changes, **rename the layers so they're unique**»*. Το Civil 3D
πληρώνει το ίδιο με το renumbering. ⇒ **Ούτε θέση, ούτε `pointNumber`.**

### 3.4 🏆 Το πρωτόγονο που λύνει το υπόλοιπο: **compare-and-swap**

Έξω από τον χώρο του CAD, το πρόβλημα «διάβασα, ο κόσμος άλλαξε, τώρα γράφω» έχει **ένα**
καθιερωμένο όνομα: *optimistic concurrency control*. Η σημασιολογία είναι ομόφωνη σε
PostgreSQL (`WHERE version=?`), DynamoDB (`ConditionExpression`), Redis (`WATCH/EXEC`),
Cassandra (`IF version=`) — τρία ορίσματα: **θέση, ΑΝΑΜΕΝΟΜΕΝΗ τιμή, νέα τιμή**, και
*«writing succeeds only when the content last read by the app is the same as the currently
persisted content»*.

🏆 **Το `sourceValue` του ADR-767 Δ2 ΕΙΝΑΙ ήδη το «content last read»** — το ADR το ονόμασε
ρητά **merge base, όπως το git**. Άρα ο φρουρός γραφής είναι CAS πάνω σε πεδίο που **ήδη
υπάρχει, ήδη ταξιδεύει, ήδη είναι ελεγμένο**. Μηδέν νέα μηχανική.

### 3.5 Cinema 4D — Take System (επικυρώνει το Δ2 του 767)

Οι παρακάμψεις ζουν στο *take*, η βάση μένει ανέγγιχτη, `BaseTake::Reset()` τις καθαρίζει.
Ίδιο μοντέλο με Figma/Δ2. 🔑 Και έχει **override groups** — παράκαμψη πάνω σε **επιλογή**, όχι
σε ένα αντικείμενο· η ίδια ανάγκη με την «ακτίνα βλάβης» του Revit (§3.2).

## 4. ΟΙ ΑΠΟΦΑΣΕΙΣ

### Δ1 — Ο πίνακας **ζητάει**: ένας μεταφραστής, **μηδέν** νέα εντολή

```
κελί επεξεργάζεται
   → TableWriteBackRequest  {γραμμή, στήλη, νέα τιμή, ΑΝΑΜΕΝΟΜΕΝΗ βάση}
   → φρουροί (Δ3·Δ4·Δ5) → ρητή απάντηση
   → ΥΠΑΡΧΟΥΣΑ εντολή του ιδιοκτήτη (MoveTopoSurveyPointCommand)
   → ο πίνακας ΞΑΝΑΡΩΤΑΕΙ (Δ6)
```

⛔ **Καμία νέα οικογένεια εντολών.** Το Α2 δεν εισάγει νέα μηχανική· το ADR-764 έκλεισε ήδη τη
γραφή+επαναϋπολογισμό.

### Δ2 — Η γραψιμότητα είναι ιδιότητα **ΣΤΗΛΗΣ**, δηλωμένη **δίπλα στον εμπρός χάρτη**

Ο περιγραφέας ζει στο **ίδιο αρχείο** με το `COORDINATE_COLUMNS` (`survey-tables.ts`) και είναι
**εξαντλητικός στον τύπο**: κάθε στήλη δηλώνει είτε `derived` (με **λόγο**) είτε `writable` (με
τον μεταφραστή της). Νέα στήλη χωρίς απόφαση ⇒ **δεν μεταγλωττίζεται**.

🔴 **Γιατί ΟΧΙ ξεχωριστό αρχείο/μητρώο**: δύο χειρόγραφες λίστες **αποκλίνουν σιωπηλά** — αυτό
το repo το πλήρωσε **τέσσερις φορές** (CHECK 3.34: δύο λίστες namespace που απέκλιναν κατά
**63**· CHECK 3.37: συγκεντρωτής με **18** ενώ το δέντρο είχε **26**). Δίπλα-δίπλα, ο ίδιος
αναγνώστης βλέπει και τις δύο κατευθύνσεις σε μία οθόνη.

Πρότυπο: Revit (§3.1) — *παράγωγο ⇒ ποτέ γράψιμο*. Η στήλη `index` είναι αύξων αριθμός, δηλαδή
**value, not parameter**.

### Δ3 — Ταυτότητα: **compare-and-swap πάνω στο υπάρχον merge base**· ανθεκτικό id **όχι ακόμη**

Ο εντοπισμός του στόχου γίνεται με **θέση** (συνεπές με τα δύο υπάρχοντα σημεία:
`buildCoordinateTable` δείκτης `i` · `MoveTopoSurveyPointCommand(pointIndex)`), αλλά **καμία
γραφή δεν εκτελείται χωρίς να ισχύει ακόμη η βάση σύγκρισης**: ο φρουρός απαιτεί ότι τα
`sourceValue` **των υπόλοιπων κελιών της γραμμής** ταιριάζουν με το σημείο-στόχο. Αστοχία ⇒
ρητή κατάσταση `source-moved`, **ποτέ** γραφή.

⇒ **Γραφή σε λάθος στόχο είναι δομικά αδύνατη.** Αυτό είναι **αυστηρότερο** από ό,τι κάνει
οποιοσδήποτε από τους τέσσερις: το AutoCAD αφήνει τα κελιά κλειδωμένα μετά την αφαίρεση του
δεσμού· το Excel σβήνει σιωπηλά· το Figma χάνει σιωπηλά τις παρακάμψεις.

🔴 **Γιατί ΔΕΝ προσθέτουμε τώρα `TopoPoint.id`**, παρότι οι μεγάλοι έχουν ανθεκτική ταυτότητα:
οι μεγάλοι την έχουν επειδή έχουν **μακρόβιους** δεσμούς (IFC export, εξωτερική βάση). Εδώ
**δεν υπάρχει ακόμη κανένας καταναλωτής**: το `TableRowLink` δεν παράγεται από κανέναν (§2.3),
και το Δ3 του ADR-767 (καμία αυτόματη ανανέωση) σημαίνει ότι ο πίνακας δείχνει στιγμιότυπο.
Πεδίο χωρίς καταναλωτή θα ήταν η **έβδομη** εμφάνιση του σχήματος που το ADR-767 §8 #7
απαγορεύει ρητά για τον εαυτό του. **Η ανθεκτική ταυτότητα μπαίνει όταν έρθει ο καταναλωτής
(παραγωγή `TableRowLink`), με το πρότυπο Α3 — προαγωγή κατ' απαίτηση, όχι GUID σε δύο
εκατομμύρια σημεία νέφους.** Καταγράφεται στο §9 ως ανοιχτό **με λόγο**, όχι από παράλειψη.

### Δ4 — Άκυρη τιμή: **άρνηση με λόγο**, ποτέ clamp, ποτέ μαντεψιά

Ρητές καταστάσεις, καμία σιωπηλή απόρριψη (πρότυπο CHECK 3.35/3.36). Καταναλώνει τους
**υπάρχοντες** validators: *hard error ⇒ άρνηση· code violation ⇒ προειδοποίηση που δεν
μπλοκάρει*. Ειδικά για το `z`: **κενό κελί ⇒ `undefined`, ΠΟΤΕ `0`** (ADR-720) — και επειδή
αυτό είναι **σβήσιμο μέτρησης**, θέλει ρητή επιβεβαίωση (Α4), όχι σιωπηλή εκτέλεση.

⚠️ **Μονάδες**: η στήλη είναι `dimension-mm-to-m` — ο χρήστης γράφει **μέτρα**, ο store κρατά
**mm**. Ο μεταφραστής κάνει τη μετατροπή **ρητά και με test** (ADR-716: «η διαγώνιος είναι
δομικά ανίκανη — λύση = ΑΠΟΔΕΙΞΗ»).

### Δ5 — `TableCell.locked` = **βέτο του ανθρώπου στο ΠΕΡΙΕΧΟΜΕΝΟ**, επιβεβλημένο

Πρότυπο: AutoCAD *«lock the **Content**, Format, or both»*. Παίρνουμε **τον έναν άξονα** που
έχει καταναλωτή — το περιεχόμενο· η **μορφοποίηση μένει ελεύθερη**, ακριβώς όπως το Δ1 του
ADR-767 το όρισε ήδη για την αντίθετη κατεύθυνση.

🔴 **Ποτέ καθρέφτης παράγωγης κατάστασης.** Η παράγωγη μη-γραψιμότητα (στήλη `derived`,
κλειδωμένο layer, υπολογισμένη τιμή) **μένει παράγωγη** και δεν γράφεται ποτέ στο πεδίο —
αυτό θα ήταν το αντιπρότυπο του ADR-720 §3.1 («ελέγχεται σε τέσσερα σημεία από τα πέντε»).
Το πεδίο απαντά **μόνο** «ο άνθρωπος είπε μη μ' αφήσεις να το αλλάξω κατά λάθος» — ερώτηση
που **κανείς άλλος δεν απαντά**, δηλαδή το ίδιο σκεπτικό με το `TopoPoint.zSource` (ADR-731).

### Δ6 — Μετά την επιτυχή γραφή, ο πίνακας **ξαναρωτάει** — και το Δ3 του ADR-767 **μένει δεσμευτικό**

Ο ιδιοκτήτης εκτέλεσε ⇒ ο πίνακας ζητά **στοχευμένη** επανεπίλυση της γραμμής του, στην **ίδια**
χειρονομία (ένα `Ctrl+Z`, όπως ADR-764 §5.3). ⛔ **Αυτό ΔΕΝ γίνεται συνδρομή.**
`subscribeTopo(() => refresh())` **ακυρώνει το Δ3** και το απαγορεύουμε ρητά. Το early cutoff
(ADR-767 Δ5) και η **ταυτότητα by-reference** χρησιμοποιούνται όπως είναι — δεν ξαναχτίζονται.

### Δ7 — Η γραψιμότητα **φαίνεται πριν** τη γραφή — **οθόνη μόνο**

Πρότυπο ArchiCAD (μπλε/μαύρο). Αλλά υπακούει στο **Δ4 του ADR-767**: ένδειξη **μόνο οθόνη**,
ποτέ σε εκτύπωση/DXF. 🔴 Ο φρουρός είναι **`getPrintColorPolicy() !== null`** — το
`skipInteractive` **ΔΕΝ** τον αντικαθιστά (το περνά και το bitmap cache, που είναι οθόνη).

### Δ8 — Ακτίνα βλάβης: **δηλώνεται πριν**, όταν ένα κελί αγγίζει Ν

Πρότυπο Revit (§3.2). Στον πίνακα συντεταγμένων η σχέση είναι **πάντα 1:1**, οπότε δεν
ενεργοποιείται σήμερα — καταγράφεται ως **δεσμευτικός κανόνας για τον δεύτερο καταναλωτή**
(BIM schedules, όπου μια στήλη τύπου αγγίζει όλα τα στιγμιότυπα).

### Δ9 — Εύρος: **μόνο ο πίνακας συντεταγμένων**, λεξιλόγιο γενικευμένο από την πρώτη μέρα

Ακριβώς το πρότυπο του Δ7 του ADR-767 (*«υλοποιείται ΜΙΑ καταχώρηση resolver… το σχήμα
σχεδιάζεται για όλους»*). Οι **44** τυποποιημένες `Update*ParamsCommand` είναι ο **δεύτερος**
καταναλωτής, όχι ο πρώτος.

## 5. 🔴 Τα σημεία που θα σπάσουν **σιωπηλά**

| # | Κίνδυνος | Τι το αποτρέπει |
|---|---|---|
| 1 | Βρόχος write-back (πίνακας γράφει → ειδοποίηση → ξαναγράφει) | Α2 (ΕΝΑΣ ιδιοκτήτης) + Δ6 (**καμία** συνδρομή) + early cutoff |
| 2 | Το `refresh()` γίνεται αυτόματο «τώρα που έχουμε write-back» | Δ6 — το Δ3 του ADR-767 **μένει δεσμευτικό** |
| 3 | Δεύτερο μοντέλο δεσμού γραμμής, επειδή το ADR έλεγε «ανοιχτό» | §2.3 — υπάρχει ολόκληρο |
| 4 | Γραφή σε **λάθος** σημείο μετά από μετακίνηση της πηγής | Δ3 — CAS· `source-moved` ⇒ άρνηση |
| 5 | `0` αντί για κενό στο `z` | Δ4 + ADR-720 |
| 6 | Μέτρα γράφονται ως χιλιοστά (ή αντίστροφα) | Δ4 — ρητή μετατροπή **με test** |
| 7 | Ένδειξη γραψιμότητας διαρρέει στο **ΧΑΡΤΙ** | Δ7 — `getPrintColorPolicy() !== null`, **όχι** `skipInteractive` |
| 8 | Νέα κατάσταση κελιού αλλάζει το **bitmap cache key** | ADR-040 #3 — paint-time κατάσταση ⇒ *subscribe → `invalidate()`* |
| 9 | Ωμό ελληνικό σε JSX | N.11 · **κανένα static gate δεν το βλέπει** — ο άνθρωπος είναι η πύλη |

## 6. Tests — **γράφονται πριν τον κώδικα**

- στήλη `derived` (`index`) ⇒ **ποτέ** γράψιμη· ρητός λόγος, όχι σιωπηλή απόρριψη
- στήλη `writable` ⇒ παράγει αίτημα με **σωστές μονάδες** (μέτρα → mm)
- CAS: αμετάβλητη πηγή ⇒ γραφή· **μετακινημένη** πηγή ⇒ `source-moved`, **καμία** εγγραφή
- κενό `z` ⇒ `undefined`, **ποτέ** `0`
- `locked: true` ⇒ άρνηση· η **μορφοποίηση** του ίδιου κελιού παραμένει ελεύθερη
- κλειδωμένο/παγωμένο layer ⇒ άρνηση μέσω `assertCanEditLayer` (**όχι** δεύτερος έλεγχος)
- επιτυχής γραφή ⇒ **μία** χειρονομία, **ένα** undo (ADR-764 §5.3)
- ίδια τιμή ⇒ **καμία** εντολή, **καμία** εγγραφή στο ιστορικό (idempotency)
- η ένδειξη γραψιμότητας **δεν** εμφανίζεται στο μονοπάτι εξαγωγής

## 10. Δ7 υλοποιημένο — η λωρίδα λέει **και** τη γραψιμότητα

Η λωρίδα του δεσμού (ADR-767 Δ8) κουβαλά πλέον `writable: boolean`, και ο ζωγράφος βάζει
`fillStyle` **ανά λωρίδα**: `columnAlpha` για τη γράψιμη, `readOnlyColumnAlpha: 0.22` για την
άλλη.

**Γιατί ένταση και όχι τέταρτο χρώμα.** Το ArchiCAD δηλώνει τη γραψιμότητα με **χρώμα**
(*«non-editable in black, editable in blue»*) επειδή εκεί ο φορέας είναι το **κείμενο** του
κελιού. Εδώ ο φορέας είναι η λωρίδα, που ήδη λέει «τρέφομαι από πηγή», και το μπλε της είναι
**πιασμένο**: είναι το `INDICATOR_BLUE`, το χρώμα «δείκτη» όλου του viewer. Τέταρτο χρώμα στην
ίδια λωρίδα θα ζητούσε από τον χρήστη να θυμάται **τέσσερα** μπλε. Η ένταση λέει το ίδιο με
λιγότερο λεξιλόγιο, και είναι η λέξη που χρησιμοποιεί το ίδιο το Revit για τα calculated
values: *«read-only… greyed out»*.

**Γιατί στη λωρίδα και όχι σε σημάδι κελιού.** Ίδιος λόγος με τον δεσμό (Δ8): η γραψιμότητα
είναι ιδιότητα **ΣΤΗΛΗΣ** (Δ2). Σημάδι ανά κελί θα δήλωνε γεγονός που το σχήμα **δεν έχει** —
και θα ήταν **800 σημάδια** σε τοπογραφικό 200 κορυφών για να ειπωθεί κάτι που ισχύει σε
ολόκληρη τη στήλη.

⚠️ **Οθόνη μόνο**, όπως όλη η οικογένεια — φρουρός `getPrintColorPolicy()` στο
`stamp-table-bound-state.ts`, **όχι** `skipInteractive`.
⚠️ Η γραψιμότητα ρωτιέται από το **μητρώο της πηγής** (`tableSourceColumnWriteBack`) και δεν
ξαναγράφεται στον ζωγράφο. Πίνακας που δηλώνει `sourceKey` χωρίς δεσμό είναι ασυνεπής ⇒
**ποτέ** γράψιμος: δεν υπάρχει πηγή να πει ποιος κατέχει τη στήλη.

## 11. 🔴 Η ΔΙΟΡΘΩΣΗ ΠΟΥ ΔΕΝ ΗΤΑΝ ΣΤΟ ΣΧΕΔΙΟ: η **μονάδα** του κελιού

### 11.1 Τι βρέθηκε — **με εκτέλεση**, όχι με ανάγνωση

Ο πυρήνας γράφτηκε πάνω στην υπόθεση του Δ4: *«ο χρήστης γράφει **μέτρα**, ο store κρατά
**mm**»*. Η υπόθεση ήταν **λάθος για τη ζωντανή συμπεριφορά**:

```
applyBoundSourceToCells(model, buildCoordinateTable([{ x: 391698400, … }]))
  → κελί.value        = 391698400     ← ΩΜΑ ΧΙΛΙΟΣΤΑ
  → cellInputText(…)  = "391698400"   ← αυτό άνοιγε ο επεξεργαστής
```

ενώ το **CSV και το PDF του ίδιου πίνακα** έδειχναν `391698.400`. Δύο απαντήσεις στο «τι λέει
αυτό το κελί» — και η μία πάει στο **παραδοτέο που υπογράφεται**.

🔴 **Η συνέπεια για τη Φ.Η ήταν σφάλμα ×1000, σιωπηλό**: ο χρήστης θα έβλεπε χιλιοστά, θα
πληκτρολογούσε χιλιοστά, και ο `parseCellToStore` θα πολλαπλασίαζε επί 1000 — μετακινώντας την
κορυφή **χίλια μέτρα** μακριά, σε πίνακα συντεταγμένων που κατατίθεται.

### 11.2 Γιατί τα 18 tests του πυρήνα ήταν πράσινα

Επειδή **έδιναν** `nextDisplayValue: 391698.5` στην είσοδο: χαρακτήριζαν την **υπόθεση**, όχι
τη ζωντανή συμπεριφορά. Είναι η κλάση που το ADR-587 §6.1 ονομάζει *«ένα test που ρωτά τα
rules αν συμφωνούν με τον εαυτό τους δεν είναι άγκυρα»*, και το ίδιο σχήμα με το
`properties.rules.test.ts` του ADR-758 §4 (21/21 πράσινο **πριν και μετά** τη διόρθωση).

Το μόνο σχήμα που δεν μπορεί να πει ψέματα γι' αυτό είναι ο **κύκλος από άκρη σε άκρη** με τις
πραγματικές συναρτήσεις — γι' αυτό γράφτηκε (§7.2).

### 11.3 Η διόρθωση: **ο εμπρός δρόμος που έλειπε**

🏆 Καμία νέα μηχανή. Ο `parseCellToStore` δηλώνει **ο ίδιος** ότι είναι *«ο **αντίστροφος** του
`formatCellForXlsx`»* — δηλαδή ο κύκλος ήταν **σχεδιασμένος σωστά** και έλειπε το μισό του: ο
δεσμός δεν καλούσε ποτέ τον εμπρός. Πλέον:

| | τι κρατά | γιατί |
|---|---|---|
| `TableCell.value` | `formatCellForXlsx(raw, valueType)` — μονάδες **ΟΘΟΝΗΣ** | ό,τι βλέπει **και γράφει** ο άνθρωπος· το ίδιο νούμερο με το CSV/PDF |
| `TableCellBinding.sourceValue` | **ωμό** | είναι η βάση σύγκρισης με **την πηγή** (Δ2/Δ3). Μορφοποιημένη βάση θα σύγκρινε μήλα με πορτοκάλια και θα κήρυσσε σύγκρουση σε κάθε refresh |

⚠️ **Γιατί `formatCellForXlsx` και όχι `formatCellForDisplay`**: ο πρώτος κρατά **αριθμό**
(`391698.4`), ο δεύτερος δίνει **κείμενο** (`"391698.400"`). Με κείμενο, το `=SUM(B2:B3)` πάνω
σε δεμένη στήλη θα έδινε **μηδέν** — υπάρχει άγκυρα ακριβώς γι' αυτό
(`table-binding-refresh.test.ts`, «τύπος πάνω σε δεμένο κελί»). Η μορφοποίηση των δεκαδικών
μένει δουλειά του **ADR-760** (`numberFormat`), όπου ανήκει, αντί να ψηθεί στο περιεχόμενο.

### 11.4 Τι άλλαξε στη Φ.ΣΤ (ADR-767)

Πέντε assertions (`table-binding-refresh` · `table-binding-override`) δήλωναν `4500` και
δηλώνουν πλέον `4.5`. **Δεν έγιναν πράσινα — ξαναγράφτηκαν**, με ρητό σχόλιο και με **νέα**
άγκυρα που απαιτεί τις δύο τιμές να **διαφέρουν** (`value` ≠ `sourceValue`): ίδιες τιμές θα
σήμαιναν ότι κάποιος από τους δύο δρόμους ξέχασε τη μονάδα του.

⚠️ **Γιατί έμεινε αόρατο μία ολόκληρη φάση**: οι στήλες `index` (`count`) και `code` (`text`)
**δεν αλλάζουν μονάδα**. Η μισή γραμμή φαινόταν σωστή.
### 11.5 `boundDataRows` / `boundSourceRowIndex` — η αντίστροφη ανάγνωση, σε **ένα** σημείο

Εξήχθησαν στο ίδιο αρχείο επειδή η Φ.Η χρειάζεται το ερώτημα ανάποδα: *«σε ποια γραμμή της
πηγής αντιστοιχεί αυτό το `rowId`;»*. Δύο υλοποιήσεις του ίδιου φίλτρου θα ήταν δύο ορισμοί
του «ποια γραμμή είναι δεδομένο» — και η πρώτη φορά που θα διαφωνούσαν, ο πίνακας θα
**μετακινούσε λάθος κορυφή**, δηλαδή ακριβώς η βλάβη που το Δ3 υπάρχει για να αποκλείσει.

Το `-1` είναι ρητό: **ποτέ** `0`, που θα διαβαζόταν ως «η πρώτη».
