## 0. Σύνοψη

Ο ΧΡΗΣΜΟΣ του CHECK 3.51 — «περιέχει ωμά i18n κλειδιά το HTML που στέλνει ο server;» —
**δεν είχε τρέξει ποτέ**, και όταν θα έτρεχε **δεν θα μπορούσε να απαντήσει**. Δύο
ανεξάρτητα ελαττώματα, και τα δύο μετρημένα:

| | | |
|---|---|---|
| **Α. Δεν μπορούσε να εκτελεστεί** | το job έχτιζε **δεύτερο** production server με **1 από τις 20** μεταβλητές περιβάλλοντος και πέθαινε σε OOM στα ~4,1 GB | → CHECK **3.57** + νέο `i18n-ssr-oracle.yml` |
| **Β. Δεν μπορούσε να κρίνει** | το θετικό control παραγόταν **αποκλειστικά** από το κέλυφος, που ζωγραφίζεται σε **κάθε** διαδρομή ⇒ ο φρουρός `probe-unproven` ήταν **δομικά αδύνατο** να πυροδοτήσει | → δύο σύνολα απόδειξης + δύο νέες καταστάσεις |

## 1. Το γεγονός που ανέτρεψε το handoff

Το handoff της 2026-08-22 έλεγε: *«ο μηχανισμός υπάρχει ήδη — dispatch → artifact → commit
ο Giorgio»*. Η μέτρηση το ανέτρεψε.

Τελευταία εκτέλεση (2026-08-21, run `32458992910`):

```
FATAL ERROR: Ineffective mark-compacts near heap limit — Allocation failed
Mark-Compact 4017.4 (4134.4) -> 4005.5 (4136.6) MB
```

Πεθαίνει στα **~4,1 GB** ενώ το βήμα δηλώνει `--max-old-space-size=12288`.

**Οι τρεις καλούντες του `build:ci`, στο ίδιο commit:**

| workflow | μεταβλητές env | build |
|---|---|---|
| `docker-build.yml` (Tier 1) | **20** | ✅ 14′15″ |
| `bundle-ratchet.yml` | **20** (ταυτόσημα ονόματα *και* τιμές) | ✅ |
| `i18n-shell-slice.yml` → ο ΧΡΗΣΜΟΣ | **1** | ❌ OOM |

🔴 Το σχόλιο **μέσα** στο τρίτο έλεγε ότι το πρόβλημα ήταν «**λείπει μία γραμμή env**» και
ότι είχε διορθωθεί. **Έλειπαν 19 από τις 20.** Η περιγραφή της διόρθωσης **ήταν η ίδια η
απόκλιση** — και το ίδιο σχόλιο υπάρχει, κατά λέξη, και στα δύο workflows που δουλεύουν:

> «Any workflow calling build:ci MUST set NODE_OPTIONS itself.»

**Ένα anchor χωρίς gate είναι σχόλιο** (CHECK 3.36). Ίδιο σχήμα με τις δύο χειρόγραφες
λίστες namespace του CHECK 3.34 (απόκλιση **63**) και τη λίστα 18-έναντι-26 του CHECK 3.37.

⚠️ **Δεν απομονώθηκε ποια από τις 19 προκαλεί το OOM** — κάθε απομόνωση κοστίζει μία
εκτέλεση CI. Το `DISABLE_SENTRY_WEBPACK` **αποκλείστηκε με ανάγνωση** (`next.config.js:488`
το θέτει ήδη `true` όταν λείπουν `SENTRY_ORG`/`SENTRY_PROJECT`). Και δεν χρειάζεται να
απομονωθεί: η ισοτιμία **δεν είναι θεραπεία του OOM, είναι προϋπόθεση ορθότητας** — το
`bundle-ratchet.yml` τεκμηριώνει ότι χωρίς το Firebase env το build σκάει με
`auth/invalid-api-key` στη συλλογή page-data, άρα ένας server χτισμένος με 1/20 **δεν είναι
ο server που στέλνεται**, ό,τι κι αν κάνει η μνήμη.

## 2. Η έρευνα: τι κάνουν οι μεγάλοι

| ερώτημα | βιομηχανική απάντηση | τι κάναμε |
|---|---|---|
| Πώς μοιράζεται περιβάλλον ανάμεσα σε workflows; | **composite action** (μοιράζεται *βήματα*, κληρονομεί env) ή **reusable workflow** (μοιράζεται *pipeline*) | **Κανένα από τα δύο** — βλ. §3 |
| Πού ζει μη-μυστική διαμόρφωση; | **GitHub configuration variables** (`vars`), org/repo/environment | **Απορρίφθηκε** — ζει **εκτός git**, όπου καμία πύλη δεν μπορεί να τη διαβάσει και κανένα review δεν τη βλέπει. Για ένα repo όπου κάθε λίστα έχει φρουρό, αυτό είναι **οπισθοδρόμηση**. |
| Πρέπει κάθε pipeline να ξαναχτίζει; | **ΟΧΙ.** «Build once, deploy many» / artifact immutability· το ξαναχτίσιμο ανά στάδιο είναι **τεκμηριωμένο anti-pattern** («you're wasting compute rebuilding the same code, and you lose traceability») | **Αυτό**, και είναι η ρίζα της λύσης |

🏆 **Πού πάμε ένα σκαλί πάνω.** Η αρχή «build once» διδάσκεται για **περιβάλλοντα
ανάπτυξης** (dev → staging → prod). Εδώ εφαρμόζεται στους **ΚΡΙΤΕΣ**: μια πύλη ποιότητας
που χρειάζεται τρέχουσα εφαρμογή **δεν χτίζει δική της** — καταναλώνει το **ίδιο artifact**
που πάει στην παραγωγή. Και επιπλέον υπάρχει **πύλη** που το επιβάλλει· τα εργαλεία των
μεγάλων (MUI theme override, «plug that into the map» των οδηγών, `isolation: isolate` ως
σύσταση σε άρθρο) **τεκμηριώνουν** χωρίς να **μετρούν**.

## 3. Η απόφαση: ο ΧΡΗΣΜΟΣ ΔΕΝ ΧΤΙΖΕΙ

Το `Dockerfile` **μόνο αντιγράφει** το `.next/standalone` (γρ. 10-15) — δηλαδή η εικόνα
`ghcr.io/yorgospag/nestor-app:main-<sha>` **ΕΙΝΑΙ** ο server, όχι κάτι ισοδύναμο.
Επαληθεύτηκε ζωντανά ότι είναι **δημόσια και ανώνυμα διαθέσιμη** (`manifests/latest` → 200)
με σχήμα ετικέτας `main-<7 χαρακτήρες sha>`.

**Νέο `i18n-ssr-oracle.yml` (Tier 2)**: `workflow_run` μετά το `docker-build.yml` →
`docker run` της εικόνας → σάρωση. **Κανένα build, καμία λίστα env, κανένα OOM.**

Γιατί **δεν** μπήκε σαν βήμα μέσα στο `docker-build.yml`: εκείνο είναι ο αγωγός
**κυκλοφορίας** (Tier 1). Μια πύλη **ποιότητας** εκεί σημαίνει ότι ένα ωμό κλειδί σταματά
το deploy στο Netcup και ότι η αποτυχία **ονομάζεται** «απέτυχε το Build & Deploy» — το
λάθος που απορρίπτει ρητά το ADR-775 και που γέννησε το ADR-757 (alert fatigue).

Γιατί **όχι** composite action για το env: μια σύνθετη ενέργεια θα **διαχειριζόταν** την
επανάληψη· η κατανάλωση του ίδιου artifact την κάνει **αδύνατη**. *Λύσε την κλάση, όχι το
δείγμα.*

🔶 **Δηλωμένο όριο**: τρέχει **μετά** το merge, γιατί η εικόνα δεν υπάρχει πριν χτιστεί.
Δεν μπλοκάρει το PR που εισάγει το ελάττωμα — μπλοκάρει το επόμενο, όπως κάθε ratchet του
CI εδώ. Το `workflow_dispatch` δίνει εκτέλεση κατ᾽ απαίτηση σε οποιαδήποτε ετικέτα.

🔶 **Δηλωμένο όριο**: τα μυστικά της παραγωγής (Firebase Admin, Coolify) δεν υπάρχουν στο
CI. Μια διαδρομή που τα χρειάζεται βγαίνει `route-unreachable` ή `probe-unproven` — ⛔ και
θορυβώδης, **ποτέ σιωπηλά «καθαρή»**.

## 4. CHECK 3.57 — «χτίζουν όλοι τον ίδιο server;»

**Η αυθεντία είναι ΡΟΛΟΣ, όχι όνομα αρχείου**: κανονική είναι η κλήση `build:ci` που ζει
στο **Tier 1** workflow, όπως το δηλώνει το `.ci-gate-tiers.json`. Χειρόγραφο
`docker-build.yml` μέσα στην πύλη θα ήταν **τέταρτη** λίστα.

**Έξι ρητές καταστάσεις, κλειστή λογιστική fail-closed** (άγνωστη ⇒ `throw` **με όνομα**):

| κατάσταση | | σήμερα |
|---|---|---|
| `canonical-build` | ✅ η κλήση που στέλνει στην παραγωγή | **1** |
| `env-drift` | ⛔ λείπουν μεταβλητές της κανονικής | 0 |
| `env-value-drift` | ⛔ ίδια ονόματα, άλλη τιμή (το περιστατικό 8192 της 2026-08-04) | 0 |
| `cross-env-build` | ⛔ καλεί `run build`, που καρφώνει 8192 και **σβήνει** το NODE_OPTIONS του workflow | 0 |
| `unanalyzable-caller` | ⛔ build κρυμμένο σε τοπική σύνθετη ενέργεια | 0 |
| `redundant-parity-build` | 🔶 ίδιο περιβάλλον, αλλά **δεύτερο** build του ίδιου commit | **1** (`bundle-ratchet.yml`) |

⚠️ **Το 🔶 ΔΕΝ μπλοκάρει, και ο λόγος είναι μετρημένος**: το `bundle-ratchet.yml` είναι
σήμερα **σωστό** (20/20). Αν το λέγαμε παραβίαση, η πύλη θα γεννιόταν μονίμως κόκκινη ⇒
`SKIP_` ⇒ διακοσμητική (δοκιμάστηκε και απορρίφθηκε στο CHECK 3.39). Αν το λέγαμε ✅, θα
**θεσμοθετούσαμε** την επανάληψη. Ονομάζεται και μετριέται, με γραμμένη κατεύθυνση: το
`bundle-ratchet` διαβάζει **μόνο** `.next/static`, που υπάρχει μέσα στην εικόνα — μπορεί
να την καταναλώσει με `docker cp`. **Ανοιχτό, απόφαση Giorgio.**

### ⚠️ Κριτήριο που μετρήθηκε και απορρίφθηκε

«Καμία κλήση `npm run build`» (γιατί το `build` καρφώνει `cross-env NODE_OPTIONS=8192` και
**σβήνει** ό,τι έθεσε το workflow — η αιτία του περιστατικού 2026-08-04):
**1 εύρημα / 1 ψευδώς θετικό = 100%** — το `ssot-discover.yml:466` γράφει
`npm run build:tokens` **μέσα σε echo** περίληψης. Κρατήθηκε `build(?![:\w])`. Το υπόλοιπο
(εντολή μέσα σε κείμενο περίληψης) είναι **δηλωμένο όριο**, μετρημένο **0**.

### SSoT — καμία νέα μηχανή

Ο **μόνος** αναγνώστης workflow του έργου (`scripts/lib/ci/workflow-meta.js`, ADR-757)
έμαθε ένα πεδίο: το `env:` ανά βήμα. Δεύτερος αναγνώστης YAML θα ήταν η «δεύτερη διάλεκτος»
του ADR-749. ⚠️ Η πρώτη γραμμή ενός βήματος φέρει το πρόθεμα `- `, άρα τα κλειδιά του
κάθονται **δύο κενά** πιο μέσα· υπολογισμός εσοχής που το αγνοεί βρίσκει **μηδέν** κλειδιά
και επιστρέφει `{}` — δηλαδή «δεν έχει env», που είναι το ίδιο σχήμα «0 = κανείς δεν
κοίταξε». Άγκυρα: `Μ0.2`.

**Στρώματα**: Layer 1 = pre-commit με σκανδάλη μέσα στην πύλη (~0,1s) · Layer 2 = job στο
**υπάρχον** `ci-gate-tiers.yml`, **άνευ όρων**. **Κανένα νέο workflow γι' αυτήν** — το
μητρώο παρακολουθεί **αρχεία**, όχι jobs. **ΔΕΝ είναι ratchet — καμία baseline, ποτέ**:
δεν υπάρχει «λιγότερα builds με λάθος περιβάλλον από χθες».

## 5. Ο ΧΡΗΣΜΟΣ ξαναμαθαίνει να κρίνει

### 5.1 Ο φρουρός που ήταν αδύνατο να πυροδοτήσει

Το θετικό control παραγόταν **αποκλειστικά** από το `shell-slice.el.json`. Το κέλυφος όμως
ζωγραφίζεται σε **κάθε** διαδρομή (το sidebar ζει στο root layout). Άρα `proven === true`
για **κάθε** διαδρομή που απαντά 200 — ανεξάρτητα από το αν το περιεχόμενο της σελίδας
αποδόθηκε ποτέ.

> **Ο χρησμός αποδείκνυε ότι η διαδρομή ΚΟΙΤΑΧΤΗΚΕ, ποτέ ότι η ΕΠΙΦΑΝΕΙΑ ΑΠΟΔΟΘΗΚΕ.**

**Μετρημένο 2026-08-22:**

| σύνολο | τιμές |
|---|---|
| ΟΛΟ το corpus (103 namespaces, ελληνικές τιμές ≥4 χαρακτ.) | **18.657** |
| κέλυφος | **2.119** (829 `admin` · 790 `common` · 268 `navigation`) |
| **σελίδα** (corpus **μείον** κέλυφος) | **16.538 (88,6%)** |
| μόνο από `navigation.pages.*` — βάφονται **παντού** | ≥9 |

Πλέον **δύο** σύνολα (`scripts/lib/i18n-ssr/controls.js`), **ξένα μεταξύ τους**:
`shellProven` = «απάντησε ο server;» · `pageProven` = «αποδόθηκε περιεχόμενο πέρα από το
κέλυφος;».

#### 🔬 Το ανά-διαδρομή control μετρήθηκε και απορρίφθηκε

Η ισχυρότερη διατύπωση («τιμή που **μόνο η κλειστότητα ΑΥΤΗΣ** της σελίδας μπορούσε να
βάλει») **υπάρχει** ως μηχανισμός (`buildRouteSlice`, ADR-744 Φ4). Μετρήθηκε:
`/properties/[id]` → **2.945** δικές του τιμές, `/spaces/parking` → **876**.
Απορρίφθηκε για **δύο** λόγους:

1. **Κόστος**: ~10-13s/διαδρομή × 154 ⇒ **~25 λεπτά** σε κάθε εκτέλεση, για πάντα. Μια
   πύλη που κοστίζει πολύ δεν είναι αυστηρότερη — είναι ανενεργή (CHECK 3.52).
2. **ΔΕΝ λύνει την Παγίδα Α** — και αυτός είναι ο αποφασιστικός: μια δυναμική διαδρομή που
   χτυπιέται με συνθετικό id βάφει το **δικό της** «δεν βρέθηκε», με κλειδιά του **δικού
   της** namespace ⇒ θα έλεγε ✅ «η σελίδα αποδόθηκε» πάνω σε οθόνη που **δεν είναι** η
   σελίδα.

🔶 **Δηλωμένο όριο**: το `page` control αποδεικνύει «αποδόθηκε **κάτι πέρα από το
κέλυφος**», όχι «αποδόθηκε *αυτή* η σελίδα».

### 5.2 Παγίδα Α — το συνθετικό `[param]`

Οι **33** δυναμικές διαδρομές χτυπιούνται ως `/properties/ssr-probe` — id που **δεν
υπάρχει**. Ό,τι κι αν βάψουν, **δεν είναι η σελίδα**.

**Νέα κατάσταση 🔶 `surface-synthetic-id`** — μετριέται, δεν απαριθμείται (πρότυπο
`unanalyzable-heritage`, CHECK 3.44). **ΔΕΝ** είναι ⛔: 33 από τις 154 θα ήταν μονίμως
κόκκινες. **ΔΕΝ** είναι ✅: θα ήταν ψέμα.

⚠️ **Η ασυμμετρία είναι σκόπιμη και κωδικοποιημένη στη σειρά κρίσης**: πάνω σε ακρίτη
επιφάνεια, το «**βρήκα** ωμό κλειδί» παραμένει **αληθές** (το κλειδί ζωγραφίστηκε όντως),
ενώ το «**δεν** βρήκα» δεν αποδεικνύει τίποτα. Γι' αυτό το `raw-key` κρίνεται **πριν**.
Άγκυρα: `Ν4`.

### 5.3 Η νέα μηχανή καταστάσεων

```
unreachable                      → route-unreachable        ⛔
!shellProven                     → probe-unproven           ⛔
hits.length > 0                  → raw-key                  🔴 ratchet
route.dynamic                    → surface-synthetic-id     🔶 μετριέται
!pageProven                      → surface-shell-only       🔴 ratchet
αλλιώς                           → clean                    ✅
```

### 5.4 Ο διαχωριστής κόμβων

Το δεύτερο πέρασμα (υπο-συμβολοσειρά) γινόταν πάνω σε `haystack.join('')` — που κολλά το
τέλος ενός κόμβου στην αρχή του επόμενου και γεννά ταιριάσματα **μέσα σε λέξη** που ποτέ
δεν υπήρξαν στην οθόνη. **Μια απόδειξη χτισμένη πάνω σε συμβολοσειρά που ο browser δεν
ζωγράφισε δεν είναι απόδειξη.** Πλέον ένωση με **κενό**: επιτρέπει ακόμη ανασύνθεση σε
**σύνορο λέξης** (`<strong>Διαχείριση</strong> Ακινήτων`), που είναι η πραγματική περίπτωση
για την οποία υπήρχε το πέρασμα. 🔶 Δηλωμένο υπόλοιπο: δύο *γειτονικοί άσχετοι* κόμβοι
μπορούν ακόμη να συνθέσουν κατά τύχη μια τιμή. Άγκυρα: `Ν7`.

### 5.5 Μία πηγή για ταυτότητες και λεπτομέρειες

Οι `violationIds` και οι `violations` χτίζονταν από **δύο** βρόχους με διαφορετικό
κριτήριο, και το `route-skipped` έβγαζε ταυτότητα (`…|skipped|—`) που **καμία** λεπτομέρεια
δεν αντιστοιχούσε — σχήμα ADR-749 σε μικρογραφία, μέσα στην ίδια συνάρτηση. Πλέον
`toViolations()` και `violationIds = violations.map(VIOLATION_ID)`.

## 8. Ανοιχτά — απόφαση Giorgio

1. 🔴 **Η ΣΠΟΡΑ ΤΗΣ BASELINE ΔΕΝ ΕΓΙΝΕ, ΚΑΙ ΔΕΝ ΜΠΟΡΟΥΣΕ.** Ο χρησμός χρειάζεται
   **δημοσιευμένη εικόνα** αυτού του κώδικα· η διόρθωση πρέπει πρώτα να φτάσει στο `main`
   (commit + push = **απόφαση Giorgio**, κανόνας N.(-1)). Τοπική εκτέλεση δεν είναι
   δυνατή: **δεν υπάρχει docker** σε αυτό το μηχάνημα (επαληθεύτηκε), και μια baseline
   μετρημένη σε άλλο περιβάλλον θα κωδικοποιούσε άλλον server.
   **Η μη-σπορά ΔΕΝ είναι παράλειψη: είναι η ίδια η εγγύηση** — το `--write-baseline`
   **αρνείται** όσο υπάρχει ⛔ κατάσταση.
2. 🔶 **Το `bundle-ratchet.yml` εξακολουθεί να ξαναχτίζει.** Διαβάζει μόνο `.next/static`,
   που υπάρχει μέσα στην εικόνα ⇒ μπορεί να την καταναλώσει. Θα έκανε τα production builds
   του repo **ένα**, και την κατάσταση `redundant-parity-build` **μηδέν**.
3. 🔶 **Η σύνθεση του tab `info`** (Βήμα 2 του handoff, στο ADR-777): δεν ξεκίνησε. Το Βήμα 1
   ήταν προϋπόθεσή του («μέτρηση πριν από αλλαγή») και αποδείχθηκε δύο επίπεδα βαθύτερο.
   ⚠️ **Δεν γράφεται εδώ αριθμός ενότητας**: η ενότητα **δεν υπάρχει ακόμη**, και ένας δείκτης

   πάνω σε αυτό το αρχείο, την ώρα του commit. Βρες τον επόμενο ελεύθερο **τη στιγμή που θα
   γράψεις την ενότητα**: `grep -n "^### 8\." docs/…/ADR-777-*.md | tail -2`.
