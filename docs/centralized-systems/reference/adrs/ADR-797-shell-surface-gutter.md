# ADR-797 — Ο διάδρομος του κελύφους: ποιος αποφασίζει το κενό γύρω από το περιεχόμενο

**Κατάσταση**: Accepted · **Ημερομηνία**: 2026-08-24 · **Πύλη**: CHECK 3.63

---

## 1. Το ερώτημα

> Το περιεχόμενο ακουμπάει την πλαϊνή μπάρα. Γιατί;

Η απάντηση δεν ήταν «λείπει μια κλάση». Ήταν ότι **κανείς δεν ήταν ιδιοκτήτης της
ερώτησης**.

### 1.1 Η μέτρηση, πριν γραφτεί γραμμή

Ολόκληρη η αλυσίδα από την μπάρα ως το κείμενο δήλωνε **μηδέν** οριζόντιο κενό:

| # | Στοιχείο | Κλάσεις | Οριζόντιο κενό |
|---|---|---|---|
| 1 | `(app)/layout.tsx` → `shellAppContainer` | `flex h-screen w-full max-w-full overflow-hidden` | **0** |
| 2 | `SidebarInset` (`ui/sidebar.tsx:206`) | `relative flex min-h-svh flex-1 flex-col` | **0** ⚠️ |
| 3 | `MainContentBridge` (`<main>`) | `flex-1 overflow-y-auto overflow-x-hidden w-full max-w-full` | **0** |
| 4 | `BrokeredListingPageContent:126` | `flex flex-col gap-4` | **0** |

Και οι σελίδες δεν το κάλυπταν: **86 από τις 104** κάτω από `/o/[workspace]` δεν
δήλωναν κανένα κενό.

### 1.2 Η παγίδα στο #2 — προστασία που δεν ενεργοποιείται ποτέ

Το `SidebarInset` **έχει** περιθώριο γραμμένο μέσα του:

```
md:peer-data-[variant=inset]:m-2
```

αλλά ενεργοποιείται **μόνο** με `variant="inset"`. Το `app-sidebar.tsx:77` γράφει
`<Sidebar collapsible="icon">` — **χωρίς variant** ⇒ ο επιλογέας δεν ταιριάζει
**ποτέ**. Το περιθώριο υπάρχει στον κώδικα και είναι **δομικά ανενεργό**.

### 1.3 Γιατί καμία πύλη δεν το έβλεπε

Δεν ήταν κενό καμίας υπάρχουσας πύλης — ήταν **ερώτημα που δεν έκανε κανείς**.
Το κενό ήταν ανάθεση σε κάθε σελίδα ξεχωριστά: το σχήμα που σε αυτό το repo έχει
αποτύχει **μετρημένα τέσσερις φορές** — CHECK 3.34 (δύο λίστες namespace,
απόκλιση **63**) · 3.37 (**18 έναντι 26**) · 3.49 (**60** συγκρούσεις) ·
3.57 (**19 από 20** μεταβλητές).

## 2. Τι κάνουν οι μεγάλοι (ερευνήθηκε 2026-08-24)

Και οι τέσσερις αυθεντίες συμφωνούν στο **ποιος**:

| Πηγή | Τι λέει |
|---|---|
| **Brad Frost**, *Layout & Grid in Design Systems* | ο layout container είναι *«an important, **invisible** component … [that] controls the gutter padding so content doesn't butt up against the viewport edge»* |
| Κανόνας design tokens | *«outer spacing is a **layout** concern, not a component one; base components export **zero** external margins»* |
| **Carbon (IBM)** | **ξεχωριστή** layout scale από τη spacing scale — *«larger increments used to control the **density** of a design»* |
| **Material 3** | margins ανά window size class: **16dp** compact → **24dp** medium |
| **Atlassian** | 8px base· `space.400` (**32px**) και πάνω για page content |

### 2.1 🏆 Πού τους ξεπερνάμε — και είναι μετρήσιμο

**M3, Utopia και Carbon μετρούν όλα το παράθυρο.**

Αυτή η εφαρμογή έχει μπάρα που **διπλώνει**: `16rem → 3rem`, δηλαδή **208px**
αλλαγή στο διαθέσιμο πλάτος **με το παράθυρο ακίνητο**. Ένα μοντέλο
window-size-class δίνει **την ίδια απάντηση σε δύο διαφορετικές επιφάνειες** —
δομικά, όχι κατά λάθος.

Εδώ ο διάδρομος μετριέται στο **pane**: `100vw − <όσο πιάνει η μπάρα>`, όπου το
«όσο πιάνει» το λέει το **ίδιο** `data-collapsible` που ζωγραφίζει την μπάρα.
Και είναι **συνεχής**, όχι σκαλοπάτια (μοντέλο Utopia, με το pane στη θέση του
`100vw`).

**Ζωντανή απόδειξη** (2026-08-24, παράθυρο 2400px):

## 3. Τι απορρίφθηκε, και γιατί

### 3.1 🔴 Container query — η προφανής λύση θα έσπαγε το z-index

Το προφανές είναι `container-type: inline-size` στο pane και `@container`.
**Απορρίφθηκε**, και ο λόγος είναι γραμμένος αλλού σε αυτό το repo:

1. Το `container-type: size | inline-size` **δημιουργεί stacking context**. Το
   **ADR-780 Φ.Γ** μέτρησε ότι **όλες** οι επιφάνειες με `z-index ≥ 1000`
   κάθονται στο **ROOT** stacking context. Ένα container στο pane θα τις
   εγκλώβιζε **όλες** — και η κλίμακα των 40 ρόλων θα γινόταν διακοσμητική
   **χωρίς να κοκκινίσει τίποτα**.
2. Δημιουργεί **containing block για `position: fixed`** — μετρημένα **15**
   αρχεία με fixed επιφάνειες θα άλλαζαν σημείο αναφοράς.

Ο ρευστός υπολογισμός δεν αγγίζει τίποτα από τα δύο: μηδέν containment, μηδέν
stacking context, μηδέν JavaScript, μηδέν re-render.

### 3.2 🔴 Typed arithmetic στο CSS — θα αποτύγχανε σιωπηλά, σε ξένη οθόνη

Η ευθεία θέλει `(gmax − gmin) / (pmax − pmin)` = **διαίρεση μήκους με μήκος**.
Αυτό είναι CSS Values 4 και υποστηρίζεται **μόνο** σε Chrome 119+ / Safari 17+ /
Firefox 116+. Σε παλαιότερο browser η `calc()` γίνεται *invalid at
computed-value time* ⇒ **ολόκληρη η δήλωση πέφτει** ⇒ ο διάδρομος γίνεται **0**:
ακριβώς το ελάττωμα που θεραπεύουμε, ξαναγεννημένο **σιωπηλά** και μόνο εκεί που
δεν κοιτάζουμε.

Λύση: τα **παράγωγα** (`slope`, `intercept`) τα παράγει ο **generator** μία φορά
στο build (`emitFluidLayout`). Το CSS μένει με `number × length` (Level 3,
παντού). Κανείς δεν γράφει τους αριθμούς, άρα **δεν μπορούν να αποκλίνουν**.

### 3.3 Style queries

Chrome 111+ / Safari 18+, **όχι Firefox**. Απορρίφθηκε: θα ήταν σιωπηλή
υποβάθμιση σε browser που δεν ελέγχουμε.

## 4. Η λύση

### 4.1 Ένα SSoT για τους αριθμούς

`design-tokens.json → spacing.layout` — **η κλίμακα του κελύφους, ξεχωριστή από
την component** (πρότυπο Carbon). Οι τιμές είναι **ΠΟΛΟΙ ρευστής συνάρτησης**,
όχι σκαλιά:

| token | τιμή | προέλευση |
|---|---|---|
| `gutter.min` | 16 | Material 3 compact margin |
| `gutter.max` | 32 | Atlassian `space.400` |
| `pane.min` | 640 | το pane μόλις χωρέσει δίστηλη φόρμα |
| `pane.max` | 1600 | Material 3 extra-large |
| `block` | 24 | κάθετος διάδρομος — **σταθερός** |
| `density.*` | 1 / 0.75 | **πολλαπλασιαστής**, όχι δεύτερη κλίμακα |

**Ο κάθετος άξονας δεν είναι ρευστός, και ο λόγος είναι μετρημένος**: το κάθετο
κενό δεν ανταγωνίζεται τίποτα (η σελίδα κυλά), ενώ το οριζόντιο τρώει πλάτος από
πίνακες δεδομένων. Δύο άξονες, δύο απαντήσεις.

### 4.2 Δύο ερωτήσεις, δύο μηχανισμοί — ποτέ ένας με «ή»

*(μάθημα CHECK 3.41)*

- **«πόσο κενό;»** → ρευστός διάδρομος, από το pane.
- **«κενό καθόλου;»** → `data-shell-surface="bleed"`, δήλωση της σελίδας.

Ένας μηχανισμός για τα δύο θα ήταν πράσινος **και προς τις δύο** κατευθύνσεις: ο
χάρτης θα έπαιρνε «λίγο» κενό αντί για κανένα, και μια φόρμα θα μπορούσε να πέσει
στο μηδέν χωρίς να το δηλώσει κανείς.

### 4.3 🔴 Η προεπιλογή είναι «παίρνει κενό» — fail-closed

Ο Brad Frost περιγράφει *component* που κάθε σελίδα **θυμάται** να τυλίξει. Εδώ
το κέλυφος το δίνει **χωρίς να το ξέρει κανείς**, και η σελίδα κάνει **opt-out** —
πρότυπο `tenant-config.ts` (*«Every CollectionKey **NOT listed** here defaults to
companyId»*), το ίδιο που ακολουθεί ήδη το CHECK 3.60.

Νέα σελίδα είναι **σωστή από τη γέννησή της**· ξεχασμένη εξαίρεση είναι **ορατή
στην οθόνη**, όχι σιωπηλή διαρροή.

Η επικοινωνία γίνεται με `:has()` (Baseline 2023): η σελίδα **δηλώνει την πρόθεσή
της**, το κέλυφος **αντιδρά** — χωρίς context, χωρίς prop drilling, χωρίς να
γνωρίζονται τα δύο.

### 4.4 Ζωντανή επαλήθευση (2026-08-24)

| Τι | Αποτέλεσμα |
|---|---|
| pane, μπάρα ανοιχτή | **2144** = 2400 − 256 ✅ |
| pane, μπάρα σε εικονίδια | **2352** = 2400 − 48 ✅ (με **ακίνητο** παράθυρο) |
| `--shell-sidebar-occupied` | `16rem` ↔ `3rem`, αυτόματα ✅ |
| ρευστή καμπύλη | 7 σημεία, γραμμική με clamp και στα δύο άκρα ✅ |
| `/contacts`, `/procurement/vendors` | 32px καθαρό, **μηδέν** overflow ✅ |
| `/dxf/viewer` **πριν** το opt-out | έχανε **64×48px = 6,9%** επιφάνειας σχεδίασης |
| `/dxf/viewer` **μετά** | καμβάς 2352×1126 = **ολόκληρο** το pane ✅ |
| `/listings/mandates` | βρέθηκε **διπλό κενό** 32+24=56px ⇒ διορθώθηκε |

**Το διπλό κενό το βρήκε η οθόνη, όχι ο κώδικας.** Γι' αυτό υπάρχει η πύλη.

## 5. Η πύλη (CHECK 3.63)

**Τρεις ανεξάρτητοι κανόνες:**

| | Κατάσταση | Μηχανισμός |
|---|---|---|
| **Κ1** | `owner-declares-padding` · `owner-lost-marker` | ⛔ ZERO-TOL |
| **Κ2** | `page-padding` · `content-padding` · `negative-margin` | 🔴 RATCHET **κατά ταυτότητα** |
| **Κ3** | `undeclared-bleed` · `orphan-declaration` | ⛔ ZERO-TOL + **κλειστό σύνολο** |

**Το Κ3 φυλά και τη σωστή πράξη**: μια νέα, απολύτως δικαιολογημένη επιφάνεια-
καμβάς **ΜΠΛΟΚΑΡΕΙ** ώσπου να τη δει άνθρωπος. Ένα κλειστό σύνολο που εγκρίνει
σιωπηλά τις σωστές πράξεις δεν θα έβλεπε ποτέ τη **δεύτερη** σωστή πράξη να
γίνεται **τρίτη**, και μετά κανόνας.

### 5.1 Το κριτήριο άλλαξε από τη μέτρηση

Η πρώτη, χονδροειδής γραφή έψαχνε `p-*` **οπουδήποτε** στο δέντρο εισαγωγών:
**18 ευρήματα, >60% ψευδώς θετικά** — `FrameworkAgreementFormDialog` (διάλογος),
`MaterialDetail` (πλαϊνό ταμπλό), και δύο που «βρήκαν» το `p-*` μέσα στο ίδιο το
`lib/design-system.ts`. Πήχης για **μπλοκάρουσα** πύλη: **<10%**.

Κρατήθηκε: **μόνο η ΡΙΖΑ**. Το κενό **μέσα** σε κάρτα, διάλογο ή ταμπλό είναι
`spacing.component.*` και είναι **σωστό**.

### 5.2 🔴 Η πύλη γεννήθηκε τυφλή στο 67% — και το έπιασε η λογιστική

Η πρώτη γραφή του `rootElementOf` έψαχνε μόνο `return (` και έδινε **93 από 139**
`unresolved-root`. Θα γεννιόταν **σχεδόν ανενεργή**, με το «δεν βρήκα» να
διαβάζεται «καθαρό» — το σχήμα «0 = κανείς δεν κοίταξε». Αιτία: το κυρίαρχο
ιδίωμα εδώ είναι `return <Foo />;` **χωρίς** παρενθέσεις.

Σήμερα **12** (8,6%), και η άγκυρα `Λ2` κλειδώνει το κατώφλι στο 15%.

### 5.3 Δηλωμένα όρια

- Ο σαρωτής κάνει **ΕΝΑ άλμα** (σελίδα → πρώτο component περιεχομένου). Σελίδα
  που περνά από **τρίτο** ενδιάμεσο δεν κρίνεται — κατάσταση `unresolved-root`,
  **μετριέται και τυπώνεται**.
- ⚠️ **Ο αριθμός 13 ΔΕΝ είναι δείκτης υγείας**: είναι το μέτρο εκστρατείας που
  **τελειώνει στο μηδέν**. Μερικές είναι **ακίνδυνες σήμερα**
  (`mx-auto max-w-3xl px-4` — κεντραρισμένη στήλη) και **παραμένουν
  παραβιάσεις**: το ερώτημα δεν είναι «φαίνεται;» αλλά «**ποιος αποφασίζει;**».
