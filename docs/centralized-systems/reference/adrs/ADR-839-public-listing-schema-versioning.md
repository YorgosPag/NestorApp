# ADR-839 — **Ο τύπος που έλεγε την αλήθεια για τον γραφέα και ψέματα για τη βάση**

**Κατάσταση**: **ΕΠΙΠΕΔΑ 1 + 2 + 3 + 5 ΟΛΟΚΛΗΡΩΜΕΝΑ** (§4, §5, §6, §8) · Επίπεδο 4 = **λειτουργική πράξη**, εκτελείται από άνθρωπο (§7)
**Ημερομηνία**: 2026-09-01
**Σχετικά**: ADR-777 Α3 (η οθόνη 3 — **ο παθών**) · ADR-835 §4.4/§4.5 · ADR-838 §6 (τα τρία πεδία που
γεννήθηκαν χωρίς προεπιλογή) · ADR-736 §5.3 (η κλάση «χειρόγραφη λίστα πεδίων» — εδώ **δεν** γίνεται
το δέκατο περιστατικό της) · ADR-749 («δύο μηχανές, μία ερώτηση») · ADR-802 (μητρώο πυλών)

---

## §1. Το περιστατικό

```
TypeError: Cannot read properties of undefined (reading 'map')
  https://www.nestorconstruct.gr/listing/ownp_330a5a4b-3d36-41a6-8f61-b5a85f1ae9d1
  2026-08-31T20:52:34.481Z
```

Η **οθόνη 3** κατέρρευσε σε λευκό για έναν ανώνυμο επισκέπτη. Η γραμμή ήταν το
`ListingLegality.tsx:143` — `listing.legality.map(...)` — και το `legality` ήταν `undefined`.

## §2. Η αιτία, από την ίδια τη βάση

Δεν ήταν εικασία. Το έγγραφο διαβάστηκε ζωντανά:

```jsonc
// public_listings/ownp_330a5a4b-3d36-41a6-8f61-b5a85f1ae9d1
{
  "offerKinds": ["sell"],                          // ✅ υπάρχει
  "commercial": { "askingPrice": 150000, … },      // ⚠️ χωρίς nightlyRate
  "projectedAt": "2026-08-31T06:46:59.692Z"        // 🔑 06:46 της ίδιας μέρας
  // legality: ΔΕΝ ΥΠΑΡΧΕΙ
  // stay:     ΔΕΝ ΥΠΑΡΧΕΙ
}
```

Τα τρία πεδία μπήκαν στο κλειστό σχήμα **την ίδια μέρα**, με το `49e82175` (ADR-835), **ώρες
μετά** τη σύνθεση αυτής της προβολής. Ο γραφέας τα γράφει σωστά
(`public-listing-projection.ts:447`). Κανείς απλώς δεν ξανάχτισε τα υπάρχοντα έγγραφα.

🔴 **Ο τύπος έλεγε την αλήθεια για τον ΓΡΑΦΕΑ και ψέματα για τη ΒΑΣΗ.** Το
`readonly legality: readonly LegalitySignal[]` είναι υπόσχεση που τηρεί ο σημερινός γραφέας —
όχι κάθε έγγραφο που κάθεται ήδη στη Firestore.

## §3. Η κλάση — γιατί δεν αρκούσε το rebuild

Το δείγμα θεραπεύεται με μία επανασύνθεση. Η κλάση ζούσε αλλού, σε **τρία** σημεία:

| | |
|---|---|
| `usePublicListings.ts:57` | `doc.data() as PublicListing` — πελάτης, λίστα |
| `usePublicListings.ts:141` | `snapshot.data() as PublicListing` — πελάτης, ένα έγγραφο |
| `mandate-inbox.service.ts:243` | `...(data as PublicListing)` — **Admin SDK**, διακομιστής |

Ένα `as` δεν είναι έλεγχος· είναι **εντολή στον μεταγλωττιστή να πάψει να ρωτά**. Κάθε επόμενο
πεδίο που θα προστεθεί στο σχήμα θα ξανάριχνε τη σελίδα για κάθε προϋπάρχον έγγραφο, και ο
`tsc` είναι **δομικά ανίκανος** να το δει — γιατί το `as` του απαγορεύει να ρωτήσει.

## §4. Τι κάνουν οι μεγάλοι (έρευνα 2026-09-01)

| | πρακτική | τι σημαίνει εδώ |
|---|---|---|
| **Revit · ArchiCAD · Cinema 4D** | κάθε αρχείο κουβαλά **έκδοση μορφής**· το άνοιγμα παλιότερου είναι **ρητή αναβάθμιση κατά την ανάγνωση** | κανένα από τα τρία δεν ανοίγει παλιό αρχείο υποθέτοντας ότι φέρει τα νέα πεδία — ακριβώς ό,τι κάναμε |
| **Protobuf · Avro** | κάθε νέο πεδίο είναι προαιρετικό **ή έχει προεπιλογή**· άγνωστα πεδία **αγνοούνται** | με αυτούς τους όρους το `legality` ήταν *required field χωρίς default* — η κατηγορία που **και τα δύο** formats ρητά απαγορεύουν |
| **MongoDB Schema Versioning Pattern** | `schemaVersion` + κανονικοποίηση στην ανάγνωση + lazy migration + batch | το σχήμα μας ακριβώς: document store, όχι σχεσιακή βάση |
| **«Parse, don't validate»** | επικύρωση **στο σύνορο**, εμπιστοσύνη μέσα | το σύνορο υπήρχε· απλώς δεν είχε φύλακα |

🏆 **Πού σταματήσαμε, και γιατί.** Το **Cambria** (Ink & Switch / Geoffrey Litt, MIT) μεταφράζει
σχήματα με **αμφίδρομους φακούς**, ενώ ο Revit πάει μόνο μπροστά. Είναι γνήσια ανώτερο — και
λύνει πρόβλημα που **δεν έχουμε**: συνεργασία ζωντανά ανάμεσα σε διαφορετικές εκδόσεις
εφαρμογής. Εμείς έχουμε **έναν** γραφέα στον διακομιστή. Θα ήταν έξυπνο σε χαρτί και βάρος
στην πράξη.

## §5. Η απόφαση — αλυσίδα μεταναστεύσεων, όχι καθρέφτης

Η προφανής θεραπεία ήταν ένα `z.object({ … })` με τα 18 πεδία και προεπιλογή στο καθένα.
**Απορρίφθηκε.** Το ADR-736 §5.3 ονομάζει την κλάση *«χειρόγραφη λίστα πεδίων»* και το ADR-833
μέτρησε ότι είναι στο **ένατο** περιστατικό της· ένας καθρέφτης εδώ θα ήταν το **δέκατο** —
δύο δηλώσεις του ίδιου σχήματος, ελεύθερες να αποκλίνουν μόλις κάποιος αγγίξει τη μία.

Αντ' αυτού, `lib/listings/public-listing-schema.ts`:

```ts
export const PUBLIC_LISTING_SCHEMA_VERSION = 2;
export const UNSTAMPED_SCHEMA_VERSION = 1;   // η απουσία σφραγίδας ΕΙΝΑΙ πληροφορία

export const LISTING_MIGRATIONS = [
  { to: 2, adr: 'ADR-835 · ADR-838',
    adds: ['legality', 'stay', 'commercial.nightlyRate'], apply: … },
];
```

**Λίγες γραμμές ανά έκδοση** αντί για διακόσιες μία φορά. Κάθε κρίκος απαντά **ένα** ερώτημα:
*«τι λείπει από την έκδοση N ώστε να γίνει N+1;»*. Αύριο που θα προστεθεί πεδίο, γράφεται
**ένας** κρίκος και τίποτα άλλο.

⚠️ **ΟΙ ΚΡΙΚΟΙ ΕΙΝΑΙ ΑΜΕΤΑΒΛΗΤΟΙ** — περιγράφουν αλλαγή που **συνέβη**, και υπάρχουν έγγραφα
που τους έχουν ήδη περάσει. Διόρθωση = **νέος** κρίκος. Ίδια αρχή με τους αριθμούς ADR
(«never renumber») και με τα field numbers του Protobuf.

🔑 **`.catch()` και όχι `??`.** Το `??` δέχεται ό,τι δεν είναι `null`/`undefined`, άρα ένα
`legality: "ναι"` θα περνούσε αυτούσιο και θα έσκαγε **στο ίδιο `.map`**. Ο έλεγχος είναι
σκόπιμα **ρηχός** (*«πίνακας από αντικείμενα»*, όχι *«έγκυρο `LegalitySignal`»*): το βαθύ
ερώτημα το απαντά ο **γραφέας**, όπου ο μεταγλωττιστής μπορεί να το επιβάλει.

🔑 **Κενός πίνακας ΕΙΝΑΙ η σωστή απάντηση, όχι μπάλωμα.** Το ADR-838 λέει ρητά *«προτιμάμε να
φανούμε λιγότερο πλήρεις παρά περισσότερο βέβαιοι απ' όσο είμαστε»*: μια αγγελία γραμμένη πριν
υπάρξει η ερώτηση δεν έχει **άγνωστη** νομιμότητα — δεν της **τέθηκε** το ερώτημα. Η οθόνη
γνωρίζει ήδη να το πει.

## §6. Το σύνορο — γιατί καθαρή συνάρτηση και όχι `withConverter`

Το ιδίωμα του έργου για σύνορα Firestore είναι ο `FirestoreDataConverter`
(`lib/firestore/utils.ts:9`), και ήταν η πρώτη σκέψη. **Δεν αρκεί**: ο τρίτος καταναλωτής
τρέχει σε **Admin SDK**, άλλη βιβλιοθήκη με άλλον τύπο converter. Ένας converter θα κάλυπτε τα
δύο από τα τρία σημεία και θα άφηνε το τρίτο με το `as` — δηλαδή θα γεννούσε **δεύτερο** κριτή
για την ίδια ερώτηση (ADR-749). Η καθαρή `readStoredListing(raw, id)` απαντά και στους τρεις.

⚠️ **Ο ισχυρισμός δεν εξαφανίστηκε — μαζεύτηκε.** Ζει σε **ένα** σημείο που έχει άγκυρες,
τεκμηρίωση και πύλη, αντί για τρία που δεν είχαν τίποτα.

### §6.1 Το lazy migration που **δεν** γράφτηκε, και γιατί

Το πρότυπο του document store λέει *«διάβασες παλιό; γράψ' το πίσω»*. **Απορρίφθηκε με λόγο
ασφαλείας**: ο πελάτης **δεν έχει** δικαίωμα εγγραφής στο `public_listings` (`read: if true`,
καμία `write` — γράφει μόνο ο διακομιστής). Ένα write-back-on-read θα απαιτούσε διαδρομή που
επιτρέπει σε **ανώνυμο** επισκέπτη να πυροδοτεί εγγραφές — θα αντάλλασσε μια λευκή οθόνη με
ένα διάνυσμα DoS.

Στη θέση του μπήκε **παρατηρησιμότητα**: ο αναγνώστης που βλέπει παλαιότερη έκδοση την
**καταγράφει** (`needsRebuild`). Ο επισκέπτης βλέπει ήδη σωστά, γιατί η μετάφραση έγινε **στη
μνήμη** — άρα τίποτα δεν πονάει, και χωρίς την καταγραφή τίποτα δεν θα το φανέρωνε ποτέ.

## §7. Επίπεδο 4 — η επανασύνθεση (λειτουργική πράξη)

Η μετάφραση στη μνήμη κάνει τη σελίδα σωστή **αμέσως**. Τα έγγραφα όμως μένουν v1 μέχρι να
τρέξει το **υπάρχον** `rebuildAllPublicListings` (`/api/admin/rebuild-public-listings`), που
έχει ήδη `dryRun` και κλειστή λογιστική. Καμία νέα μηχανή.

🔴 **Εκτελείται από άνθρωπο** — απόφαση του Giorgio (2026-09-01): ο πράκτορας δεν γράφει σε
παραγωγική Firestore χωρίς να το βλέπει.

## §8. Επίπεδο 5 — CHECK 3.74, η πύλη που το κάνει αδύνατο

Δύο κριτήρια, zero-tolerance:

- **Κ1** — κανένα `as PublicListing` έξω από `lib/listings/public-listing-from-document.ts`.
- **Κ2** — οι άγκυρες του σχήματος περνούν (`npm run test:listing-read-boundary`).

🏆 **Η Κ7 των αγκυρών είναι που κάνει περιττή τη δεύτερη λίστα πεδίων.** Ρωτά τον **ίδιο τον
γραφέα** ποια πεδία υπάρχουν — ο μεταγλωττιστής τον αναγκάζει να τα γράφει όλα, γιατί
επιστρέφει `PublicListing` — κατασκευάζει το «όπως θα ήταν στην v1» αφαιρώντας ό,τι δηλώνει η
αλυσίδα, και απαιτεί η αναβάθμιση να τα ξαναφτάσει **όλα**. Πεδίο χωρίς κρίκο ⇒ **κόκκινο**.
