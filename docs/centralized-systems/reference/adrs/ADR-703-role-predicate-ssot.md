| | |

| **Σχετικά** | ADR-702 (tenant query scope — γέννησε αυτή την εκστρατεία στο §5), ADR-697, ADR-356, ADR-255 |

## 1. Context

Το ADR-702 §5 κατέγραψε ως επόμενη εκστρατεία τις **ωμές συγκρίσεις συμβολοσειράς**
`globalRole === 'super_admin'` που ζουν δίπλα σε κώδικα ο οποίος ρωτά σωστά το
`isRoleBypass()` — τον predicate του roles SSoT (`src/lib/auth/roles.ts:429`).

### 1.1 Γιατί είναι πρόβλημα, παρότι σήμερα «δουλεύει»

Το `isRoleBypass(roleId)` δεν συγκρίνει όνομα ρόλου· διαβάζει τη **δήλωση**
`PREDEFINED_ROLES[roleId].isBypass`. Σήμερα **μόνο** το `super_admin` τη φέρει
(`roles.ts:61`), άρα οι δύο διατυπώσεις είναι **συμπεριφορικά ταυτόσημες**.

Η διαφορά εμφανίζεται τη στιγμή που κάποιος προσθέσει **δεύτερο ρόλο με `isBypass: true`**
(break-glass λογαριασμός, support engineer, on-call). Τότε:

- τα σημεία που ρωτούν `isRoleBypass()` τον τιμούν **αυτόματα**·
- τα σημεία με ωμή σύγκριση τον **αρνούνται σιωπηλά**.

Δεν σκάει τίποτα. Δεν πέφτει test. Ο κώδικας **διαβάζεται σωστός**. Είναι το ίδιο σχήμα
με τα «0» των N.11/N.12: *η απουσία σήματος δεν είναι απόδειξη υγείας.*

### 1.2 Γιατί δεν υπάρχει δεύτερο δίχτυ (κληρονομιά ADR-702)

Τα routes διαβάζουν με **Firebase Admin SDK, που παρακάμπτει by design τους
`firestore.rules`**. Ό,τι δεν πιάσει το επίπεδο εφαρμογής δεν το πιάνει τίποτα.
Ένας ρόλος που αρνείται σιωπηλά **δεν** διορθώνεται από τα rules παρακάτω.

> έδειξε ότι το ίδιο string εξυπηρετεί **πέντε διαφορετικά ερωτήματα**. Blanket `sed` =
> εγγυημένη ζημιά. Ο ratchet μετρά το string· η ταξινόμηση μετρά τη σημασία.

## 3. Οι πέντε κατηγορίες

### Κ-Α — Πύλη διαχειριστή ✅ ΕΓΙΝΕ (31 αρχεία / ~48 σημεία)

```ts
if (ctx.globalRole !== 'super_admin') { return 403 }
```

Ερώτημα: *«έχει ο καλών προνόμιο παράκαμψης;»* — ακριβώς ό,τι απαντά το `isRoleBypass()`.
Πρότυπο: η μετανάστευση του ADR-702 στο `api/admin/iso19650/costs/route.ts`.

Καλύφθηκαν: `api/admin/{backfill-*, bim-diagnostics, bootstrap-company, fix-admin-registry,
migrate-*, migrations/*, search-backfill, seed-*, telegram/webhook}`,
`api/navigation/{add-companies, auto-fix-missing-companies, fix-contact-id,
force-uniform-schema, normalize-schema, radical-clean-schema}`,
`api/setup/firebase-collections`, `api/accounting/bank/reconcile` (η **εξαίρεση διαχωρισμού
καθηκόντων** — «δεν εκκαθαρίζεις ό,τι ταίριαξες ο ίδιος, εκτός αν παρακάμπτεις»).

### Κ-Β — Διάζευξη admin ⏸️ ΑΝΟΙΧΤΟ (9 σημεία)

```ts
const isAdmin = ctx.globalRole === 'super_admin' || ctx.globalRole === 'company_admin';
```

**Άλλο ερώτημα**: «επίπεδο admin», όχι «bypass». **Δεν υπάρχει SSoT γι' αυτό** και
**δεν δημιουργήθηκε** — η επιλογή είναι πολιτικής, όχι μηχανικής.

> 🚨 **ΠΑΓΙΔΑ — ΜΗΝ χρησιμοποιήσεις το `isAdminRole()`.**
> Το `src/lib/auth/security-policy.ts:65` μοιάζει ο προφανής υποψήφιος και **είναι λάθος**:
> δουλεύει σε **άλλο λεξιλόγιο ρόλων** — `ADMIN_ROLES = ['admin','broker','builder']`
> (γρ. 24) — όχι στο `GlobalRole`. Χρήση του εδώ θα έκανε **κάθε** έλεγχο `false`,
> δηλαδή **καθολική άρνηση**. Δύο λεξιλόγια ρόλων συνυπάρχουν στο repo· δεν ενοποιούνται εδώ.

Σημεία: `api/companies:75`, `api/navigation/company:49,107`, `api/onboarding/organization:69,83`,
`api/org-structure:69`, `api/projects/bootstrap/bootstrap-queries:49`,
`api/accounting/bank/reconcile:168`, `api/admin/set-user-claims/claims-handler:161`.

### Κ-Γ — Διαφυγή ανά έγγραφο ⛔ ΔΕΝ ΑΓΓΙΖΕΤΑΙ (7 σημεία)

```ts
if (data.companyId !== ctx.companyId && ctx.globalRole !== 'super_admin') { … }
```

Έδαφος **ADR-255** (per-document), όχι ADR-702 (list-scope). Τα τέσσερα δόγματα
tenant-scoping **δεν ενοποιούνται** — μετανάστευση εδώ αλλάζει *ποιος βλέπει τι*.

### Κ-Δ — List-scope ➡️ ΑΝΗΚΕΙ ΣΤΟ ADR-702 (7 σημεία)

```ts
const isSuperAdmin = ctx.globalRole === 'super_admin';   // → όλα τα tenants ή μόνο δικά μου
```

Σωστός προορισμός: `resolveTenantListScope` + `tenantScopedCollection` (ADR-702) —
**μεγαλύτερο κέρδος** από το `isRoleBypass`, γιατί εκεί το λάθος δεν είναι «σιωπηλή άρνηση»
αλλά **σιωπηλή διαρροή**. Σημεία: `api/dxf-dimension-styles:52`, `api/dxf-levels:76`,
`api/parking:259`, `api/storages:150`, `api/quotes/[id]/comments/[commentId]:116`,
`lib/asset-packs/asset-pack-guard.server:117`,
`services/filesystem/file-mutation-gateway:81`, `services/firestore/auth-context:68`,
`subapps/dxf-viewer/systems/levels/LevelsSystem:82`.

### Κ-Ε — Νόμιμα ειδικά ⛔ ΔΕΝ ΑΓΓΙΖΟΝΤΑΙ

- **`lib/auth/super-admin-scope.ts:39,46`** — **είναι** ο SSoT του ADR-356· το
  `superAdminOverride` (header switcher) αφορά τον συγκεκριμένο ρόλο εξ ορισμού.
- **`api/admin/bootstrap-admin:83,85`** — ελέγχει αν **υπάρχει** super admin (bootstrap).
- **`api/admin/set-user-claims/claims-handler:161`** — χαρτογράφηση ρόλου → δικαιωμάτων.
- **UI** (`debug/token-info`, `RoleManagementPageContent`, `app-sidebar`,
  `ConditionalAppShell`) — εμφανίζουν/χρωματίζουν τον **συγκεκριμένο** ρόλο.

## 4. Decision

1. **Κ-Α → `isRoleBypass(ctx.globalRole)`**, ένα αρχείο τη φορά, με ανάγνωση του γύρω κώδικα.
2. **Ένας κοινός guard για τα 7 byte-identical σημεία** — νέο
   `src/lib/auth/bypass-role-guard.ts`:

```ts
const forbidden = bypassRoleGuard(ctx);
if (forbidden) return forbidden;
```

   Καταναλωτές: `bootstrap-company` (×3), `migrate-accounting-profile` (×2),
   `migrate-accounting-singletons` (×2) — τα μόνα με **ταυτόσημο** σώμα 403
   (`{ success:false, error:'Forbidden: super_admin required', code:'SUPER_ADMIN_REQUIRED' }`).

3. **ΕΝΑ payload, επίτηδες — καμία παραμετροποίηση.** Routes με διαφορετικό 403
   (`ApiError`, `createErrorResponse`, δικό τους κείμενο) καλούν **απευθείας** το
   `isRoleBypass()`. Ένα option-bag δεν θα αφαιρούσε το διπλότυπο — θα το **μετακόμιζε στο
   config του call site**, η ακριβής αστοχία που μετρήθηκε στα ADR-698/699. *Δεύτερο σταθερό
   payload ⇒ δεύτερη ονομασμένη συνάρτηση, όχι flag.*

4. **Κανένα σχόλιο-αιτιολόγηση στα call sites.** Πρώτη εκδοχή είχε δίστιχο σχόλιο σε 31
   αρχεία· μετρήθηκε ότι το ίδιο το `isRoleBypass()` αυτο-τεκμηριώνεται και ότι τα σχόλια
   **παρέθεταν το ίδιο το απαγορευμένο pattern**, δηλαδή θα γεννούσαν 31 μόνιμα ψευδώς
   θετικά στον μελλοντικό φύλακα. Το «γιατί» ζει εδώ και στο `bypass-role-guard.ts`.

### Τι ΔΕΝ αποφασίστηκε

Τα 4 σημεία με payload **χωρίς** `code` (`migrate-company-id` ×2, `migrate-nav-company-id` ×2)
έμειναν εκτός του guard: η ενοποίησή τους **προσθέτει** πεδίο `code` στο σώμα 403 — προσθετική
αλλά υπαρκτή αλλαγή συμβολαίου. Είναι απόφαση του Giorgio, τεσσάρων γραμμών.

## 5. Παράπλευρο εύρημα — νεκρός κλάδος `'admin'`

`components/app-sidebar.tsx:39` και `components/layout/ConditionalAppShell.tsx:126`
συγκρίνουν με `globalRole === 'admin'`. Το `'admin'` **δεν υπάρχει** στο `GLOBAL_ROLES`
(`super_admin | company_admin | internal_user | external_user`, `lib/auth/types.ts:11-16`) —
ανήκει στο **άλλο** λεξιλόγιο (`ADMIN_ROLES`, §3 Κ-Β). Ακίνδυνο σήμερα επειδή είναι
`||`-ωμένο με το `super_admin`, αλλά είναι μετρημένο ίχνος ότι τα δύο λεξιλόγια έχουν
διαρρεύσει το ένα στο άλλο. **Δεν διορθώθηκε** — δικό του εισιτήριο.

## 6. Επαλήθευση

| Έλεγχος | Αποτέλεσμα |
|---|---|
| `npx jest src/lib/auth src/app/api` | ✅ **463/463**, 32 suites (453 προϋπάρχοντα **αμετάβλητα** + 10 νέα) |
| Μέτρηση pattern | ✅ 87 → 39 σημεία· 33 κώδικας, **0 στην Κ-Α** |
| `jscpd` πριν/μετά (μετρημένο, βλ. §6.1) | ⚠️ clones **30 → 31**, duplicatedTokens **2096 → 2076** |
| `tsc` | ❌ δεν έτρεξε — **N.17** |
| Browser | ❌ δεν απαιτείται — μηδενική αλλαγή συμπεριφοράς· η απόδειξη είναι τα αμετάβλητα tests |

Η **μηδενική αλλαγή συμπεριφοράς** δεν είναι ευχή: `isRoleBypass('super_admin') === true`
και κανένας άλλος ρόλος δεν φέρει `isBypass`. Το καρφώνει το
`__tests__/bypass-role-guard.test.ts` — που **δεν** ελέγχει «περνά ο super_admin» (αυτό το
ικανοποιεί και μια ωμή σύγκριση) αλλά ότι η ετυμηγορία του guard **συμφωνεί με το registry
για κάθε ρόλο**, με **self-test** ότι το registry δηλώνει σήμερα ακριβώς έναν bypass ρόλο
(αλλιώς το πρώτο test γίνεται κενό περιεχομένου).

### 6.1 Το jscpd — τι πραγματικά έδειξε (N.18)

Η πρώτη εκτέλεση `jscpd:diff` βρήκε clones. **Δεν αρκεί το «προϋπήρχαν» ως ισχυρισμός**, οπότε
μετρήθηκε: αντιγράφηκαν οι HEAD εκδοχές των ίδιων 31 αρχείων σε temp και έτρεξε το ίδιο jscpd.

| Στιγμιότυπο | clones | duplicatedTokens |
|---|---|---|
| HEAD (πριν) | 30 | 2096 |
| Πρώτη εκδοχή (με τα 31 σχόλια) | 34 | 2369 |
| **Τελικό** (χωρίς σχόλια, με τον guard) | **31** | **2076** |

Απομόνωση αιτίου: αφαιρώντας **μόνο** τη γραμμή `import { isRoleBypass } …` από τα αντίγραφα,
το δέλτα έπεσε από `+4/+273` σε `+1/+89` ⇒ **3 από τα 4 clones ήταν η κοινή γραμμή import**.
Δηλαδή: *η εισαγωγή ενός SSoT συμβόλου σε 31 αρχεία κάνει τα import blocks τους πιο όμοια.*
Αυτό είναι το **ζητούμενο** της κεντρικοποίησης, όχι ελάττωμα — και είναι δομικό τυφλό σημείο
ενός token-based εργαλείου: το jscpd δεν ξεχωρίζει «μοιράζονται SSoT» από «διπλασιάζουν λογική».

Το υπόλοιπο `+1` είναι **jitter στο κατώφλι των 50 tokens** πάνω σε προϋπάρχον boilerplate
(`withSensitiveRateLimit(withAuth(async (req, ctx, _cache) => …))`). Τελικό αποτέλεσμα:
**λιγότερα διπλά tokens από ό,τι στο HEAD** (−20), χάρη στον guard.

> 🔴 **Το CHECK 3.28 θα ΜΠΛΟΚΑΡΕΙ παρ' όλα αυτά** (`exit 1`, 15 ζεύγη). Ο λόγος **δεν** είναι
> αυτή η αλλαγή: οποιοδήποτε commit αγγίζει ≥2 από αυτά τα admin routes σκοντάφτει στην
> **προϋπάρχουσα τελετουργία route** που μοιράζονται. Η πραγματική θεραπεία είναι η
> μετανάστευση σε `defineRoute` (ADR-602/603) — ξεχωριστή εκστρατεία, **όχι** κρυφό
> παρακλάδι αυτής. Μέχρι τότε: `SKIP_JSCPD_DIFF=1` με αυτή την παράγραφο ως αιτιολόγηση,
> ή grouped commits που δεν βάζουν clone-εταίρους στο ίδιο commit.

## 7. Επιβολή — τι ΔΕΝ μπήκε και γιατί

**Κανένας ratchet/registry κανόνας δεν προστέθηκε.** Με 33 ζωντανά σημεία σε Κ-Β/Γ/Δ/Ε, μια
allowlist 29 αρχείων θα ήταν **μηδέν σήμα** — ακριβώς η παθολογία που τεκμηριώνει το
CLAUDE.md N.12 για το CHECK 3.18. Ο φύλακας μπαίνει **μετά** την απόφαση για Κ-Β και τη
μετανάστευση Κ-Δ, και το πρότυπο υπάρχει: `lib/auth/__tests__/tenant-scope-anchor.test.ts`
(σαρώνει αρχεία API, **έχει self-test**). Δεν χρειάζεται νέα μηχανή ratchet.

## 8. Google-level declaration

✅ **Google-level: ΝΑΙ** για την Κ-Α — ένα ερώτημα, ένας ιδιοκτήτης (`isRoleBypass`), ένα
σταθερό payload χωρίς παραμετροποίηση, μηδενική αλλαγή συμπεριφοράς **αποδεδειγμένη** από
αμετάβλητα tests, και ο ισχυρισμός «τα clones προϋπήρχαν» **μετρήθηκε** με before/after
αντί να δηλωθεί.

⚠️ **PARTIAL για το σύνολο** — και αυτό είναι το σωστό αποτέλεσμα εδώ: 33 σημεία παραμένουν,
αλλά τα 7 από αυτά (Κ-Δ) ανήκουν σε **άλλο** ADR, τα 7 (Κ-Γ) σε **τρίτο**, τα 9 (Κ-Β)
χρειάζονται **απόφαση προϊόντος**, και τα υπόλοιπα είναι **σωστά ως έχουν**. Η εναλλακτική —
να τα «καθαρίσω» όλα — θα ήταν ακριβώς το blanket refactor που το §2 απορρίπτει.
