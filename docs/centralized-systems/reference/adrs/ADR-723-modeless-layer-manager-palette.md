## 1. Το πρόβλημα

Ο «Διαχειριστής Στρώσεων» άνοιγε (Ctrl+L / View tab) ως Radix `Dialog`: **focus trap**, backdrop,
`inert` στο υπόλοιπο δέντρο. Δηλαδή για να κρύψεις μια στρώση έπρεπε να **σταματήσεις** να σχεδιάζεις,
και για να σχεδιάσεις έπρεπε να **κλείσεις** τον Διαχειριστή. Ο κύκλος «κρύψε → δες → σχεδίασε →
ξανακρύψε» απαιτούσε άνοιγμα/κλείσιμο σε κάθε βήμα.

**Η modality ήταν η ανωμαλία, όχι το floating.** Ο κλάδος είναι ομόφωνος:

| Εφαρμογή | Layer / Properties palette |
|---|---|
| **AutoCAD** | `LAYER` = modeless palette· αλλαγές εφαρμόζονται **άμεσα**, χωρίς κουμπί OK |
| **Revit** | Properties palette = modeless, μένει ανοιχτή όσο δουλεύεις |
| **Cinema 4D** | Layer Manager = dockable manager σε δικό του tab |
| **Figma** | Layers panel μόνιμα ορατό, μηδενική modality |

Το ίδιο το repo είχε ήδη γράψει το δόγμα — στο `@/components/ui/dialog`:

> ⚠️ Ένα panel που πρέπει να μείνει ανοιχτό ΕΝΩ ο χρήστης δουλεύει σε ό,τι βρίσκεται πίσω του
> **δεν είναι dialog**. Ακόμη και με `modal={false}` ένας Radix dialog κλείνει στο πρώτο κλικ
> εκτός — δηλαδή τη στιγμή που ο χρήστης αγγίζει ακριβώς αυτό για το οποίο μιλά.

Και το είχε ήδη εφαρμόσει **τρεις φορές**: `ClashReportPanel` (ADR-435), topography QA panel
(ADR-650 M5α.2), Visibility/Graphics (ADR-375 v2.15, ίδιο ακριβώς migration από dropdown σε παλέτα).
Ο Διαχειριστής Στρώσεων ήταν απλώς ο επόμενος στη σειρά.

## 2. Τι έλειπε από το κοινό primitive (και γιατί διορθώθηκε **εκεί**)

Το SSoT audit (grep πριν από κάθε γραμμή κώδικα) βρήκε ώριμη υποδομή:

| Υπάρχον SSoT | Ρόλος |
|---|---|
| `@/components/ui/floating` → `FloatingPanel` | compound, draggable, `aria-modal="false"`, χωρίς backdrop, **17 καταναλωτές** |
| `@/hooks/useDraggable` | θέση· pointer events (ADR-176), όρια, Minimum Visible Header (ADR-030) |
| `@/lib/storage` | SSR/quota-safe localStorage του **κοινού** επιπέδου |
| `systems/escape-bus` + `ESC_PRIORITY` | ιδιοκτησία του Escape (ADR-364) |
| `@/lib/a11y/keyboard-scope` | «ποιος κατέχει το πληκτρολόγιο;» (ADR-711) |
| `stores/createToggleStore` | factory για `{isOpen}` singleton stores |
| `config/panel-tokens` → `PanelPositionCalculator` | αγκύρωση panel από το DOM (ADR-029) |

Έλειπαν **δύο** πράγματα — και έλειπαν από **όλες** τις 17 παλέτες, όχι μόνο από αυτήν:

1. **Αλλαγή μεγέθους.** Καμία. (Το `react-resizable-panels` του repo λύνει άλλο πρόβλημα:
   split-pane groups μέσα σε ροή διάταξης, όχι ελεύθερα τοποθετημένο `fixed` στοιχείο.)
2. **Μνήμη θέσης/μεγέθους.** Καμία παλέτα δεν θυμόταν τίποτα.

Υλοποιημένα μέσα στον Διαχειριστή θα ήταν το **18ο αντίγραφο** λογικής διάταξης. Υλοποιημένα στο
primitive είναι **προαιρετικά** (`resizable`, `persistenceKey`) και οι 17 υπάρχουσες κλήσεις μένουν
byte-identical — καμία τους δεν περνά τα νέα props (regression test το κλειδώνει, §6).

## 3. Ο ΕΝΑΣ κανόνας γεωμετρίας

Μέχρι τώρα ο κανόνας «πόσο μπορεί να βγει εκτός οθόνης» ζούσε **inline** στο `FloatingPanel.tsx`, ως
δύο literals στην κλήση του `useDraggable`. Με **έναν** καταναλωτή (το σύρσιμο) αυτό αρκούσε. Το
ADR-723 προσθέτει **δύο** ακόμη: την αλλαγή μεγέθους και την **επαναφορά** από localStorage.

Τρία αντίγραφα του ίδιου κανόνα αποκλίνουν σιωπηλά: το σύρσιμο θα σταματούσε στα 40px και η
επαναφορά θα επέτρεπε 0px ⇒ **παλέτα που δεν πιάνεται**. Γι' αυτό ο κανόνας εξήχθη σε καθαρές
συναρτήσεις (`floating-panel-geometry.ts`) και τον **εισάγουν** και οι τρεις.

```
panelDragBounds(size, viewport):
  min.x = -(width - 40)      // βγαίνει αριστερά, μένουν 40px της δεξιάς άκρης
  max.x = viewport.w - 40    // βγαίνει δεξιά,   μένουν 40px της αριστερής
  min.y = 0                  // ΠΟΤΕ πάνω από την κορυφή: εκεί δεν πιάνεται
  max.y = viewport.h - 40
```

**Η σειρά στο `clampPanelGeometry` δεν είναι στιλιστική:** μέγεθος **πρώτα**, θέση **μετά**. Τα όρια
θέσης είναι συνάρτηση του πλάτους· αν η θέση κρινόταν πρώτη, θα κρινόταν με το **παλιό** πλάτος και το
αποτέλεσμα θα ήταν εκτός ορίων μετά τη συρρίκνωση. (Test: §6, «περιορίζει ΠΡΩΤΑ το μέγεθος».)

### 3.1 Το ελάττωμα του κλάδου που κλείνει εδώ

«Layer Properties palette lost off-screen» είναι **τεκμηριωμένο** πρόβλημα του AutoCAD: η παλέτα
αποθηκεύει x/y, ο χρήστης αποσυνδέει τη δεύτερη οθόνη, και στο επόμενο άνοιγμα επαναφέρεται σε
συντεταγμένες που **δεν υπάρχουν πια**. Η θεραπεία είναι χειροκίνητη (registry / Move+βελάκια). Ίδιο
σχήμα και στα Windows — γι' αυτό υπάρχει το «Remember window locations based on monitor connection»,
που και αυτό αστοχεί.

**Εδώ η αποθηκευμένη γεωμετρία δεν είναι ποτέ αλήθεια — είναι ιστορικό.** Κάθε ανάγνωση περνά από
`clampPanelGeometry` με το **τρέχον** viewport, και το ίδιο ξανασυμβαίνει σε κάθε `window.resize`
(μικρότερο παράθυρο, αποσύνδεση οθόνης, περιστροφή tablet, άνοιγμα devtools). Η παλέτα **δεν μπορεί
δομικά** να χαθεί.

Δύο λεπτομέρειες που δεν είναι προφανείς:

- Ο φύλακας του resize ρωτά **πρώτα** `isPanelGeometryWithinBounds`. Στη συνήθη περίπτωση δεν γράφεται
  state ⇒ κανένα render. Το `resize` συγχωνεύεται σε frame (rAF), ένα render ανά frame το πολύ.
- Η διάσωση **δεν κάνει persist**. Η μεγιστοποίηση/επαναφορά παραθύρου είναι προσωρινή· ο χρήστης δεν
  «χάνει» τη διάταξή του για τη δεύτερη οθόνη επειδή μίκρυνε στιγμιαία το παράθυρο. Επιβεβαιώθηκε
  ζωντανά: μετά τη διάσωση, το localStorage κρατούσε ακόμη το `{x:5200, y:2400}`.

### 3.2 Η αλλαγή μεγέθους: η απέναντι άκρη δεν κουνιέται

`useResizable` (νέο, αδελφός του `useDraggable`, ίδιο λεξιλόγιο — Pointer Events, pointer capture,
`pointercancel`, μηδέν `any`, **καμία νέα εξάρτηση** ⇒ ο κανόνας N.5 δεν ενεργοποιείται).

Στις άκρες **βόρεια/δυτικά** το σταθερό σημείο είναι η **απέναντι** άκρη, άρα η θέση πρέπει να
μετακινηθεί κατά ό,τι άλλαξε το μέγεθος. Ο αφελής υπολογισμός (`width -= dx` χωρίς `x += dx`) παράγει
panel που «γλιστράει» — και **χειρότερα**, στο ελάχιστο μέγεθος συνεχίζει να μετακινείται ενώ δεν
συρρικνώνεται πια.

Η θεραπεία είναι δομική, όχι φύλακας: η θέση υπολογίζεται από το **περιορισμένο** μέγεθος
(`x + (width - nextWidth)`), όχι από το ωμό `dx`. Στο ελάχιστο, το `nextWidth` παύει να αλλάζει ⇒
παύει και η θέση. **Αδύνατο να γλιστρήσει.**

Επιπλέον, το πάνω όριο στις βόρειες/δυτικές άκρες κόβεται στο `origin.y + height` / `origin.x + width`:
η παλέτα σταματά να μεγαλώνει όταν η άκρη της φτάσει στην κορυφή / αριστερή πλευρά του viewport, αντί
να συνεχίσει «κάτω από» την οθόνη.

## 4. Ιδιοκτησία πληκτρολογίου — γιατί ο καμβάς επιβιώνει

**Το κλειδί είναι μια αφαίρεση, όχι μια προσθήκη:** η παλέτα **δεν** καλεί
`pushModalKeyboardScope()` (ADR-711).

Οι ~43 window-level accelerators του viewer περνούν από `shouldGlobalShortcutYield`, που ρωτά δύο
ανεξάρτητα πράγματα:

1. ενεργό modal scope; → **πάντα `false`** εδώ ⇒ οι συντομεύσεις ζουν όσο η παλέτα είναι ανοιχτή·
2. καταναλώνει το εστιασμένο στοιχείο τον χαρακτήρα; → **`true`** όταν ο χρήστης γράφει στο πεδίο
   αναζήτησης της παλέτας ⇒ ο καμβάς δεν κλέβει τα γράμματα.

**Το ίδιο πρωτόκολλο απαντά σωστά και στις δύο καταστάσεις, χωρίς ούτε έναν νέο listener.**
(Επαληθεύτηκε ζωντανά: πληκτρολόγηση `VT_KANABOS` στην αναζήτηση δεν ενεργοποίησε κανένα εργαλείο.)

### 4.1 Το Escape

Νέο σκαλί `ESC_PRIORITY.FOCUSED_PALETTE = 990`, με **υποχρεωτικό** έλεγχο εστίασης στο `canHandle()`.

⚠️ Ο έλεγχος δεν είναι προαιρετικός. Χωρίς αυτόν, μια ανοιχτή παλέτα θα κατανάλωνε **κάθε** ESC της
εφαρμογής ⇒ θα σκότωνε το «ακύρωση εντολής / αποεπιλογή», το συχνότερο πλήκτρο του σχεδιαστή. Αυτό
είναι ακριβώς η παλινδρόμηση §10.12 του ADR-364 σε νέα συσκευασία.

**Γιατί καθόλου ESC, αφού οι μεγάλοι δεν το κάνουν;** Σε Revit / AutoCAD / Figma το ESC με εστίαση σε
παλέτα δεν κάνει τίποτα — νεκρό πλήκτρο. Το WAI-ARIA για non-modal dialogs το ζητά. Επειδή είναι
φραγμένο στην εστίαση, **δεν μπορεί δομικά** να ενοχλήσει τον καμβά: γνήσια προσθήκη πάνω από την
πρακτική του κλάδου, όχι απόκλιση από αυτήν. (Και όταν ο χρήστης γράφει στην αναζήτηση, ο bus
παραιτείται μόνος του — το ESC ακυρώνει **πρώτα** το πεδίο, όπως παντού.)

### 4.2 Εστίαση κατά το άνοιγμα

Η παλέτα **δεν** κλέβει την εστίαση. Είναι η συμπεριφορά AutoCAD/Revit **και** η κυριολεκτική
απαίτηση του αιτήματος: αν το Ctrl+L έπαιρνε την εστίαση, το επόμενο πλήκτρο δεν θα πήγαινε στο σχέδιο.

Το `role="dialog"` απέκτησε **προσβάσιμο όνομα** (`aria-labelledby` → ο `<h3>` του header). Μέχρι το
ADR-723 και οι 17 παλέτες ήταν ανώνυμες — πραγματική παραβίαση axe («dialog must have accessible name»),
που διορθώθηκε για όλες ταυτόχρονα.

### 4.3 Δύο ψεύτικες υποσχέσεις που αφαιρέθηκαν

- Η **λαβή συρσίματος** ήταν `role="button"` + `tabIndex={0}` **χωρίς κανέναν χειριστή πληκτρολογίου**:
  ο χρήστης έφτανε με `Tab`, πατούσε `Enter`, δεν συνέβαινε τίποτα. Μία ψεύτικη στάση **σε καθεμία από
  τις 17 παλέτες**. Έγινε `aria-hidden` βοήθημα δείκτη· η επικεφαλίδα παραμένει συρόμενη.
- Οι **8 λαβές αλλαγής μεγέθους** είναι εξαρχής `aria-hidden`. Ο πειρασμός `role="separator"` +
  `tabIndex` είναι λάθος: (α) οκτώ νέες στάσεις `Tab` ανά παλέτα πριν καν το περιεχόμενο, και το
  `separator` του APG περιγράφει διαχωριστικό **μεταξύ δύο περιοχών** με `aria-valuenow` (VS Code sash),
  όχι περίγραμμα παραθύρου· (β) η αλλαγή μεγέθους **δεν φράζει περιεχόμενο** — το σώμα κυλά, άρα κάθε
  γραμμή είναι προσβάσιμη και στο προεπιλεγμένο μέγεθος. Κατά WCAG 2.1.1 απαιτείται λειτουργική με
  πληκτρολόγιο η **λειτουργία**, όχι κάθε βοήθημα δείκτη. Ίδια στάση με Revit/AutoCAD.

### 5.1 Δύο παγίδες που κοστίζουν ώρες

- **ΚΑΜΙΑ κλάση `relative` στη ρίζα.** Η ρίζα φέρει ήδη `fixed` (design tokens), που από μόνο του
  ορίζει containing block για τις απόλυτες λαβές. Το `relative` δεν θα ήταν περιττό — θα **έσπαγε** το
  panel: στο Tailwind οι utilities θέσης παράγονται με σταθερή σειρά (static, fixed, absolute,
  **relative**, sticky) και νικά η τελευταία **στο CSS**, όχι η τελευταία στο `className`.
- **`min-h-0` στο `CardContent`.** Flex item με προεπιλογή `min-height:auto` δεν συρρικνώνεται κάτω
  από το περιεχόμενό του ⇒ το `overflow-auto` δεν θα ενεργοποιούνταν ποτέ και η παλέτα θα ξεχείλιζε
  αντί να κυλά.
- **Η αποθηκευμένη θέση νικά τον `getClientPosition`.** Το `useDraggable` τρέχει τον υπολογιστή θέσης
  σε effect **μετά** το mount και κάνει άνευ όρων `setPosition`. Χωρίς ρητή απόσυρσή του όταν υπάρχει
  επαναφορά, η παλέτα θα «θυμόταν» για ένα frame και μετά θα πηδούσε στην προεπιλογή.

## 7. Ρητά **εκτός** σκοπού
