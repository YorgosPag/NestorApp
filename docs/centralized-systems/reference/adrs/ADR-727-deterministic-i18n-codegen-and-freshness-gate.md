## 1. Το πρόβλημα

Το `src/types/i18n.ts` είναι **παραγόμενο** αρχείο (`scripts/generate-i18n-types.js`). Είναι ο κορμός
τύπων κάθε κλήσης `t('ns.key')` στην εφαρμογή: `I18nKeys`, `TranslationNamespace`, `TranslationKey`.

Στις 2026-07-29 μετρήθηκε ότι ήταν **μπαγιάτικο από τις 2026-04-03 — τέσσερις μήνες**:

| Μέγεθος | Τιμή |
|---|---|
| Header του αρχείου | `Generated: 2026-04-03T19:12:27.149Z` |
| Απόκλιση από αναπαραγωγή | **+39.920 / −16.368** γραμμές (μετρημένο με `git diff --stat`) |
| Γραμμές στον δίσκο → μετά την αναπαραγωγή | 28.065 → 51.618 |
| Είσοδοι | 100 αρχεία `*.json` στο `src/i18n/locales/el/` |

**Καμία από τις 30+ CHECK του pre-commit δεν το έπιασε**, και οι λόγοι είναι διδακτικοί:

- `validate:i18n` έδειχνε **30016/30016 ✅** — ελέγχει πληρότητα EL↔EN, **άλλο ερώτημα εντελώς**.
- CHECK 3.8 / 3.9 / 3.13 ελέγχουν κλειδιά, ICU και resolver reachability — καμία φρεσκάδα τύπων.
- `scripts/validate-i18n-manifest.js` διαβάζει όντως το αρχείο, αλλά **μόνο** την ένωση
  `TranslationNamespace` (ονόματα namespace) ⇒ τυφλό σε αλλαγή κλειδιών. Και δεν είναι συνδεδεμένο
  πουθενά — μηδέν αναφορές σε hook ή workflow.

➜ **Κανείς δεν ρωτούσε το μόνο ερώτημα που μετράει: «ταιριάζει ακόμη αυτό το παραγόμενο αρχείο με τα
αρχεία από τα οποία παρήχθη;»**

Αυτό είναι το ίδιο σχήμα με τα `0` του N.11/N.12: **το πράσινο σήμαινε «κανείς δεν κοίταξε», όχι «καθαρό».**

## 2. Η αιτία: η έξοδος δεν ήταν ντετερμινιστική

Ο γεννήτορας ενσωμάτωνε στη γραμμή 149:

```js
 * Generated: ${new Date().toISOString()}
```

**Συνέπεια: κάθε εκτέλεση παρήγαγε διαφορετικό αρχείο, ακόμη και με μηδενική πραγματική απόκλιση.**

Αυτή η μία γραμμή απαγόρευε **δομικά** το καθιερωμένο βιομηχανικό μοτίβο ελέγχου παραγόμενου κώδικα:
«αναπαρήγαγε και απέτυχε αν το diff δεν είναι κενό» (`go generate ./... && git diff --exit-code`,
Bazel `diff_test`). Με ρολόι στην έξοδο, **καμία** τέτοια πύλη δεν μπορεί ποτέ να περάσει.

Ένα timestamp μέσα σε παραγόμενο αρχείο είναι αναγνωρισμένο anti-pattern ακριβώς γι' αυτόν τον λόγο —
είναι η ίδια κατηγορία προβλήματος που λύνει το `SOURCE_DATE_EPOCH` στα reproducible builds.

Τα υπόλοιπα ήταν ήδη ντετερμινιστικά (`Object.keys().sort()` στα namespaces, σειρά κλειδιών JSON,
dedupe+sort στους τύπους πινάκων) — **μόνη** πηγή μη-ντετερμινισμού ήταν αυτή η γραμμή. Επαληθεύτηκε
πειραματικά: δύο διαδοχικές παραγωγές ήταν ταυτόσημες μόλις αφαιρεθεί η γραμμή `Generated:`.

### 2.1 Η απόφαση — διορθώνουμε την **αιτία**, όχι το σύμπτωμα

Απορρίφθηκε η εναλλακτική «η πύλη κόβει τη γραμμή 7 πριν τη σύγκριση»: αφήνει τον γεννήτορα σπασμένο,
απαιτεί προσαρμοσμένη λογική σε **κάθε** μελλοντικό καταναλωτή, και δεν ξεκλειδώνει το τετριμμένο
`git diff --exit-code` στο CI.

**Η γραμμή έγινε συνάρτηση των εισόδων αντί του ρολογιού:**

```js
 * Generated from: sha256:<sha256 των locale εισόδων>
```

Το fingerprint υπολογίζεται σε κανονικοποιημένη μορφή — ταξινομημένα ονόματα namespace, και για
καθένα `όνομα\0JSON.stringify(δεδομένα)\0`. Άρα είναι **αναίσθητο σε μορφοποίηση** του JSON (αλλαγή
indentation δεν το κουνά) αλλά **ευαίσθητο σε περιεχόμενο και σειρά κλειδιών** — που είναι ακριβώς οι
είσοδοι που καθορίζουν την έξοδο.

**Τι κερδίζουμε πέρα από τον ντετερμινισμό**: το header λέει πλέον **από τι** παρήχθη το αρχείο. Το
timestamp δεν σου έλεγε ποτέ αν είναι φρέσκο — το hash σου το λέει. Και επιτρέπει στην πύλη να
**διακρίνει** μεταξύ «μπαγιάτικες είσοδοι» και «κάποιος πείραξε στο χέρι ένα *Do not edit manually*
αρχείο» (§4.2) — διάκριση αδύνατη με σκέτο «τα αρχεία διαφέρουν».

## 3. Δύο δομικές παγίδες που η πύλη υπάρχει για να επιβιώσει

### 3.1 Το `mtime` **δεν** είναι σήμα φρεσκάδας

Το μπαγιάτικο αρχείο είχε mtime **σημερινό** (checkout / κανονικοποίηση γραμμών το αγγίζουν) ενώ το
περιεχόμενό του ήταν Απριλίου. Κάθε πύλη βασισμένη σε timestamps αρχείων θα έλεγε «φρέσκο».
**Μόνο σύγκριση περιεχομένου δουλεύει.**

### 3.2 Τα line endings — η παγίδα που θα έκανε την πύλη μονίμως κόκκινη

Το repo τρέχει **`core.autocrlf=true` χωρίς κανένα `.gitattributes`** (επαληθευμένο). Άρα:

| | Line endings |
|---|---|
| blob στο git | **LF** |
| αντίγραφο στο working tree (Windows) | **CRLF** |
| έξοδος του γεννήτορα (`fs.writeFileSync`) | **LF** |

Το ίδιο το git το λέει καθαρά μετά την αναπαραγωγή:
`warning: in the working copy of 'src/types/i18n.ts', LF will be replaced by CRLF the next time Git touches it`.

➜ **Μια πύλη που συγκρίνει ωμά bytes με το working tree θα ήταν κόκκινη σε κάθε μηχάνημα Windows —
μόνιμα, ανεξάρτητα από φρεσκάδα.** Δηλαδή στο μηχάνημα του Giorgio, δηλαδή πάντα.

Η `normalize()` κανονικοποιεί **και τις δύο** πλευρές: CRLF→LF, αφαίρεση BOM, ακριβώς ένα trailing
newline. Καλύπτεται από δική της ομάδα tests (Group 7), γιατί αν κάποιος αφαιρέσει τη γραμμή η πύλη
γίνεται άχρηστη με τρόπο που *μοιάζει* με πραγματικό εύρημα.

## 4. Η υλοποίηση

### 4.1 Αρχεία

| Αρχείο | Αλλαγή |
|---|---|
| `scripts/generate-i18n-types.js` | `new Date()` → `fingerprintTranslationData()`. Νέα `collectTranslationData(localeDir)` ως **μοναδικός** αναγνώστης εισόδων. Σπάσιμο της 56γραμμης `generateTypeDefinitions` σε `buildHeader` / `buildInterfaceRegistry` / `buildPublicExports` (N.7.1). Διευρυμένα exports |
| `scripts/_shared/i18n-governance.js` | Νέα `listJsonFiles(dir)`· η `getLocaleFiles(locale)` γίνεται λεπτό wrapper της — **ένας** κανόνας «ποια JSON τροφοδοτούν ένα namespace set» |
| `scripts/check-i18n-types-freshness.js` **(νέο)** | Η πύλη. 289 γραμμές |
| `scripts/run-checks-parallel.js` | Καταχώριση CHECK 3.33 στην **Phase 1** |
| `scripts/__tests__/check-i18n-types-freshness.test.js` **(νέο)** | 56 tests / 10 ομάδες |
| `.github/workflows/i18n-governance.yml` | Layer 2 — άνευ όρων εκτέλεση |
| `package.json` | `test:i18n-types-freshness`, `i18n-types:check` |

**Μηδέν διπλασιασμός εισόδων**: η πύλη **δεν** ξαναγράφει τον βρόχο ανάγνωσης — καλεί την
`collectTranslationData` του γεννήτορα. Αν οι δύο αποκλίναν, η πύλη θα σύγκρινε με κάτι που ο
γεννήτορας δεν θα παρήγαγε ποτέ.

### 4.2 Οι πέντε ετυμηγορίες

| Verdict | Σημασία |
|---|---|
| `fresh` | ταιριάζει — exit 0 |
| `missing` | το παραγόμενο αρχείο δεν υπάρχει |
| `legacy-header` | φτιαγμένο από τον προ-ADR-727 γεννήτορα (header με timestamp) |
| `stale-inputs` | fingerprint header ≠ τρέχουσες είσοδοι ⇒ **τα locale προχώρησαν, ο γεννήτορας δεν ξανάτρεξε.** Αυτό ήταν το τετράμηνο σφάλμα |
| `hand-edited` | fingerprint ταιριάζει, σώμα όχι ⇒ κάποιος πείραξε στο χέρι μηχανική έξοδο |

Το μήνυμα αποτυχίας δίνει και τα δύο fingerprints, την πρώτη διαφορετική γραμμή, την **ακριβή εντολή
διόρθωσης** (`npm run generate:i18n-types`) και το escape hatch.

### 4.3 Γιατί Phase 1 και όχι Phase 0.x

Οι υπο-φάσεις 0.5–0.9 υπάρχουν για **έναν** λόγο: εκείνες οι CHECK κάνουν `spawn()` παιδικών
διεργασιών (jscpd, tsc, knip), που κάνουν deadlock μέσα στο `worker_threads` pool της Phase 1.
Η 3.33 είναι **καθαρή Node χωρίς spawn** ⇒ ανήκει στην Phase 1. Να μπει σε 0.x «για ασφάλεια» θα
πλήρωνε σειριακό κόστος χωρίς λόγο.

**Σκανδάλη**: staged `src/i18n/locales/**/*.json` **ή** `src/types/i18n.ts`. Χρησιμοποιεί το
υπάρχον `LOCALE_FILES` του hook — δεν γράφτηκε τρίτο glob.

**Escape hatch**: `SKIP_I18N_TYPES=1`, και επαναλαμβάνεται μέσα στο μήνυμα αποτυχίας.

### 4.4 Δύο σχεδιαστικές απορρίψεις — μετρημένες, όχι εικαζόμενες

**Απορρίφθηκε το «έξυπνο fast path»**: με fingerprint στο header, η πύλη θα μπορούσε να συγκρίνει
*μόνο* hashes και να παραλείψει το χτίσιμο των 51k γραμμών. Μετρήθηκε:

| Βήμα | Χρόνος |
|---|---|
| ανάγνωση + parse των 100 JSON | 87ms |
| χτίσιμο του string τύπων | 50ms |
| hash | 24ms |
| **πλήρης έλεγχος** | **~137ms** |

Το fast path γλιτώνει **26ms από τα 137** — το parse κυριαρχεί και απαιτείται και στα δύο μονοπάτια.
Και θα ήταν **τυφλό** στο `hand-edited`. Πολυπλοκότητα για το τίποτα ⇒ ο έλεγχος κάνει πάντα την
πραγματική δουλειά.

**Απορρίφθηκε το `--smoke` mode**: οι αδελφές CHECK (3.28/3.29/3.30) το έχουν επειδή η πραγματική
τους σάρωση κάνει spawn πολυδευτερόλεπτης διεργασίας. Εδώ ο πλήρης έλεγχος είναι 137ms in-memory —
ένα «φθηνό» mode θα ήταν διάκριση χωρίς διαφορά.

### 4.5 Γιατί **όχι** ratchet

Η φρεσκάδα είναι **δυαδική**: το αρχείο είναι αναπαραγμένο ή δεν είναι. Δεν υπάρχει πλήθος που
μειώνεται σταδιακά, άρα **δεν υπάρχει baseline αρχείο και δεν πρέπει να δημιουργηθεί ποτέ**.
Αν βρεθείς να γράφεις `.i18n-types-baseline.json`, έχεις πάρει λάθος στροφή.

## 5. Enforcement (Defense in Depth)

| Layer | Πού | Εμβέλεια | Ταχύτητα |
|---|---|---|---|
| **Layer 1 — pre-commit** | `scripts/run-checks-parallel.js` CHECK 3.33 (Phase 1) | trigger-scoped: staged locale JSON **ή** `src/types/i18n.ts` | ~137ms, παράλληλα |
| **Layer 2 — CI** | `.github/workflows/i18n-governance.yml` | **άνευ όρων** σε κάθε PR/push που αγγίζει i18n | ~1s |
| **Layer 3 — κατ' απαίτηση** | `npm run i18n-types:check` | πλήρης | ~137ms |

**Γιατί χρειάζεται το Layer 2**: το Layer 1 είναι trigger-scoped. Commit με `--no-verify`, ή σε
μηχάνημα χωρίς `core.hooksPath`, το παρακάμπτει ολόκληρο.

## 6. Επικύρωση — τα tests αποδείχθηκε ότι **μπορούν** να κοκκινίσουν

Πράσινο test δεν αποδεικνύει τίποτα μέχρι να δεις ότι μπορεί να κοκκινίσει. Επανεισήχθη τεχνητά το
ελάττωμα, τέσσερις φορές, με αυτόματο mutation harness:

| Μετάλλαξη | Αναμενόμενο | Αποτέλεσμα |
|---|---|---|
| M1 — επαναφορά του ρολογιού στο header | ομάδα ντετερμινισμού κόκκινη | ✅ **18/56 κόκκινα** |
| M2 — αφαίρεση κανονικοποίησης CRLF | ομάδα line-endings κόκκινη | ✅ **2/56 κόκκινα** |
| M3 — η `classify` λέει πάντα `fresh` | ανίχνευση + CLI κόκκινα | ✅ **11/56 κόκκινα** |
| M4 — το fingerprint αγνοεί το περιεχόμενο | ανίχνευση `stale-inputs` κόκκινη | ✅ **6/56 κόκκινα** |

**4 στις 4 μεταλλάξεις πιάστηκαν.** Όλες οι πηγές επαναφέρθηκαν και επαληθεύτηκαν.

Επιπλέον επαληθεύτηκε στο **αληθινό μονοπάτι του hook** (μέσω `run-checks-parallel.js` με τις env
μεταβλητές που θέτει το hook, χωρίς άγγιγμα του κοινού index):

| Σενάριο | Αποτέλεσμα |
|---|---|
| locale staged, τύποι φρέσκοι | ✅ CHECK 3.33 OK, exit 0 |
| locale άλλαξε, τύποι δεν αναπαρήχθησαν | ⛔ exit 1, με διάγνωση `stale-inputs` |
| `SKIP_I18N_TYPES=1` | παρακάμπτεται (1 check αντί 2) |
| σκανδάλη μόνο από `src/types/i18n.ts` | τρέχει |
| άσχετο αρχείο staged | δεν τρέχει |

Και ο ανασχηματισμός του γεννήτορα επαληθεύτηκε **ισοδύναμος** με τον προηγούμενο: το σώμα των 51.618
γραμμών είναι **byte-identical** με την έξοδο του παλιού γεννήτορα (φορτωμένου από το `HEAD`), εκτός
της γραμμής header.

## 8. Σχέση με άλλες CHECK

- **CHECK 3.8** (missing keys) → κώδικας→locale: `t('key')` χωρίς αντιστοιχία. **Δεν** βλέπει τύπους.
- **CHECK 3.13** (resolver reachability) → runtime προσπελασιμότητα namespace.
- **`validate:i18n`** (ADR-666) → πληρότητα EL↔EN. Έδειχνε **30016/30016** όσο οι τύποι σάπιζαν.
- **CHECK 3.33** (αυτό) → **παραγόμενο αρχείο ↔ είσοδοί του**. Καμία άλλη CHECK δεν ρωτά αυτό.

**Γενικευμένο μάθημα**: αυτή είναι η **πρώτη** μηχανή «μπαγιάτικο παραγόμενο αρχείο» στο repo — έγινε
grep για `checksum`/`md5`/`sha256`/`stale`/`regenerate` στο `scripts/` και δεν υπήρχε καμία. Το
`scripts/generate-ssot-flat-registry.js` **τεκμηριώνει την ίδια κατηγορία σφάλματος** στο header του
(«3 days stale, 10 modules enforcing nothing»). **Κάθε παραγόμενο αρχείο που δεσμεύεται στο repo
χρειάζεται πύλη φρεσκάδας, αλλιώς σαπίζει σιωπηλά** — και το προαπαιτούμενο κάθε τέτοιας πύλης είναι
**ντετερμινιστική έξοδος**.
