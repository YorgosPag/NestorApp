# ADR-807 — Ο άνθρωπος **χωρίς γραφείο** έχει ταυτότητα

**Ημερομηνία:** 2026-08-25 · **Κατάσταση:** ✅ Εφαρμοσμένο (`96b0b445` · `ff307a28` · `e46ed507`)
**Σχετικά:** ADR-745 Φάση Γ *(η προηγούμενη — λάθος — διάγνωση)* · ADR-749 §5 *(αδρανείς φρουροί)* · ADR-787 Ε-3 / §5.3 · ADR-798 *(Βήματα 1-3)*

---

## 1. Δύο βλάβες, ένα σχήμα

Και οι δύο βρέθηκαν σε **μία** συνεδρία, ξεκινώντας από ένα «λάθος κωδικός» που δεν ήταν λάθος κωδικός. Έχουν **διαφορετική** αιτία και **ταυτόσημο** σχήμα:

> **Μια σιωπηλή απουσία διαβάστηκε ως άρνηση.**

| # | Απουσία | Διαβάστηκε ως | Αποτέλεσμα στην οθόνη |
|---|---|---|---|
| **Α** | το `NEXT_PUBLIC_USE_FIREBASE_EMULATOR` δεν έφτασε στο client bundle | `false` — «μη χρησιμοποιείς emulator» | «**Μη έγκυρα στοιχεία σύνδεσης**» |
| **Β** | το claim `companyId` λείπει | `ok:false` — «**δεν έχεις ταυτότητα**» | **ατέρμονος βρόχος** `/dashboard → /login` |

## 2. ΒΛΑΒΗ Α — ο πελάτης μιλούσε στην **παραγωγή** ενώ το script έλεγε «emulator»

### 2.1 Ο μηχανισμός, μετρημένος

Το `dev:emulator` έθετε `NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true` **μόνο στο process**. Το Next/Turbopack ενσωματώνει στο client bundle τα `NEXT_PUBLIC_*` που **γνωρίζει** — από `.env*` ή από το κλειδί `env` του `next.config.js`. Μεταβλητή που υπάρχει μόνο στο process **δεν ενσωματώνεται**: μένει runtime lookup πάνω στο `next/dist/build/polyfills/process.js`, που στον browser είναι **κενό**.

Η μεταγλωττισμένη γραμμή ήταν κυριολεκτικά:

```js
[next/dist/build/polyfills/process.js].env.NEXT_PUBLIC_USE_FIREBASE_EMULATOR === 'true'
```

⇒ `undefined === 'true'` ⇒ **false, πάντα** ⇒ Admin SDK (server) → emulator, **client → ΠΑΡΑΓΩΓΗ**.

Μετρημένο στο **ίδιο** bundle: τα `NEXT_PUBLIC_FIREBASE_PROJECT_ID` και `…_API_KEY` ήταν **απόντα ως ονόματα** (⇒ ενσωματώθηκαν, ζουν στο `.env`), ενώ το `…_USE_FIREBASE_EMULATOR` ήταν **παρόν ως όνομα**. Η διαφορά ήταν ορατή, και κανείς δεν την είχε κοιτάξει.

### 2.2 🔴 Ο φρουρός ήταν **ΑΔΡΑΝΗΣ**, και το ADR-745 είχε **λάθος αιτία**

Το `connectEmulatorOrReport` (`src/lib/firebase.ts`) γράφτηκε από το **ADR-745 Φάση Γ** ακριβώς γι' αυτή τη βλάβη, και το σχόλιό του περιγράφει το σύμπτωμα **σωστά**:

> «Το σύμπτωμα έφτανε στον χρήστη ως “Λάθος κωδικός πρόσβασης” … δηλαδή ως λάθος **διαπιστευτηρίων** ενώ ήταν λάθος **προορισμού**.»

Αλλά τυπώνει ✅/⚠️ **ΜΕΣΑ** στο `if` — που **δεν αλήθευε ποτέ**.

> **Δεν σιωπούσε επειδή πέτυχε· σιωπούσε επειδή δεν εκτελέστηκε.**

Το ADR-745 πίστεψε ότι έφταιγε το σιωπηλό `catch {}`: **σωστό όνομα βλάβης, λάθος αιτία**. Η διόρθωσή του ήταν πραγματική βελτίωση και **δεν άγγιζε** το ελάττωμα.

### 2.3 Η θεραπεία — **μία πηγή**, όχι δεύτερος διακόπτης

```js
// next.config.js
env: {
  NEXT_PUBLIC_USE_FIREBASE_EMULATOR: String(Boolean(process.env.FIREBASE_AUTH_EMULATOR_HOST)),
}
```

Το `FIREBASE_AUTH_EMULATOR_HOST` είναι η μεταβλητή που **ήδη** στρέφει τον Admin SDK (αυτόματη ανίχνευση του Firebase). Παράγοντας το client flag από **αυτήν**, η απόκλιση server/client γίνεται **δομικά αδύνατη** αντί για ανιχνεύσιμη.

⚠️ Το `.env` και το `.env.local` είναι **gitignored** — γι' αυτό η λύση ζει στο `next.config.js` (tracked): αλλιώς **δεν ταξιδεύει** στον επόμενο.

### 2.4 🔴 Ο δεύτερος διακόπτης δεν αφαιρέθηκε — είχε **μετακομίσει**

Ο SSoT audit βρήκε ότι το `NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true` ζούσε **ακόμη** σε δύο tracked αρχεία (`scripts/qa-tests/run-qa-clean.sh|.ps1`), τα οποία μάλιστα ήταν **ήδη σπασμένα, ανάποδα**: ξεκινούν `--only firestore,auth,storage` (ο Auth emulator **τρέχει**) αλλά έθεταν μόνο `FIRESTORE_EMULATOR_HOST` ⇒ client→emulator, **server→παραγωγή για Auth**. Το ίδιο ελάττωμα, καθρεφτισμένο.

```diff
- NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true      # ο δεύτερος διακόπτης
+ FIREBASE_AUTH_EMULATOR_HOST=localhost:9099  # η ΜΙΑ πηγή
+ STORAGE_EMULATOR_HOST=http://localhost:9199
```

### 2.5 🔴 ΔΥΟ dev servers στον ίδιο κατάλογο build

Μετρημένο ζωντανά: έτρεχαν **δύο** `next dev` — `npm run dev` (:3000, **παραγωγή**) και `dev:emulator` (:3001) — και **κανένας** δεν έθετε `NEXT_DIST_DIR` ⇒ έγραφαν **και οι δύο στο `.next`**, ξαναγράφοντας ο ένας τα chunks του άλλου. Ο φυλλομετρητής ήταν στο `:3000`, δηλαδή στον **λάθος server**.

Συνέπεια που δεν είναι εργονομική αλλά **επιστημολογική**: *κάθε μέτρηση του `.next` ήταν αδιάψευστη*. Το `dev:emulator` πήρε `NEXT_DIST_DIR=.next-emulator` — χρησιμοποιώντας τον μηχανισμό που το ίδιο το `next.config.js` **ήδη τεκμηρίωνε** στη γραμμή 4.

⚠️ **Δοκιμάστηκε και ΑΠΟΡΡΙΦΘΗΚΕ** και ένα καρφωμένο `--port 3001`, με το επιχείρημα «ο προορισμός γίνεται ορατός στη διεύθυνση». Είναι **σύμβαση που πρέπει να θυμάται άνθρωπος** — το σχήμα που εδώ έχει αποτύχει μετρημένα σε **3.34** (63) · **3.37** (18 vs 26) · **3.49** (60) · **3.57** (19/20). Οι πραγματικοί φρουροί είναι **ανεξάρτητοι θύρας**. Το `NEXT_DIST_DIR` κρατήθηκε γιατί είναι **δομικό**: δεν απαιτεί να θυμάται κανείς τίποτα.

### 2.6 Η ζωντανή απόδειξη

| μέτρηση | πριν | μετά |
|---|---|---|
| runtime lookups | `1` | **`0`** |
| τιμή flag | `"false"` | **`"true"`** |
| πύλη σύνδεσης | `compile-time falsy` → `unreachable` | **`compile-time truthy`** |
| `connectAuthEmulator(auth,'http://localhost:9099')` | νεκρός κώδικας | **ζωντανός στο chunk** |
| νέος φρουρός `fetch(:9099)` | ενεργός | **αφαιρέθηκε** *(αντιδρά στο flag)* |

Το τελευταίο είναι **δεύτερη, ανεξάρτητη** επιβεβαίωση: ο φρουρός εξαφανίστηκε **επειδή** το flag έγινε αληθές. Αν ήταν πάντα παρών, δεν θα απεδείκνυε τίποτα.

## 3. ΒΛΑΒΗ Β — «δεν έχεις εταιρεία» διαβαζόταν ως «δεν υπάρχεις»

### 3.1 Το γεγονός

Με τον προορισμό διορθωμένο, η σύνδεση του `ext.architect@solo.local` **πέτυχε** — και ο άνθρωπος **δεν έφτασε ποτέ σε οθόνη**: `/dashboard → /login → /dashboard`, κάθε ~2 δευτερόλεπτα, επ' άπειρον.

Η αιτία, **μία γραμμή** (`src/server/auth/page-identity.ts`):

```ts
const companyId = decoded.companyId as string | undefined;
if (typeof companyId !== 'string' || companyId.length === 0) {
  return { ok: false, reason: 'missing-companyId' };   // ← κατηγοριακό λάθος
}
```

Ο μόνος καταναλωτής με γνώμη — το δίχτυ `(app)/[...unprefixed]` — έκανε `if (!identity.ok) redirect(login)`.

### 3.2 🔴 Η θεραπεία ήταν **ήδη γραμμένη, τρεις φορές** — και οι τρεις **ανέφικτες**

| # | Πού | Τι λέει |
|---|---|---|
| 1 | `lib/routes/landing.ts` | στέλνει τον άνθρωπο χωρίς οργανισμό στον **δικό του** χώρο |
| 2 | `(app)/[...unprefixed]/page.tsx:84` | `PERSONAL_WORKSPACE_ALIAS` — γραμμένο **ειδικά** γι' αυτόν |
| 3 | `lib/auth/workspace-from-path.ts:113` | λύνει τον προσωπικό χώρο με **μηδέν** αναγνώσεις βάσης |

Και το σχόλιο του `dashboard/page.tsx` το λέει **κατά λέξη**:

> «⚠️ Η απουσία `companyId` **δεν** είναι λόγος για ουρά έγκρισης — είναι απλώς ένδειξη ότι ο άνθρωπος ενεργεί στον **δικό του** χώρο.»

Το #2 ήταν **αποδεδειγμένα νεκρός κώδικας**: το `ok:true` συνεπαγόταν `companyId.length > 0`, άρα το `hasOrganization(identity.ctx)` ήταν **πάντα** αληθές και ο κλάδος `PERSONAL_WORKSPACE_ALIAS` **δεν μπορούσε να εκτελεστεί**. Αδρανής φρουρός (ADR-749 §5) — αλλά χειρότερης κατηγορίας: *φρουρός που δεν είναι απλώς σιωπηλός, αλλά η ίδια η σιωπή του γεννά τη βλάβη που θα απέτρεπε.*

> **Η γνώση υπήρχε τέσσερις φορές. Η εκτέλεση καμία.**

### 3.3 Η απόφαση — **τρεις ρητές καταστάσεις, ποτέ boolean**

```ts
export type PageIdentity =
  | { ok: true;  scope: 'organization'; ctx: AuthContext }             // companyId: string
  | { ok: true;  scope: 'personal';     ctx: PersonalIdentityContext } // ΧΩΡΙΣ πεδίο companyId
  | { ok: false; reason: 'no-session' | 'invalid-session' | 'invalid-role' };
```

Το `'missing-companyId'` **έπαψε να είναι λόγος απόρριψης**. Ήταν **κατηγοριακό λάθος**: απαντούσε στο *«σε ποιον χώρο ενεργείς;»* μέσα σε ένωση που απαντά *«ποιος είσαι;»*.

### 3.4 ⚠️ Δύο αποφάσεις που δεν είναι ύφος

**(α) Ξεχωριστός τύπος, ΟΧΙ `companyId: string | null`.**
Το `AuthContext` το καταναλώνουν οι **352** διαδρομές API μέσω του `buildRequestContext`, η απομόνωση μισθωτή και τα `firestore.rules`. Χαλαρώνοντας **εκείνον** τον τύπο, κάθε σημείο που σήμερα **εγγυάται** μισθωτή θα δεχόταν σιωπηλά `null` — δηλαδή θα πληρώναμε μια διόρθωση **προσγείωσης** με **διεύρυνση της επιφάνειας ασφαλείας**. Το `PersonalIdentityContext` κάνει το αντίθετο: ο προσωπικός χώρος **δεν μπορεί δομικά** να περάσει εκεί όπου απαιτείται `companyId`.

**(β) Ο ρόλος κρίνεται ΠΡΙΝ τον χώρο.**
Ο ρόλος είναι ιδιότητα της **ταυτότητας**· άκυρος ρόλος σημαίνει cookie που δεν εμπιστευόμαστε. Με την παλιά σειρά, ένα cookie με **άκυρο ρόλο** και **χωρίς** `companyId` θα έβγαινε πλέον `personal` — δηλαδή η διόρθωση θα είχε **χαλαρώσει την ασφάλεια, σιωπηλά**.

### 3.5 🏆 Η πρακτική των μεγάλων — ομόφωνη, και πού τους ξεπερνάμε

| Παίκτης | Τι κάνει | Το όριό του |
|---|---|---|
| **OIDC / Auth0 Organizations** | το `org_id` είναι **προαιρετικό** claim· απουσία = προσωπικό context, **ποτέ** αποτυχία αυθεντικοποίησης | 🔴 το αφήνει **σιωπηλά απόν** — ακριβώς η σιωπή που διαβάστηκε λάθος εδώ |
| **GitHub** | **ένας** ενιαίος χώρος ονομάτων: ο κάτοχος είναι *είτε* πρόσωπο *είτε* οργανισμός, **ίδιου είδους** | — αυτό **είναι** το `/o/<alias>/` |
| **Confluence** | personal space με **δεσμευμένο** πρόθεμα `~username` | 🔴 το κλειδί δενόταν σε **μεταβλητό** username ⇒ η μετονομασία **έσπαγε** τον χώρο ⇒ **υποχώρησαν σε τυχαίο κλειδί** |
| **Figma** | χωρίς ομάδα ⇒ **κατασκευάζει** free Starter team | 🔴 **επιβάλλει οργανισμό** που ο άνθρωπος δεν ζήτησε |
| **Autodesk ACC** | — | 🔴 **δεν έχει καθόλου** την περίπτωση «ανεξάρτητος χωρίς εταιρεία» |

**Πού ξεπερνάμε:**

1. Το **Figma φτιάχνει πλασματική εταιρεία** για να μη μοντελοποιήσει τον μόνο άνθρωπο. Εδώ ο ιδιωτικός χώρος είναι **πρώτης τάξεως κατάσταση** — μηδέν εγγραφές στη βάση, και το `resolveWorkspaceFromPath` τον λύνει με **μηδέν αναγνώσεις**.
2. Το **Confluence έδεσε το κλειδί σε μεταβλητό όνομα** και το πλήρωσε. Το `PERSONAL_WORKSPACE_ALIAS = 'me'` είναι **σταθερή δεσμευμένη λέξη** — η λύση στην οποία κατέληξαν **μετά** το περιστατικό, εδώ εξ αρχής.
3. Το **Auth0 αφήνει το `org_id` απλώς απόν** και ελπίζει ότι η εφαρμογή θα το ελέγξει. Ακριβώς αυτή η σιωπηλή απουσία διαβάστηκε λάθος εδώ. Πλέον είναι **ονομασμένη κατάσταση σε discriminated union**: ο μεταγλωττιστής **δεν επιτρέπει** σε κανέναν από τους 3 καταναλωτές να την αγνοήσει. *Η απουσία έπαψε να είναι κάτι που θυμάσαι να ελέγξεις.*

### 3.6 Οι τρεις καταναλωτές

| Αρχείο | Τι απαντά για τον προσωπικό χώρο |
|---|---|
| `(app)/[...unprefixed]/page.tsx` | `alias = PERSONAL_WORKSPACE_ALIAS` — **ο νεκρός κλάδος ζωντάνεψε** |
| `(app)/o/[workspace]/layout.tsx` | `companyId: ''` — το **καθιερωμένο** ιδίωμα του repo για «κανένας οργανισμός»· fail-closed: ζητώντας **ξένο** γραφείο, το `decideMembership` **αρνείται** |
| `server/auth/require-project-for-page.ts` | **403, ίδιο κείμενο** — αλλά ως **απόφαση τομέα** («έργο ανήκει σε εταιρεία· ο προσωπικός χώρος δεν έχει καμία»), όχι ως παρενέργεια σφάλματος αυθεντικοποίησης |

## 4. Η άγκυρα — `scripts/__tests__/firebase-emulator-destination.test.js`

**Τέσσερις ανεξάρτητοι κανόνες, ποτέ ένας με «ή»** (μάθημα CHECK 3.41)· το κριτήριο διαχωρισμού είναι ότι έχουν **διαφορετική θεραπεία**:

| | Ερώτημα | Θεραπεία όταν κοκκινίζει |
|---|---|---|
| **Κ1** | η σημαία **παράγεται** από το `FIREBASE_AUTH_EMULATOR_HOST`; | *δηλώσου στο `env` του `next.config.js`* |
| **Κ2** | υπάρχει **δεύτερος γραφέας**; | *σβήσε τον δεύτερο διακόπτη* |
| **Κ3** | ο φρουρός ζει **έξω** από το `if` που κρίνει; | *βγάλ' τον έξω* |
| **Κ4** | το artifact έχει **runtime lookup**; | *το Next έπαψε να τιμά το `env`* |

**Ο Κ2 ήταν ΚΟΚΚΙΝΟΣ** τη μέρα που γράφτηκε, σε **δύο** ζωντανά αρχεία. Κανένας άλλος κανόνας δεν τα έβλεπε.

### ⚠️ Τρεις αποφάσεις της άγκυρας

**Ο Κ1 δεν είναι κυκλικός παρονομαστής.** Δεν διαβάζει το **κείμενο** του `next.config.js` (αυτό θα ρωτούσε τον κριτή αν είναι σωστός — ADR-790 §9.1). **Εκτελεί** το config σε **δύο ξεχωριστές διεργασίες**, με και χωρίς τη μεταβλητή, και απαιτεί **διαφορετική** απάντηση. Ξεχωριστή διεργασία **υποχρεωτικά**: το `require` απομνημονεύει, άρα δύο κλήσεις στην ίδια διεργασία θα **επικύρωναν τον εαυτό τους**.

**Ο Κ3 έχει ρητό παρονομαστή.** Το «ο φρουρός ζει έξω από το `if`» είναι εύκολο να είναι πράσινο επειδή **δεν κοίταξε τίποτα**. Γι' αυτό ο Κ3 απαιτεί **ΚΑΙ ΤΟ ΑΝΤΙΘΕΤΟ**: το `connectAuthEmulator` **ΠΡΕΠΕΙ** να είναι **μέσα** σε `if` που κρίνει τη σημαία.

**🔴 Ο Κ4 γεννήθηκε με λάθος παρονομαστή και το πλήρωσε.** Η πρώτη γραφή σάρωνε **κάθε** `.next*` και κοκκίνισε με **20** runtime lookups — αληθινούς **για τον κώδικα του Ιουλίου**: το δέντρο κρατά **παγωμένους** καταλόγους άλλων εργαλείων (`.next-oracle` του χρησμού 3.51, `.next-3100`). Ήταν κρίση **ιστορίας**. Πλέον ρωτά το SSoT `resolveBuildDir()` (δημοσιεύτηκε από το `bundle-analyzer.js`, ο **ίδιος** αναγνώστης που χρησιμοποιεί ο bundle ratchet ADR-598 G6) — και έγινε **43 δευτερόλεπτα φθηνότερο** (49s → 17s). ⚠️ **ΟΧΙ `mtime` για φρεσκάδα**: ένα `git checkout` το αλλάζει χωρίς να αλλάξει τίποτα (CHECK 3.33).

### 🔶 Δηλωμένο όριο του Κ4

Είναι ο **μόνος** που αποδεικνύει την τελική αξίωση *«η τιμή έφτασε στον browser»*, και απαιτεί build — που το `jest-suite.yml` **δεν κάνει**. Δύο δρόμοι απορρίφθηκαν: **αποτυχία χωρίς artifact** ⇒ μονίμως κόκκινο ⇒ `SKIP_` ⇒ διακοσμητικό (CHECK 3.39)· **σιωπηλό πέρασμα** ⇒ το «0 = κανείς δεν κοίταξε». Κρατήθηκε **ρητό skip** με τη λογιστική (Λ1) να τυπώνει τους αριθμούς **ακόμα και στο μηδέν**.

## 5. ⛔ Τι να ΜΗΝ κάνεις

1. **ΜΗΝ** ξαναβάλεις `NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true` σε npm script, shell ή workflow. Δεν είναι πια ο διακόπτης — ο Κ2 μπλοκάρει.
2. **ΜΗΝ** «λύσεις» τον προορισμό βάζοντας τη μεταβλητή στο `.env.local`: είναι gitignored ⇒ **δεν ταξιδεύει** στον επόμενο.
3. **ΜΗΝ** ξαναφέρεις λόγο απόρριψης για την **απουσία οργανισμού**. Θα ξαναγεννούσε τον βρόχο, τώρα με **τέσσερις** φρουρούς να δείχνουν ότι δεν έπρεπε.
4. **ΜΗΝ** χαλαρώσεις το `AuthContext.companyId` σε `string | null`. Είναι διεύρυνση επιφάνειας ασφαλείας σε **352** διαδρομές, για να λυθεί πρόβλημα **προσγείωσης**.
5. **ΜΗΝ** αλλάξεις τη σειρά «ρόλος πριν από χώρο».
6. **ΜΗΝ** κάνεις τον Κ4 να αποτυγχάνει χωρίς artifact.

## 6. 🔶 Ανοιχτά — γεννήθηκαν από αυτή τη δουλειά

### 6.1 Ο αυτόνομος επαγγελματίας ζωγραφίζει **κόκκινο σφάλμα** σε κάθε φόρτωση

Το `UserRoleProvider` καλεί **άνευ όρων** `checkUserRole` → `loadSecurityRoles` → ερώτημα σε **εταιρική** συλλογή. Για όποιον δεν έχει εταιρεία είναι δομικά αναπάντητο· ο κώδικας **ανακάμπτει** (`return getDefaultSecurityRoles(...)`) αλλά το καταγράφει ως **`[ERROR]`**:

```
[EnterpriseSecurityService] ❌ Failed to load security roles: AUTHORIZATION_ERROR: User is not assigned to a company
```

Δηλαδή **σχεδιασμένη, νόμιμη κατάσταση αναφέρεται ως βλάβη** — ίδια οικογένεια με τη Βλάβη Β, ένα σκαλί πιο κάτω. Ο θόρυβος θα κρύψει τα αληθινά σφάλματα.
⚠️ **Δεν αγγίχθηκε**: το `EnterpriseSecurityService` είναι κοινό, και η σωστή θεραπεία θέλει **απόφαση τομέα**.

### 6.2 Ο `checkUserRole` κρίνει με **λίστα email** από το bundle

`NEXT_PUBLIC_ADMIN_EMAILS` — δεύτερη αυθεντία εξουσιοδότησης, **μέσα στο bundle του φυλλομετρητή**. Είναι ήδη στην εμβέλεια του CHECK 3.68 / ADR-801.

### 6.3 Τα ports του emulator δηλώνονται **τρεις** φορές

`firebase.json` *(αυθεντία)* · `package.json` `dev:emulator` · **hardcoded** στο `src/lib/firebase.ts` (`localhost` 8080/9099/9199). Αλλαγή θύρας στο ένα ⇒ ο client μιλά σε **τίποτα**, με το ίδιο σύμπτωμα «λάθος προορισμού». **Δεν διορθώθηκε** — εκτός εμβέλειας, καταγράφεται.
